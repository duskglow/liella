#### §2: Error reporting and diagnostics

| ID | Spec | Ann. | Decision |
|---|---|---|---|
| D-2.1 | §2.1 | HIST | The errno cell is a TLS slot in `legacy::errno_slot`, exported via `__errno_location`. It is never touched internally. **Hosted test builds** (no `export` feature, where the host C library owns the threads and their TLS) reach the errno of the running C library through the interposable `__errno_location` symbol, as `caller_alloc` reaches `malloc` (F23). Product builds resolve the same symbol to Liella's own export. Translation tests therefore observe the real per-thread `errno` from phase 2 on. |
| D-2.8 | §2.4 | COMPAT | The assertion messages are glibc 2.39's exact text (ERRATA E8). They are written straight to descriptor 2, with no allocation and no stream (so they appear even from a corrupted heap), then `abort`. |
| D-2.2 | §2.2 | COMPAT, HIST | **Internal:** `Errno::{name, description}`, plus translation through an explicit `Locale`. **Boundary:** `strerror_r` is two exports (`strerror_r` GNU, `__xpg_strerror_r` XSI). `sys_errlist`/`sys_nerr` are compat data arrays sized per OD-1. Realised in phase 8: the texts are `liella::diag`'s (the reference C-locale texts of `spec/abi/errmsgs.tsv`, observed with `spec/tools/errmsg_probe.py`), NUL-terminated so `strerror` returns them directly; `Unknown error N` goes to the library's buffer; translation waits for the catalogs (phase 13); the compat arrays wait for compat versions (phase 15). `perror` leaves an unoriented `stderr` unoriented, as the spec says (glibc orients it; recorded in `diag_products.rs`). `strerror_r` (both forms) and `perror` (rewritten under §1.4, item 7, in a fresh session from the spec, `spec/behaviour/diagnostics.md` and black-box probes): GNU `strerror_r`/`__strerror_r` returns a known number's static text and leaves the buffer untouched; an unknown number writes `Unknown error N` cut to `n-1` bytes plus a NUL into the buffer (nothing when `n` is 0) and returns the buffer; a NULL buffer with `n > 0` returns `strerror`'s buffer. XSI `__xpg_strerror_r` writes the text cut to fit and returns 0 when a known text fitted, `ERANGE` when it did not, `EINVAL` for an unknown number (the cut text still stored), `EFAULT` for a NULL buffer with `n > 0` (S6), and never changes `errno`. `perror` writes `s: text\n` (or `text\n` for a NULL or empty `s`) as one write through the `stderr` stream, honouring wide orientation and leaving an unoriented stream unoriented (the spec; glibc orients it, recorded in `diag_products.rs`); `errno` is unchanged on success and the write error on failure (glibc sometimes leaves `EINVAL` depending on stream state). |
| D-2.3 | §2.3 | HIST | One renderer, `boundary::report::report`, behind the `err`/`warn`/`error` C adapters (`liella_report7`) and the `v` exports (rewritten under §1.4, item 6, in a fresh session from the spec, `spec/behaviour/diagnostics.md` and black-box probes). `warn`/`err` print `short: msg: text` (`short: text` for a NULL format); `warnx`/`errx` print `short: msg`; `err`/`errx` then `exit(status)`. `error` prints `full: msg[: text(errnum)]` (a NULL format counts as empty); `error_at_line` prints `full:file:line: msg[...]` with the line unsigned (glibc prints it signed), and as `error` for a NULL file. `short`/`full` are `program_invocation_short_name`/`program_invocation_name` (NULL prints `(null)`). The message is formatted first (so `%m` sees the caller's `errno`), then `stdout` is flushed (the `error` forms only), then one write through `stderr` (wide streams through their codec; an unoriented stream becomes byte-oriented). `error_message_count`, `error_one_per_line` and `error_print_progname` are exported data read on each call (F6): the hook, when set, replaces the name prefix (the BSD family ignores it); the count counts each message printed; while `error_one_per_line` is set, `error_at_line` skips a message whose file name (compared as text; at most 4096 bytes remembered) and line equal those of the previous `error_at_line` call made while it was set, and a NULL file clears the remembered location. A non-zero status exits even when the message was suppressed (glibc returns, undefined behaviour for callers of the header's `noreturn` form). `errno` is left as the caller had it, except that a failed write stores its error. Spec gaps found (§2.3 is silent): which name each family uses, the NULL-format layout, when the previous location is recorded, and a suppressed message with a non-zero status. |
| D-2.6 | §2.6 | ARB | `fmtmsg` and `addseverity`, rewritten under the clean-room rules of §1.4 (item 4) in a fresh session from the spec, `spec/behaviour/fmtmsg.md` and black-box probes. **Message:** label, severity, text, `TO FIX: ` + action, tag, in that order; each present field is followed by its separator (`": "` after label and severity, a newline after text, two spaces after action) and the message ends with a newline; a field is present when its pointer is non-NULL; `MM_NOSEV` prints no severity. **Labels:** the 10:14 byte limits exactly as the contract states, split at the first colon; no colon, an unknown or negative severity gives `MM_NOTOK` whatever the classification. **Environment:** `MSGVERB` (colon-separated keywords, one optional trailing colon; anything else selects all fields) and `SEV_LEVEL` (`keyword,level,printstring`; `strtol` base-0 levels above 4 and within `int`; malformed elements skipped) are read once, at the first `fmtmsg`, into one table shared with `addseverity` (so `SEV_LEVEL` overrides earlier `addseverity` calls for the same level and later calls override it). **addseverity** copies its string (the reference keeps the pointer) and refuses levels ≤ 4 and removal of absent levels; the table holds 256 added severities (`MM_NOTOK` when full; replaced strings are not reclaimed, a known inefficiency). **Output:** `MM_PRINT` writes through the `stderr` stream (unoriented becomes byte-oriented; wide gets the text converted; no flush), a failure gives `MM_NOMSG`; `MM_CONSOLE` writes the full message (ignoring `MSGVERB`) to `/dev/console` as the spec names, a failure gives `MM_NOCON`, both failing give `MM_NOTOK`. The reference sends console messages through `syslog(LOG_ERR)` and never reports a failure; Liella follows the spec (owner ruling 2026-10-02: spec over reference, §1.4). |
| D-2.7 | §2.7 | HIST | Written under the clean-room rules of §1.4 in a fresh session, from the spec, the psABI and DWARF (normative references), `spec/behaviour/backtrace.md` and black-box probes. **Internal:** `backtrace` unwinds with Liella's own DWARF call-frame unwinder (IP-27; no `dlopen` of `libgcc_s`), so it and `backtrace_symbols_fd` are async-signal-safe from the first call (observable, stricter): no allocation, no lock, no initialisation. Registers are captured by the `getcontext` primitive in a never-inlined boundary function; that frame, and the export's own frame when it has one (identified by its FDE start), are left out. Objects searched: the executable (`AT_PHDR`) and the library's own image (`__ehdr_start`). Call-frame information is found through `PT_GNU_EH_FRAME` (binary search), or, in a static executable (linked without `.eh_frame_hdr`), by scanning `.eh_frame` between the start object's label `liella_eh_frame_start` and a terminator in `.eh_frame.liella_end` (`adapter/runtime.c`). The signal restorer carries call-frame information with `S` (CFA = `%rsp` = the kernel's `ucontext_t`, registers from `uc_mcontext`); `_start` marks the outermost frame. **Boundary:** `backtrace_symbols` returns one caller-owned block holding the pointer array, then the texts; texts are `argv0(+0xOFF) [0xADDR]` for an address in the executable (OFF = address − load bias, also for non-PIE and static programs, where glibc prints `()` or nothing), otherwise `[0xADDR]`; no symbol names (the static product has no dynamic symbols). `_fd`: the same without the space, newline-terminated, one `writev` per frame, stopping at the first failed write with `errno` set. A negative count is 0 for all three (glibc's `backtrace_symbols` crashes). Limits: objects other than the executable and the library image are not discovered until `dl_iterate_phdr` exists (phase 14); a seccomp policy denying `process_vm_readv` gives 0 frames. Spec note: §2.7's edge case about `dlopen` of the unwinder and its Kernel line describe the reference; Liella uses `getpid`, `rt_sigprocmask`, `process_vm_readv` and `writev`. |
| D-2.9 | §2.5 | ARB | **Opt-in diagnostic channel (LIELLA-DIAG-CHANNEL; owner ruling #422, 2026-10-21, with the condition: no performance impact when disabled, particularly on hot paths).** `LIELLA_DIAG=<topic>[,<topic>...]` (`all`: every topic; unknown names and empty items ignored, names exact and case-sensitive) is read once and LAZILY (LIELLA-DIAG-CHANNEL-2, coordinator decision under the owner's condition): the first time a diagnostic call site runs (a rare failure path), `diag::on` checks `process::secure()` (`AT_SECURE`: ignored, like the other tuning), copies the value with `process::getenv_into` (the environment writers' lock, so a racing `setenv` cannot free it; values over 256 bytes are ignored) and caches the topic bits in `boundary::diag::TOPICS` (an `UNREAD` bit until then; compare-exchange, the first answer wins). Startup is exactly as without the channel: run 1 read it at start, and both variants tried there cost startup (a shared `getenv_many` scan with `LIELLA_NSCACHE`: an empty static program 17 -> 20 page faults; a second `getenv`: one more scan per process), so neither was kept. A `setenv` before the first reportable event is honoured; changes after it are not. `diag::note(Topic, text)` (cold, out of line) writes `<program_invocation_short_name>: liella: <topic>: <text>\n` to descriptor 2 with one gathered `writev` (`rt::fatal::message`: async-signal-safe, no allocation, no stdio, no lock; a short write is continued, an error ends it quietly). Call sites sit only on rare paths (a failure episode's start and its end, never per event) and check the one flag there; no common path changes. Default: off, silent (a libc does not write to a program's stderr unprompted). A new topic is one `Topic` constant and one `NAMES` entry. First topic `timers`: `timer::note_episode` (D-23.3), one line per timer's failure episode at its start and one at its recovery. Gain over glibc (no channel; the event is silent): diagnosability. Tests: `timer_episodes_reported_on_the_diagnostic_channel`, `timer_notification_retried` (silent when off), `diag_channel.rs` (a static C program from a real start: the variable at start or set by `setenv` before the failure). |
| D-2.10 | §2.6 | ARB | **fmtmsg assembly, severity table and destinations** (COLD-REWRITE2-W-far-10-REWRITE, 2026-10-21; record `liella-historic:handoff/decisions/COLD-REWRITE2-W-far-10-REWRITE.md`; mqueue part D-25.6, `va_source` part D-12.25). (F1) Up to 16 borrowed pieces joined into one heap buffer, so each destination gets one write and fields are not interleaved with other threads; without memory the pieces are written one by one. (F2) Layout is a five-row table (bit, prefix, separator); a separator is written only when another present field follows (empty strings count as present). (F3) A fixed 256-entry severity table (D-2.6 capacity, `MM_NOTOK` when full), atomic level plus copied string, under one `RawMutex`; replaced strings are not reclaimed (D-2.6's known inefficiency). (F4) `MSGVERB` and `SEV_LEVEL` read once at the first `fmtmsg` under the table lock; `SEV_LEVEL` elements go through `addseverity`'s `define` in order; a level must be one whole base-0 C integer above 4 within `int` (`5z` skipped). (F5) Validation order: label (split at the first colon, at most 10:14 bytes), then environment, then severity (unknown: `MM_NOTOK`); no destination: `MM_OK` after validation. (F6) stderr through the stream layer; console via `/dev/console` (`O_WRONLY or O_NOCTTY or O_CLOEXEC`), short writes and EINTR retried; both failed `MM_NOTOK`, else `MM_NOMSG` / `MM_NOCON`. (F7) `errno` saved and restored around the writes (a guard: no write path sets it today). |
| D-2.11 | §2.7 | ARB, HIST | **Backtrace unwinder: three pure layers, no cache between calls** (COLD-REWRITE2-W-far-03-REWRITE, 2026-10-21; record `liella-historic:handoff/decisions/COLD-REWRITE2-W-far-03-REWRITE.md`; D-2.7). Liella exports no `_Unwind_*`; C++ throws use libgcc's unwinder over Liella's CFI. (1) Locate (object, FDE), interpret (row at pc), apply (caller registers); one walker serves `trace` and `caller`. (2) A row is 17 rules plus the CFA rule, a rule 16 bytes (expressions kept as address and length); remember-state depth 4; about 1.5 KB of working storage (fits a small alternate stack); columns above 16 parsed and dropped. (3) Nothing kept between calls (async-signal-safe, no allocation, no lock); header lookup by binary search; a scan (static programs without a header) keeps the last CIE; `OwnMemory` keeps one aligned 64-byte line per trace. (4) Any fixed-size header table encoding is decoded; a header without a usable table falls back to scanning. (5) Signal frames by CFI only (`S`): the next address is looked up exactly; no code-pattern fallback; termination is no progress (same return address and stack pointer), not a growing stack. (6) Augmentations "" or "z" + {R, P, L, S, B, G}, an unknown letter rejects the CIE; CIE versions 1, 3, 4; pointer encodings absolute, pcrel, datarel (header only). (7) An unreadable save slot makes that register unknown, not the step fail. (8) Expressions: wrapping arithmetic, signed `div` failing on zero and overflow, unsigned `mod`, signed comparisons, branches inside the block, stack 32, 1024 operations. (9) `caller`'s `max` counts return addresses examined; `program_headers` is `None` for PN_XNUM. |
