#### §26–§29

| ID | Spec | Ann. | Decision |
|---|---|---|---|
| D-26.1 | §26.1 | HIST | **Internal:** `Logger` handle (owned ident, explicit facility), with an optional structured journald protocol. **Boundary:** the global logger keeps the ident *by pointer*, as the contract says. The connection is synchronised (observable, stricter). |
| D-26.2 | §26.1 | HIST, ARB | **syslog (phase 13); decisions.** `liella::log::Logger` (owned ident, options, facility, mask, channels); the global logger `legacy::log_compat::GLOBAL` keeps the ident by pointer under one lock over settings, connection and delivery; a fork child resets the lock and shares the connection. **Never blocks indefinitely:** sends use `MSG_DONTWAIT\|MSG_NOSIGNAL` and `ppoll` with at most 1 s per message, and the console is opened `O_NONBLOCK` with the same bound (the reference blocks on a full receiver or a FIFO console with no reader); a timeout counts as not delivered (`LOG_CONS` then writes to the console). One reconnect and resend on any other failure. The socket is moved to descriptor 3 or above. The stream transport cuts the text at the first NUL. `errno` is never changed (X3; the reference leaks it after a failed send). A NULL format logs nothing (the reference crashes). Kept from the reference: the extra "unknown facility/priority" record for stray priority bits, `openlog` replacing the options, facility 0 accepted, `closelog` resetting only the ident, `setlogmask(0)` querying; timestamp per `localtime_r`, English month names; console form `IDENT[PID]: MSG\r\n`. The journald protocol of D-26.1 is not built (optional). `openlog(NULL)` selects the program name, also after an earlier `openlog` with another ident (openlog(3); owner ruling 2026-10-04; the reference keeps the previous ident: recorded in `syslog_products`). |
| D-27.1 | §27 | HIST | Our own loader follows the ELF gABI, the x86-64 psABI and the GNU extensions. Object lists are RCU-style, so `dl_iterate_phdr`/`_dl_find_object` take no global lock (observable: fewer deadlocks). |
| D-27.2 | §27.1 | HIST | **Internal:** `Result`. **Boundary:** per-thread `dlerror` state. |
| D-27.3 | §27.1 | — | Library search reads the system `ld.so.cache` through its inspected format (Appendix D, phase 14), with `ld.so.conf` directory scanning as the fallback. |
| D-27.4 | §27 | — | **`dl_iterate_phdr`** (static programs, until the loader of phase 14 supplies the object list): one callback for the main program (name "", `AT_PHDR`/`AT_PHNUM`, `dlpi_addr` from `PT_PHDR`, TLS module 1 and the calling thread's block when `PT_TLS` exists), then one for the vDSO (`linux-vdso.so.1`, ELF64 header fields e_phoff at 32, e_phentsize 54, e_phnum 56) when `AT_SYSINFO_EHDR` is set, as a glibc static program reports (probe); `dlpi_adds` = objects, `dlpi_subs` = 0, `size` = 64; a non-zero callback result stops the walk and is returned; it reads immutable startup data only (async-signal-safe). **`stime`** is compat-only as in glibc 2.39: `libc.so` exports `stime@GLIBC_2.2.5` (non-default; `.symver` stub in `s23_time.rs`, listed in the version script by `cargo xtask so`), `libc.a` offers no plain `stime`, so no new program links it while old binaries resolve it. Known difference: `libc.so` binds `dl_iterate_phdr` GLOBAL where glibc binds WEAK (the same for every WEAK export, e.g. `fgetc`). Probes: CONF-SYMS-2. |
| D-27.5 | §27.1 | — | **`_dl_find_object`** (static programs, until phase 14): a `pc` in one of the main program's `PT_LOAD` segments gives that segment's range (a static glibc 2.39 program reports the segment, not the whole object), one in the vDSO the vDSO's whole mapped range; `dlfo_eh_frame` = the object's `PT_GNU_EH_FRAME` address (0 without one), `dlfo_flags` 0, result 0; any other `pc` (stack, past `_end`, 0) gives -1 and leaves `*result` alone. libgcc_eh (GCC 13) calls it, so a static C++ or `-fexceptions` program needs it to link. Exported with feature `runtime` only (`export! { runtime ... }`): the answer covers only a process Liella started, so test builds that interpose exports on a host process keep the host's (interposed, it hid the host's shared objects from Rust's panic unwinder: SIGABRT). Known gap: `dlfo_link_map` is 0 (no `struct link_map` before phase 14; glibc gives a non-null one). Probe: PTHREAD-ONCE-UNWIND-2 (static and dynamic glibc). |
| D-27.6 | §27.5 | — | **`__x86_get_cpuid_feature_leaf@GLIBC_2.33`** (`<sys/platform/x86.h>`, behind `CPU_FEATURE_PRESENT`/`CPU_FEATURE_ACTIVE`): returns `struct cpuid_feature` (32 bytes, align 4: the raw CPUID words eax, ebx, ecx, edx, then the "active" words in that order). Index to leaf: 0=1, 1=7.0, 2=0x80000001, 3=0xd.1, 4=0x80000007, 5=0x80000008, 6=7.1, 7=0x19, 8=0x14.0, 9=0x24. A leaf or subleaf past the CPU's maximum reads zero. Index 10 and above (including 0xffffffff) gets one shared all-zero entry, never NULL. The table is filled on the first call (`liella_rt::cpu::feature_leaves`). Active = present AND a fixed per-bit rule: the `ACTIVE_ALWAYS` bits; FMA/AVX/F16C/AVX2 only with XCR0 SSE+AVX state; AVX-512 F/DQ/CD/BW/VL only with XCR0 0xe6; HLE/RTM inactive and RTM_ALWAYS_ABORT active (even though not present) when 7.EDX bit 11 or 13 is set. Probe: X86-CPUID-FEATURE-LEAF (glibc 2.39 on sumire Skylake-SP, shiki Haswell, kanon Broadwell, keke Zen 1). **Known gaps (ruling #778, #781, #782):** (1) an active bit never seen present on a probed CPU stays inactive (AVX512_IFMA/VBMI/VNNI/BITALG, GFNI, VAES, VPCLMULQDQ, the 7.1, 0x19, 0x14 and 0x24 active bits, among others). This is the safe answer: a feature is never claimed usable when it is not. Trigger: extend `ACTIVE_ALWAYS` once a newer CPU (Ice Lake+ / Zen 4) can be probed against glibc. (2) The TSX rule (abort bit 11 or 13) rests on one CPU per side (sumire with bit 13, kanon without either bit). A model-based rule cannot be told apart on these hosts. (3) `glibc.cpu.hwcaps` tunable masking of the active bits is not implemented. |
| D-28.1 | §28 | HIST | `gmon.out` follows the gprof file format specification. `profil` uses `ITIMER_PROF`, per the contract. |
| D-29.1 | §29 | HIST, COMPAT | RPC and XDR follow RFC 5531/4506. NIS follows the YP protocol. STREAMS and removed interfaces are `ENOSYS` stubs. `_IO_*` vtable objects export tables of our functions (F32). |
| D-29.2 | §29.1 | COMPAT | **UDP RPC replies from the called address only** (owner ruling 2026-10-23, #1643, provisional): the UDP client compares each datagram's `recvfrom` source (port and IPv4 address) with the called address and drops any other, whatever its xid; the socket is not connected (that would change ICMP error reporting). A reply-shaped datagram (type REPLY, status accepted or denied; the xid is never consulted) from another address during a call turns its timeout into `RPC_CANTRECV` with `EREMCHG`; nothing ends a call early. Each call's xid is fresh random bits (`getrandom`), except the call after `CLSET_XID`, which is stepped from the set value as probed. Opt-out COMPAT-12 (`liella.compat.rpc_reply_any_source=1`, ignored when `AT_SECURE`). `clnt_broadcast` and TCP are not affected. Reason: replies over UDP are matched by xid only; accepting them from any source lets a third party who can send packets to the client answer in the server's place. |
