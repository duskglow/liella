#### §22: Threads

| ID | Spec | Ann. | Decision |
|---|---|---|---|
| D-22.1 | §22.4 | ARB, COMPAT | Every sync object fits its ABI size, is valid when all-zero (static initializers), and holds no pointers, so it works process-shared and survives being moved between processes by `mmap`. |
| D-22.2 | §22.3 | HIST | **Cancellation is an explicit internal error.** Deferred cancellation makes the current cancellation point return `Error::Canceled`. That propagates through Rust frames normally, and at the ABI boundary `ret` hands it to `rt::cancel::act()`. `act()` runs the cleanup handlers and performs the forced unwind of the *caller's* frames, never unwinding a Rust frame. Asynchronous cancellation is acted on only while the thread executes outside the library's text range, and is deferred to the next boundary crossing otherwise (F12, F39). |
| D-22.3 | §22.1 | — | C11 `thrd_*`/`mtx_*`/`cnd_*`/`tss_*` are translations of the same internals. |
| D-22.4 | §22.5 | HIST | Read-write locks default to prefer-reader, per the contract. A fair policy is available internally. |
| D-22.5 | §22.6 | ARB | Keys beyond `PTHREAD_KEYS_MAX` are allowed (P-lift). The constant stays 1024 in the ABI. |
| D-22.6 | §22.6 | HIST | The static TLS surplus for initial-exec `dlopen` objects is sized by tunable, with a generous default. Dynamic TLS never fails except for `ENOMEM`, which aborts, per the contract (§27.3). |
| D-22.7 | §22.9 | KERN | The library owns the per-thread rseq registration and publishes `__rseq_*`. |
| D-22.8 | §22.10 | HIST | We ship our own `libthread_db` describing our layout (F30). |
| D-22.9 | §22.1–22.2, §22.6, §22.9 | KERN, ARB | **The thread runtime** (phase 6). `pthread_t` is the thread pointer (as glibc). One mapping per thread: guard (rounded to pages; none when 0), stack, static TLS block, thread block, then the *descriptor* (start routine and argument, result, join and detach state, cancellation word, cleanup-buffer chain, setxid request word, stack bounds, the robust-list head, the 32-byte-aligned rseq area, the key table pointer, the per-thread result slots of D-H3), whose address the thread block holds. A caller-supplied stack (`attr_setstack`) gets the TLS block, thread block and descriptor at its top. Creation is `clone3` (falling back to `clone`) with the flags of §22.1, through `machine/thread_start.S`, which switches to the new stack, calls the runtime's entry, and makes the `exit` system call if it ever returns. The kernel writes the TID into the thread block (0x84, `CLONE_PARENT_SETTID`) and clears it at exit (`CLONE_CHILD_CLEARTID`), which is the futex `join` waits on; `gettid` is that load. The main thread's TID comes from `set_tid_address` at startup. The new thread registers its robust list and rseq area itself (Liella owns rseq in its processes, D-22.7; `glibc.pthread.rseq=0` disables it) and publishes `__rseq_offset`/`__rseq_size`/`__rseq_flags`. Stacks of exited threads are cached (up to 40 MiB, glibc's figure) and reused only once their TID word is 0. **No transparent huge pages on thread mappings (owner ruling 2026-10-01).** Before Linux 6.7 a `MAP_STACK` mapping may take transparent huge pages; one that merges with an adjacent anonymous mapping can then have a fault fill a whole 2 MiB range, making the neighbour's untouched pages resident (found by `s11_10_c_10`, which a glibc thread stack did this to). So on a kernel whose `uname` release is below 6.7, each thread mapping is made `PROT_NONE`, marked `MADV_NOHUGEPAGE`, then opened, so it is never usable unmarked. 6.7 made `MAP_STACK` imply `VM_NOHUGEPAGE`, and there the mapping is made as before. Default stack size: the `RLIMIT_STACK` soft limit at startup, 2 MiB if unlimited (§22.2). A thread list (lock-protected; changed only at create and exit) serves setxid, `fork` and `pthread_getattr_np`. `__libc_single_threaded` becomes 0 at the first creation and stays 0 (P5). |
| D-22.10 | §22.1 | — | **Threads Liella did not create.** In a test process the host C library starts (D-4.15) every thread is glibc's. Liella's thread-block fields there are glibc's zero reserved area (0x80–0x280), and a reused glibc stack keeps them: such a thread inherits the `errno` slot and heap cache of the dead thread whose block it reuses. That is sound for the heap, because exactly one live thread uses a block at a time, and it is the only case: a cache of a glibc thread whose stack is unmapped is never parked (it leaks its partial slabs; test processes only). What needs the TID asks the kernel (`gettid`) instead of the thread block, because a reused block's TID word is stale; descriptor-backed operations (`join`, cancellation, setxid) are defined only for threads Liella created (`FLAG_OWN`). In a process Liella started, or under glibc's `ld.so` with Liella's `libc.so.6`, every thread is Liella's. **Interim gap (owner ruling 2026-10-01): dynamically linked programs.** Under another `ld.so`, a new thread's TLS for every loaded module must come from that loader's private interface (glibc's `_dl_allocate_tls`), which Liella does not use. Until Liella's own `ld.so` (phase 14), `pthread_create` and `thrd_create` in a dynamically linked program fail with `EAGAIN`. Statically linked programs, which Liella starts itself, have full threads. That covers the conformance suite, which links statically and suffices for this milestone. In-process tests that create Liella threads run start routines that call only Liella and atomics (the host library's TLS is not set up in them); the full contracts run as C conformance programs against the products. |
| D-22.11 | §22.3 | KERN, HIST | **Cancellation mechanics** (refines D-22.2). A cancellation point checks the descriptor's cancellation word on entry (`Err(Canceled)` if acted on) and makes its blocking system call through a C-layer *window* primitive (`liella_sys_cancellable`: check the word, then `syscall`, between two exported labels). The internal signal's handler, interrupting a thread whose program counter is inside the window (the system call had no effect: the kernel restarts it, or it has not started), rewrites the saved program counter to the primitive's cancelled exit, which returns `-ECANCELED`; the Rust caller turns that into `Err(Canceled)`, which propagates to the export (no Rust frame is skipped). Past the `syscall` instruction (a completed call, or a partial transfer) the request stays pending for the next point (§22.3 guarantees). **Asynchronous cancellation (owner ruling 2026-10-01, interim):** it takes effect only at safe points outside Liella code. The handler acts immediately only when it can prove the interrupted program counter lies outside Liella's text, from text bounds the products' link records. Where no such bounds exist, in a statically linked program until the product build marks them and in test processes, the request stays pending. It is then acted on at the thread's next safe point: a cancellation point, `pthread_testcancel`, or `pthread_setcancelstate`/`setcanceltype` (the only async-cancel-safe calls). **Known deviation from glibc,** which acts immediately at any instruction: a thread that runs only its own code with asynchronous cancellation enabled is not cancelled until it reaches such a point. This is the owner's chosen tradeoff, preferred over guessing the text boundary in a statically linked program. Revisit if coreutils' tests fail because of it. **Acting** runs the C cleanup buffers that `pthread_cleanup_push` registered (`__pthread_register_cancel`: each is a `__sigsetjmp` buffer; `__pthread_unwind_next` continues to the next), then key and `thread_local` destructors, then exits with `PTHREAD_CANCELED`. **Interim until phase 14:** glibc runs the cleanup through `_Unwind_ForcedUnwind` from `libgcc_s` (loaded by `dlopen`), which also runs C++ destructors and `-fexceptions` `__attribute__((cleanup))` handlers. Without `dlopen` (phase 14), Liella runs only the registered C buffers; a cancelled or exiting C++ thread skips its destructors. C programs (the coreutils target) are complete. **Fast points (CANCEL-FAST, 2026-10-11):** `read`, `write`, `pread`/`pread64`, `pwrite`/`pwrite64`, `__read_chk`, `__pread_chk`/`__pread64_chk` and `close`/`__close` act on a due request themselves (`sys::point4`, `sys::close_point`, `cancel::act`) instead of setting `CANCEL_HIT` for `cancel::point`; the order of effects is unchanged: `errno` from the call's result, then acting. The 4-argument calls enter the same window through `liella_machine_syscall_cancel4` (all arguments in registers, no stack arguments; the word's address moves to `%r11` before the window, so the window is still exactly load-test-`syscall` for both entries). No single-threaded special case: the window's first load IS the one-load "nothing to act on" check, in every thread. **Happens-before argument (unchanged by the fast path):** a request is published by `pthread_cancel`'s `fetch_or(REQUESTED)` (AcqRel) BEFORE it signals the thread. (a) If the target's window load comes after that RMW in the word's modification order, it reads REQUESTED and returns -ECANCELED without the system call. (b) If the load came earlier, the signal is sent after the RMW and delivered at the next kernel entry: while the program counter is between the load and the `syscall` instruction (the handler redirects it), during the system call (a restartable call is rewound to the `syscall` instruction, inside the window: redirected; a completed or partial transfer is past `window_end`: the request stays pending for the next point, as the row above says). A self-request (`pthread_cancel(pthread_self())` before the call) is sequenced before the load: case (a). `close` keeps its own order (the descriptor is closed outside the window, then the word is read: a request due then acts). No path skips the load; an interruption with -EINTR re-reads the word, as before. **Kernel ECANCELED (CANCEL-FAST-2, 2026-10-11, coordinator decision):** a point acts on a -ECANCELED (or -EINTR) result ONLY when the word says a request is due (`cancel_due`, `sys::found_due`); otherwise it is an ordinary error result (-1, errno ECANCELED), e.g. a timerfd read after a clock change or a seccomp filter. Sound because the window returns -ECANCELED only for a due request and only the thread itself can make a due request not due. Test: conformance/c/s22_cancel_fast.c part 5 (seccomp ECANCELED, main and created thread). Not changed: the futex waits of `pthread_cond_wait`/`sem_wait`/`pthread_join` (sync.rs `ThreadCtx::wait`) still read a raw -ECANCELED as acted on; futex(2) never returns ECANCELED itself (only a seccomp filter could); follow-up. **Direct points (CANCEL-FAST-2, 2026-10-11):** in the products `read`, `write`, `pread`/`pread64`, `pwrite`/`pwrite64` and `close`/`__close` are assembly entries (csys/src/machine/points.S; plan S2 hot-kernel; Rust twins `export! { asm }` call the same code in the tests). The common case: the descriptor word at `%fs:0xa0` (non-zero), count 1..=isize::MAX and a non-NULL buffer, then `call` into the SAME window (`liella_machine_cancel_window`, word address in `%r11`), then one result test; an error result tail-jumps to `liella_cancel_point_fail` (the rule above, errno, -1). Everything else tail-jumps to the former Rust export (`liella_*_rest`), unchanged. `close` makes its call first (outside any window), then reads the word: due, or an error, goes to `liella_close_point_fail`. The happens-before argument above is unchanged: the window is the same code and the first load is still its first instruction. `close` takes the Rust path (`aio::closing`) once any asynchronous I/O was started: one flag byte `liella_machine_aio_used`, set before the first request is counted (`PENDING`) or an internal descriptor is published (`RING_FD`, `EVENT_FD`), so a close that the old code would have seen as busy (its submission happened-before the close) sees the flag. |
| D-22.12 | §22, §1.1, §1.2, §2.4, §2.5, §27.3, §27.5 | ARB, HIST | **rt futex, sync, cpu, tls and fatal cores** (COLD-REWRITE-W-far-13 with proof passes -2 and -3, 2026-10-15; records `liella-historic:handoff/decisions/COLD-REWRITE-W-far-13.md`, `-13-2.md`, `-13-3.md`; D-22.1, D-22.4, D-22.9, D-22.10). (1) Futex wrappers thin and typed; private scope adds `FUTEX_PRIVATE_FLAG`; a deadline uses `FUTEX_WAIT_BITSET` with `FUTEX_CLOCK_REALTIME` (the only absolute wait); errors returned, callers re-check. (2) `RawMutex`: one zero-initialised `u32`, bit 0 locked, bits 1-31 the count of registered sleepers; lock CAS 0 to 1, slow path a short read-only spin, then register (+2) and wait on the exact value; unlock one `fetch_sub(1)`, wake exactly when the count was non-zero (the classic 0/1/2 design wakes needlessly). `reset` in the fork child stores 0. (3) `RawOnce`: bit 0 running, bit 1 sleepers, 4 done; an unwinding routine puts the word back to new and wakes the sleepers (POSIX `pthread_once` rule; a deliberate change, pinned by P1). (4) `RawRwLock` (D-22.4 reader-preferring): bit 0 writer, bit 1 sleepers, readers in units of 4; the unlock that frees the lock clears bit 1 and wakes all. (5) `RawCondvar`: a sequence word; `notify_all` increments then wakes all (no lost wake-up); broadcast only. (6) `cpu::Features`: a `Copy` value of the raw registers, cached once by the boundary; at most five `cpuid` (STARTUP-COST); out-of-range leaves not read; AVX family needs XCR0 bits 1-2, AVX-512 bits 1-2 and 5-7; psABI levels v2/v3/v4. (7) TLS: the thread-block layout and its offset asserts unchanged (ERRATA E7, D-22.10); initial area `A = max(64, p_align)`, thread pointer the first A-aligned address at least `tls` above the base, slack `A - PAGE` when A exceeds a page, checked arithmetic; canary = first 8 `AT_RANDOM` bytes with the low byte zeroed, pointer guard the next 8. (8) Fatal path: no allocation, lock or stdio; one `writev` per diagnostic (chunks of 16), resuming after partial writes and EINTR, giving up on other errors (P2); `abort` unblocks and raises SIGABRT, then the default disposition, then a trap, then `_exit(127)`, streams not flushed; assertion texts in the ERRATA E8 form. (P1-P2, P4) The unwind rule of `RawOnce` and the EINTR rule of `fatal::message` are new contracts with tests; four further contracts (condvar sequence, futex realtime clock, leaf-7 bound, canary bytes) got deterministic tests. |
| D-22.13 | §22.5 (s22_5_c_1_2) | COMPAT, HIST | **Old-ABI condition variables hold a heap pointer: the one exception to D-22.1** (COMPAT-CONDVAR-OLD, ruling #1153, 2026-10-23). Only `pthread_cond_*@GLIBC_2.2.5`, which old binaries bind; the 2.3.2 defaults keep D-22.1. The old object is one 8-byte word (probe tools/probe/compat/compat_condvar.c, spec/behaviour/compat.glibc.txt "== compat_condvar"), too small for Liella's condition variable, so the word holds the address of a `calloc`'d block: Liella's `Cond` (all-zero = default, private, `CLOCK_REALTIME`) plus a reference word (waiters inside; bit 31 = destroyed). `init` zeroes the word and allocates nothing; the first signal, broadcast or wait installs the block by compare-exchange (the loser frees its own). Conditions, each tested (crates/boundary/src/sync.rs `old_cond_tests`, tests/s22_threads_symbols.rs `sym_liella_compat_pthread_cond_objects`): (1) allocation failure on first use returns `ENOMEM` with the word still zero and the mutex untouched, as glibc (probe `rc=12 ... word zero`); never a half-built block, the block is complete before it is published. (2) `destroy` detaches and frees the block, or leaves it to the last waiter still inside (a destroy right after a broadcast is allowed); 1000 init/use/destroy cycles leave no block. (3) No old object is process-shared: `init` with `PTHREAD_PROCESS_SHARED` (or `CLOCK_MONOTONIC`) zeroes the word and returns `EINVAL`, as glibc, so no heap pointer is ever shared between processes. Kept difference: `destroy` leaves the word zero (glibc's leaves it nonzero), so the object is again a valid static initializer; gain: robustness, nothing observable to a correct program. |
