## The change

Three clauses are still pending `clause!` stubs although a test already exercises them under another name, so
`cargo xtask trace` cannot find their test. Replace each stub with a `#[test] fn` of the same name that runs the
existing check (or move the check there), fill the one real gap named below, and fix the old test's trace line.

1. `s22_5_c_1_2` (`pthread_cond_*@GLIBC_2.2.5` keep the pre-2.3.2 condvar ABI), stub in
   `crates/core/tests/s22_threads_clauses.rs`. Covered by `conformance/c/s22_compat_condvar.c` (header already names
   the clause), run from `crates/boundary/tests/s22_threads_symbols.rs`. Code: `old_cond_init/destroy/wait/signal` in
   `crates/boundary/src/sync.rs`, entries in `crates/boundary/src/posix/s22_threads.rs` (from line ~727).
   The stub becomes `conformance(&["s22_compat_condvar"])` (or the core file's equivalent runner).
2. `s24_5_c_3` (`getdomainname` returns the NIS domain, not the DNS domain), stub in
   `crates/core/tests/s24_system_clauses.rs`. `sym_getdomainname` in `crates/boundary/tests/s24_system_symbols.rs`
   compares sizes with `uname().domainname`. Gap: nothing shows it is not DNS-derived. Add: in an unprivileged
   user+UTS namespace (`unshare -r -u` equivalent from the test, a standing yes; skip with a printed reason if
   user namespaces are unavailable), `setdomainname("nis.example")` and `sethostname("h.dns.example")`, then
   `getdomainname` returns `nis.example`. Code: `core::system::domainname` (`crates/core/src/system.rs:181`),
   `getdomainname` (`crates/boundary/src/posix/s24_system.rs:319`). Probe glibc with the same steps first.
3. `s0_6_c0_6_0` (versioned names: several versions with different contracts; old-binary-only names cannot be linked
   against), stub in `crates/boundary/tests/s00_conventions_clauses.rs`. `compat_memcpy_2_2_5_is_overlap_safe` in
   `crates/boundary/tests/s04_strings_symbols.rs` says `no spec clause`: retag it with `s0_6_c0_6_0`. Gap: add a check
   on `target/liella/libc.so.6` that each name the clause lists as no longer linkable that Liella exports (`gets`,
   `sys_errlist`, `_sys_siglist`, `pow10` in libm, `sigvec`, `ustat`, `stime`, `__malloc_hook`; take the list from
   `spec/abi/compat-plan.tsv`, not from memory) has only non-default versions, and that `memcpy` has both
   `memcpy@GLIBC_2.2.5` and `memcpy@@GLIBC_2.14`. Code: `liella_compat_memcpy_GLIBC_2_2_5` in
   `csys/src/machine/compat_aliases.S` (generated by `cargo xtask compat-gen`, `xtask/src/compat.rs`).

Plants (each under `timeout 600`, RAM copy, fresh directory, restore with `cat backup > file`; a pattern that does
not apply fails the script): (a) `old_cond_signal` returns Ok without waking -> `s22_5_c_1_2` CAUGHT (a hang is
caught by timeout); (b) `core::system::domainname` copies `nodename` -> `s24_5_c_3` CAUGHT; (c) the generator emits
`gets` with a default version -> `s0_6_c0_6_0` CAUGHT; (d) `liella_compat_memcpy_GLIBC_2_2_5` jumps to the forward
copy -> the retagged overlap test CAUGHT. Script exits non-zero on a survivor.
