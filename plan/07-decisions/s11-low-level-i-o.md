#### §11: Low-level I/O

| ID | Spec | Ann. | Decision |
|---|---|---|---|
| D-11.1 | §11 | KERN | Thin wrappers keep the kernel contract exactly. Internally they are typed methods on `Fd` with `Result`. |
| D-11.2 | §11.1 | HIST | **Internal:** `OpenOptions` is a typed builder, with `mode` required iff creating (type-level). **Boundary:** the variadic `open` trampoline (F11) and `__open_2` validation. `openat2` resolve flags are exposed internally (H17). |
| D-11.3 | §11.3 | KERN, HIST | Single transfers keep short-count semantics (⚑ KERN). Internal `read_exact`/`write_all` helpers are offered. `SIGPIPE` stays kernel behaviour for `write`. Internal socket sends use `MSG_NOSIGNAL`. |
| D-11.4 | §11.7 | ARB, HIST | `fd_set` is kept at 1024 (ABI). `select`/`pselect` translate to `pselect6`. `FD_SET` beyond 1024 is caught by `__fdelt_chk` (contract). Internally, polling uses `poll`/`epoll` values with no limit. |
| D-11.5 | §11.8 | HIST | `posix_fallocate` emulation writes zeros **only into holes found with `SEEK_HOLE`/`SEEK_DATA`**, never over data, and refuses `O_APPEND` descriptors with `EBADF`, per the contract. This removes the data-clobbering race (observable, safer). |
| D-11.6 | §11.9 | HIST | `copy_file_range` has no emulation (contract). An internal `copy_all` falls back to `read`/`write`. |
| D-11.7 | §11.10 | HIST | **Internal:** `Mapping` RAII values expose only safe views: read-only file maps as `&[u8]`, anonymous maps as `&mut [u8]`. **Boundary:** raw addresses. `MAP_FAILED` comes from `ret`. `posix_madvise(DONTNEED)` stays a no-op (contract). |
| D-11.8 | §11.11 | HIST | POSIX AIO runs on **io_uring** when it is available and permitted, falling back to a worker pool. Completion order per fd and priority is preserved, per the contract (observable: fewer threads). |
| D-11.9 | §11.13 | HIST | **Internal:** `FileLock{kind: Ofd | Flock | ProcessRecord}` with explicit ownership. **Boundary:** `lockf`/`fcntl`/`flock` keep their distinct kernel semantics (observable, so kept). |
| D-11.10 | §11.1, §11.5, §11.6, §11.10, §24.1, §24.6, §25.2 | HIST | **Variadic entry points (phase 5).** `open`, `openat`, `fcntl`, `ioctl`, `mremap`, `semctl`, `ulimit` and `syscall` are C adapters (`csys/src/adapter/variadic.c`) forwarding to fixed-arity `LIELLA_PRIVATE` exports. The optional argument is read unconditionally: an absent `int` or pointer is an unspecified register value on x86-64, which the Rust side ignores for the commands that take none. `syscall` reads its six arguments in order, one statement each. `prctl` (§18.9) arrives with its section in phase 11. |
| D-11.11 | §11.11 | HIST, KERN | **POSIX AIO (phase 13); decisions** (realises D-11.8). io_uring when setup works (256 entries, a 4096-entry completion queue, `FEAT_NODROP` and the needed operations checked by probe); any refusal (`EPERM`, `ENOSYS`, `EACCES`, `ENOMEM`, a missing operation) silently selects a worker pool (up to 64 threads; `aio_init`'s `aio_threads` sets it); the choice is made per process, again in a fork child. One helper thread is the ring's only submitter, under the module lock, with all application signals blocked (so `SIGPIPE`/`SIGXFSZ` never reach the application). Requests are serialised per descriptor number (the spec's submission order), lower `aio_reqprio` first; `aio_fsync` is a barrier. io_uring is made to behave like `pread`/`pwrite`: `ESPIPE` reruns at offset 0, `O_NONBLOCK` non-regular files get `RWF_NOWAIT`, short blocking writes continue, counts are capped at `MAX_RW_COUNT`, a buffer reaching 2^63 is `EFAULT` (the kernel's rule). A started request is never cancelled; `close`, `close_range`, `closefrom`, `dup2`, `dup3` cancel requests not yet started (`ECANCELED`; glibc reports `EBADF`); `exec` cancels and does not wait; a fork child starts empty and can run requests (glibc's child cannot: POSIX says nothing is inherited). Notifications: `SIGEV_SIGNAL` via `rt_sigqueueinfo` with `SI_ASYNCIO`; `SIGEV_THREAD` in a new thread with the attributes copied at submission (stack size and address, guard, scheduling, affinity), always detached (owner ruling 2026-10-04, POSIX 2.4.2; the reference honours joinable), empty mask; a caller-supplied stack serves one notification at a time (owner, 2026-10-04; `boundary::stacks`, shared with D-23.3 and D-25.5): requests completing together notify one after another, each once the previous thread on an overlapping stack has left it (the reference starts them at once on the one stack: a probe crashed 3 of 3 runs); a notification whose thread cannot be made (thread limit, memory), at once or after it waited for its stack (`boundary::stacks` hands it back: `aio::abandoned`), is not dropped (glibc drops it) but retried, like a timer's (owner ruling #680, extending #269, NOTIFY-RETRY-MQ-AIO 2026-10-22; gain: a completion is notified late instead of never when threads or memory are short for a moment; a deliberate difference with a compat-flag placeholder, as #269's; such a flag would be read only after a refusal, so the default path would pay nothing): its block is kept and the timers' helper (D-23.3) retries it with the timers' back-off (10 ms doubling to a 1 s ceiling; `aio::retry_due`), once per request, until a thread starts; the helper is made with the process's first `SIGEV_THREAD` request or list (one thread and two descriptors per process, shared with the timers; once made, a submission pays one atomic load), and a fork child does not inherit a pending retry; the request's result stays for `aio_error` and `aio_return` meanwhile (tests `aio_refused_notification_retried`, `aio_abandoned_notification_retried`); a NULL function is `EINVAL` at submission (glibc crashes). `AIO_LISTIO_MAX` has no fixed value (lists bounded by memory; glibc crashes at 1,048,576); a negative `nent` is an empty list; after `EINTR` the remaining entries complete normally (glibc crashes). `aio_suspend` returns `EINTR` after any handler, 0 when nothing is in progress. One global lock (optimization targets: per-descriptor sharding, linked submissions). **Kernel 5.10 (validation stage, 2026-10-05):** io_uring differed from `pread`/`pwrite` there: `RWF_NOWAIT` on a pipe is `EOPNOTSUPP`, socket reads never completed, and a count beyond the buffer is `EFAULT` where `pread` transfers what the file holds. Decided: with the ring, reads and writes on descriptors that are not regular files or block devices (an `fstat` at submission) run on worker threads with `read`/`write` (exactly the system call's answer, `O_NONBLOCK` included, on every kernel), and a transfer the ring refuses with `EFAULT` runs again on a worker; these workers are not bounded by `aio_threads` (at least the default 64), so with the ring `aio_init` still bounds nothing. Tested by `aio_products` on 5.10 and 6.8. **Owner rulings (2026-10-04):** io_uring by default, with guards: the workers are chosen without trying io_uring in secure-execution mode, under any seccomp filter on the calling thread (a filter that kills on an unlisted call would kill the process at `io_uring_setup`), detected first without `prctl` from the `Seccomp:` line of `/proc/thread-self/status` (owner, 2026-10-04: the second check; decided: the thread's file, not `/proc/self`, since a filter is per thread and the calling thread makes the ring and its helper; trusted only when `fstatfs` says procfs; any value but 0 settles it and `prctl` is not called), then, when procfs says 0 or cannot be read, `prctl(PR_GET_SECCOMP)` other than 0, a failure included (observed on 6.8: 2 under a filter, the filter's errno when it refuses the prctl, 0 for `RET_ERRNO|0`, death for a kill action; with procfs readable, the last two are now caught too, tested with such filters; the documented limit is left only where procfs is unreadable), after the native `liella_aio_use_threads` (`LIELLA_NATIVE_1`; `-EBUSY` once the ring has started; kept in `fork` children), or with `LIELLA_AIO_URING=0` (read by `secure_getenv` at the first request; only the exact value `0`); a kernel refusal still falls back silently (tested end to end through the injected-failure kernel: `selftest::aio_choose_engine` takes a `Faulty<CSys>`, whose plan reaches `io_uring_setup` and the probe by the names in `liella_kernel::testing::RAW_FALLIBLE`, and the eventfd, the descriptor flag and the procfs reads by their `Sys` names; a refused setup leaves no descriptor). In a hosted (test) build where `/proc/self/auxv` is unreadable, differing real and effective IDs count as secure (a set-ID process cannot read its own auxv). `aio_return` repeated returns the same status (§11.11 since 2026-10-04); `aio_suspend` with nothing in progress returning 0, a `{LONG_MAX,0}` timeout as expired, `LIO_NOWAIT` with an invalid priority returning -1 `EINVAL` while other entries run, `aio_cancel` with a mismatched descriptor `EINVAL` stay as the reference. Follow-up (decided): the io_uring system calls join `csys/syscalls.tsv` and the A.1 tests (done 2026-10-04: area `io`, `raw` calls the wrappers, `k_io_uring_setup`/`_enter`/`_register` through `selftest`, which passes on no flag that lets the kernel consume or address memory on its own). |
