Planning only. Base: `origin/next` at `d5db1cea`. These stories stay clear of the chains in flight:
the f128 complex Ziv chain (MATH-M5-CPLX-F128-ZIV-*, CPOW-EXACT, M5-CLOSE, CPLX-DIRECTED), the f64 gap chain
(MATH-M6-F64-GAP-*), the mutation campaigns (MUTATION-CAMPAIGN-*, COLLATE-STRXFRM-DA-WEIGHT-2), the perf
batches of register sections 13/14 (strnlen/rawmemchr, strcasecmp SSE2, heap pair, wctype, getc/putc, fnmatch),
the compat/RPC integration (INTEGRATE-COMPAT-A/B, COMPAT-*, RPC-*) and ARCH-SEAMS/ARCH-SYSCALLS.
In-flight list from `ops status` (2026-10-24 09:25Z), `handoff/reports/` and `docs/saturation-register.md` §12.

**Sources read.** `spec/schedule.tsv` (every phase 0-13 owner is `done`; the open pending tests belong to
phases 14/15 or the 8 UNASSIGNED C0 clauses), the "Deviations and open items" and "Untested" lists of
`plan/06-phases/` phases 8-13, `plan/07-decisions/` D-X.12 and D-16.5, the register's §7, §8, §11 and §12.
The spec-symbol gaps are closed (SPEC-SYMBOLS-TRIAGE, SPEC-GAPS-4), so there is no missing-symbol story here.
The correctness gaps that remain are **untested paths** (no `/proc`, kernel `ENOSYS` fallbacks, privilege) and
**spec gaps that were never settled by a probe**. These come first, then tooling that removes a repeated
failure class, then measurement that turns unmeasured register claims into numbers. There is no hot-path perf
row with a measured gap that is not already in flight (strcasecmp short rows: PERF-STRCASECMP-SSE2-*;
strnlen/rawmemchr: PERF-STRNLEN-*; gettext no-catalog: its remainder waits on a ruling, GETTEXT-NOCATALOG-PERCALL).

**Independence.** Every row adds its own new test file or document. No two rows edit the same source
file. A defect a test-only row finds becomes a new story, so the test rows do not fix code in shared modules
(`pthread.rs`, `spawn.rs` ...). Exception: the row allows a fix of five lines or fewer that no other row in
this batch touches.

**Rules for every row.** The clean room (no libc or libm source, black-box probes only). The direct-tier gate,
plus plants on the code or tests the story adds. Plants run from a RAM copy, one new directory per run.
`cargo xtask static`, which includes the traceability rule: each new test names a spec ID, a clause ID or
`no spec clause`. No file-system dependence. Unprivileged user and mount namespaces (`unshare -r -m`) are a
standing yes, but every other root action is not, and nothing probes `sudo`. Differences from glibc follow
glibc unless they gain something concrete. A suspected security weakness goes only to SECURITY-PRIVATE.
The stressful-environment rule applies to every row.
