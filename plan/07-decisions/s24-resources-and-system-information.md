#### §24: Resources and system information

| ID | Spec | Ann. | Decision |
|---|---|---|---|
| D-24.1 | §24.4 | HIST | **Internal:** `sysconf(Query) -> Result<Option<i64>>`, where `None` means no limit. **Boundary:** -1 without errno, per the contract. |
| D-24.2 | §24.4 | HIST | **Internal:** `available_parallelism()` = affinity ∩ cgroup CPU quota, the accurate answer the spec says is missing. `get_nprocs` and friends keep their contracts. |
| D-24.3 | §24.3 | ARB, COMPAT | **Internal:** `CpuSet` is dynamic. **Boundary:** `cpu_set_t` is 1024 bits, plus the `CPU_ALLOC` sized forms. The old unsized `sched_setaffinity` version is legacy. |
| D-24.4 | §24.3 | KERN | The `getpriority` 20−nice bias is undone in `liella-kernel`. |
| D-24.5 | §24.6 | HIST | `syscall()` is exported (thin). Typed wrappers for the modern interfaces exist internally (D-H17). Clause `s24_6_c_5` (milestone 5): calls by number, including ones nothing else wraps (`pidfd_open`, `memfd_create`), -1 with `errno` (`EBADF`, `ENOSYS` for an unknown number), and all six arguments in order through real C varargs (`conformance/c/s24_variadic.c`: `mmap` of a memfd at an offset). |
| D-24.6 | §24.4 | HIST | `sysconf`'s fixed answers and `confstr`'s texts are the reference glibc's, recorded by `spec/tools/sysconf_probe.py` in `spec/abi/sysconf.tsv` and generated into `legacy::sysconf_table` (`spec/tools/sysconf_table.py`). The answers that depend on the machine (limits, page size, clock ticks, processors, memory, caches, signal stacks) are computed by `liella::system` (D-24.1). The tests compare every name with the host glibc. |
| D-24.7 | §24.4 | HIST, ARB | **Known deviation (accepted 2026-10-01):** cache geometry (`_SC_LEVEL*`) comes from the deterministic cache leaves (Intel leaf 4, AMD 0x8000001D). glibc's leaf-2 descriptor table is not reproduced, so a CPU that describes its caches only through leaf 2 could answer differently. glibc's conventions are kept: the level-1 instruction cache's associativity and level 4's associativity and line size are -1, as is an absent level, except that on AMD and Hygon an absent level 4's size is 0 (found on an AMD EPYC host, phase 7). |
| D-24.8 | §24.3 | KERN | D-24.4 realised: `liella_kernel::uapi::nice_from_priority` undoes the bias (`Sys::getpriority` returns the system call's value, as its contract documents); `getpriority` and `nice` use it. Phase 1's `CSys::getpriority` was reported to C callers biased until phase 5 found it. |
| D-24.9 | §24.5 | HIST | `gethostid`/`sethostid` live in `liella_legacy::sys_compat`. `/etc/hostid` holds 4 native-order bytes, created with mode 0644; a shorter or empty file counts as absent, and of a longer one only the first 4 bytes count (observed 2026-10-03 with an owner-approved root probe in a private mount namespace over a tmpfs `/etc`; a directory in its place gives `EISDIR`). Without the file, the result is the node name's IPv4 address (D-15.6) with its 16-bit halves exchanged (observed), else 0. `sethostid` checks `EOVERFLOW` first (observed), gives `EPERM` when the effective IDs differ from the real ones (man page), and otherwise reports the open/write error (`EACCES`, observed). Tests never write the system's file. |
| D-24.10 | §24.4 | HIST | `_SC_ARG_MAX` = max(128 KiB, min(stack limit / 4, 6 MiB)), per execve(2) and a phase-11 probe (the reference returns 6291456 for 32 MiB, 64 MiB and unlimited stacks; Liella returned 2^62-1 for an unlimited stack before). |
| D-24.11 | §24.4–24.6 | HIST, KERN | **System identity and control** (validation stage, 2026-10-05; §24.5–24.6 had been left out of phase 13's scope, validation T2). `uname`, `sethostname`, `setdomainname`, `sysinfo`, `reboot` (the kernel's magic numbers), `acct`, `ioperm`, `iopl`, `vhangup` through `Sys`; `klogctl`, `quotactl`, `capget`, `capset`, `init_module`, `delete_module`, `modify_ldt` thin over the system call (their pointers mean what the command says; the kernel checks them, as for `syscall`). `gethostname` copies the node name and its NUL; when it does not fit, the bytes that fit are written and the result is `ENAMETOOLONG` (§24.5, the reference, probed); `getdomainname` cuts silently (getdomainname(2), the reference); NULL with a size is `EFAULT` (S6; the reference crashes); the `_chk` forms fortify the size. `getloadavg` reads `/proc/loadavg` (two decimals, as the reference) and stores at most three, none for a count of 0 or less (the reference returns 0 for a negative count). `gnu_get_libc_version`/`_release` are `"2.39"`/`"stable"` (three-way: the spec, gnu_get_libc_version(3) and the reference agree): the version of the ABI Liella implements (Appendix B), the same number as `confstr(_CS_GNU_LIBC_VERSION)`'s "glibc 2.39" (D-24.6); one library-owned string each. `modify_ldt`: the kernel returns a 32-bit result zero-extended (observed on 5.10 and 6.8: -ENOSYS arrives as 4294967258); its low 32 bits are the result and a negative one is -1 with `errno` (modify_ldt(2)), where the reference returns the negative value with `errno` untouched (a difference); three-way: the spec's thin wrapper and modify_ldt(2) agree. `CSys::modify_ldt` (the `Sys` read used by the kernel-primitive tests) had the same flaw and reads the result as an `int` too (found by the ledger thread). `_SC_MINSIGSTKSZ` without `AT_MINSIGSTKSZ` (x86 kernels before 5.14): the frame from the XSAVE size counts 64 bytes of alignment padding (448 + 64 + XSAVE + 4; 1348 on an EPYC 7551 under 5.10, the reference's value), where 48 had been counted. Tests (merged 2026-10-04 with the ledger thread's implementation of the same functions, whose tests now run against this one): unprivileged (EPERM, and the argument checks the kernel makes first), in a private user namespace (a namespace root's capability sets read, lowered and raised with `capset`; the rest still refused), and as the first process of a private PID namespace (`reboot`'s commands reach the PID-namespace rules: `EINVAL` for the others, `RB_POWER_OFF` ends the namespace with `SIGINT`), each compared with the reference in `admin_products.rs`; `syscall` with all six arguments in `conformance/c/s24_variadic.c` (clauses `s24_5_c_5`, `s24_6_c_1`, `s24_6_c_4`, `s24_6_c_5`). The compat entries of removed system calls (`bdflush`, `create_module`, `get_kernel_syms`, `query_module`, `nfsservctl`, `sstk`, `sysctl`, `__sysctl`, `uselib`) are phase 15's (§29 removed-syscall stubs). |
