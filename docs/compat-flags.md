# Compatibility flags (registry)

Liella deliberately differs from glibc 2.39 in a few observable behaviours (the full list of
differences is in `differences-from-glibc.md`). Owner philosophy (2026-10-10): where a program
might depend on glibc's behaviour, even wrongly, give it a way to get that behaviour back when
that costs nothing on the default path. This file registers each such behaviour and how a
flag would restore it. A row here is a promise to design the flag, not an implemented flag.

Mechanism (implemented for COMPAT-12; a design note for the others): `GLIBC_TUNABLES` is already parsed once at startup
(`runtime.rs`, `liella::config::Tunables`) and `cpu::init_with` already picks code paths from it
once per process. A compat flag would be one more tunable, read there and stored in the same
read-mostly startup state. Whether a flag is free depends on the row: where the restored
behaviour is a different function, the export would need a resolved-once pointer or a branch
on startup state, which is NOT free on a hot call; such a row names a cheaper route (for
example a separate preloadable object) or stays registered only. COMPAT-12 is the first
implemented flag (the tunable `liella.compat.rpc_reply_any_source`, ignored in a secure process);
every other row is registered only.

| COMPAT-1 | `bcmp` return value (§4.3; D-4.43) | Non-zero for unequal operands is the sign of the first differing byte pair, as `memcmp` | 0 when equal, exactly 1 otherwise (the equality kernel of `__memcmpeq`, D-4.41); no order | A `compat` tunable read at startup makes `bcmp` take the ordered `memcmp` kernel (`hot::compare_bytes`). | COMPAT-2 | `strcoll` on punctuation (§4.3, §4.4; D-4.42) | Disagrees with its own `strxfrm` ordering for some pairs (undocumented deviation, 68,836 of 29.8M tested pairs) | POSIX: orders exactly as `strcmp` of the `strxfrm` keys | A tunable selecting the reference comparison path for the locale collation tables; needs the old comparison kept as a second path | none today | registered |
| COMPAT-3 | `dl_iterate_phdr` and other WEAK exports: symbol binding (§27; D-27.4, CONF-SYMS-2, D-X.14) | Binds WEAK for the exports glibc declares weak (the `scope` column of `spec/abi/versions.tsv`); `libc.a` has the rest strong | `libc.so.6`: matches glibc since WEAK-EXPORTS (0 binding differences on the common exports; `cargo xtask so` checks every build against the table). `libc.a`: every definition is WEAK (D-X.14), so a program's strong definition wins where glibc's archive would give a duplicate-definition link error (differences row "Symbol binding in `libc.a`") | Not a runtime flag: binding is fixed at link time. | COMPAT-4 | Regex compile limit on stacked or nested `+` (§14.9; D-14.8 amendment, owner ruling 2026-10-10) | `regcomp` expands each `+` into a second copy of its operand, so stacked or nested `+` grow exponentially and fail with `REG_ESPACE` (from 24 stacked `+` on `b*`; 12 stacked take 10 s and 882 MB) | One copy of the operand per `+`: the program grows about linearly (quadratic at most for nested scopes) and these patterns compile; `{m,}` with m >= 2 and bounded repeats still stop at the 2^21-node cap with `REG_ESPACE` (D-14.4). Same class (DFA-TIMEOUT, coordinator ruling 2026-10-11): the back-reference work budget (`re_max_failures` x 65536) charges the work of each thread insertion (buckets probed, groups x capture classes), not one unit per insertion, so nested back-reference patterns such as `(a*)*(a*****...` answer `REG_ESPACE` in bounded time (all pinned fuzz inputs together 1.2 s at the fuzz budget of 16 failures; one took 7-9 s before) and may answer it earlier than before | A tunable selecting a lower node cap for `+` expansion that makes `regcomp` answer `REG_ESPACE` at glibc's stacking depth; the compile path already counts nodes, so the check is one compare per allocation | none on matching; compile time only | registered |
| COMPAT-5 | Seek inside the read-ahead (§12.8; D-12.22, owner ruling 2026-10-10) | A `SEEK_SET`, `SEEK_CUR` or `SEEK_END` seek (or `rewind`) to a position inside the bytes already read ahead keeps them and moves the read pointer; a later read returns the buffered (possibly stale) bytes | Since STDIO-SEEKWIN the default keeps the buffer as glibc does for `SEEK_SET`/`SEEK_CUR` targets in `[window start, window end]` once the stream knows its descriptor offset (one `lseek` to the window end, result not used); see the differences row. Remaining differences: a `SEEK_END` target inside the window takes the full seek and re-reads, a target exactly at the window end stays in the window, and a failing `lseek` there leaves `errno` alone. The spec-literal behaviour (s12_8_c_1: discard the window on every seek and re-read) is no longer the default | Two directions. (a) Spec-literal: a tunable read at startup that makes the in-window test fail, so every seek re-reads (one branch on the seek path, which already tests the window). (b) glibc's `SEEK_END` case: keep the window for a `SEEK_END` target inside it; this needs the file size (`fstat` or a second `lseek`) on that path, so it is not free and stays registered only | none today (neither flag exists); the in-window test itself is on the default seek path since STDIO-SEEKWIN | registered |
| COMPAT-6 | Full-buffer flush granularity (§12.1; STDIO-FLUSH-56 black-box probe, owner ruling 2026-10-11) | On a fresh fully buffered stream the first `fputs`/`fwrite`/`fprintf` write goes straight to the descriptor; later writes buffer, and a full buffer is written whole (64 of 64 bytes with a 64-byte `setvbuf` buffer; an `fputc` loop writes 64 at the 65th byte) | Buffers from the first write; when the buffer fills it writes 56 of 64 bytes and keeps an 8-byte tail. Both satisfy §12.1 and ISO C (output reaches the file when the buffer fills); only programs that watch the file length or pipe contents mid-run, or mix `write(2)` with the stream on one descriptor, can see it | A tunable read at startup selecting whole-buffer flushes and first-write pass-through on the write path; implement only if it costs nothing on the default path | none today (the flag does not exist) | registered |
| COMPAT-7 | `getopt` after the caller replaces `argv[optind]` mid-cluster (§1.6; D-1.6, COLD-REWRITE2-W-far-07-PROOF-2, owner ruling 2026-10-21) | Goes on reading the string it was reading when the caller stores a different pointer in `argv[optind]` between two calls in the middle of an option cluster (the cursor is a pointer into the old string) | Reads `argv[optind]` as it is now: an element shorter than the cursor position is read again from its start at the same index (cut in place, both read the element again from its start). The owner is not confident either behaviour is the right one | A tunable read at startup (and kept in the parser state) making the boundary hold the old string pointer between calls inside a cluster; the parser core already works through the `Args` trait and would need no change. Not designed further until the owner decides which behaviour is the default | none today (placeholder only, behaviour unchanged; any flag must cost nothing on the default path or stay registered only) | registered |
| COMPAT-8 | `%#g` after a rounding carry (§8.4, §12.6; D-8.11 (3), owner ruling 2026-10-22, #573) | With the `#` flag, a value that rounds up to the next power of ten keeps no digit after the point: `printf("%#.2g", 99.5)` gives `1.e+02`, `%#.3g` of 999.5 gives `1.e+03` | C's rule: the precision counts significant digits and `#` keeps trailing zeros, so the same calls give `1.0e+02` and `1.00e+03`. The owner called this borderline and kept the C output | A tunable read at startup making the `#` general-format path drop the zero digits after a carry. Not designed further; the affected code is the cold number-text core, so a flag would not touch a hot call | none today (placeholder only, behaviour unchanged; any flag must cost nothing on the default path or stay registered only) | registered |
| COMPAT-9 | Login-record times after 2038 (§17.6; D-17.5, F38, owner ruling 2026-10-22, #415) | Not observable without changing the clock (the 32-bit `ut_tv.tv_sec` is a signed member; a caller's 32 bits are written as given) | `logwtmp`/`logout` stamp, and the record translations keep, times to 2106-02-07 06:28:15 UTC as unsigned 32-bit seconds; before 2038 the bytes are glibc's | A tunable read at startup lowering the bound in `users::ut_tv` and `accounting::stamp` back to 2038-01-19 03:14:07 UTC, so later times are written as no time, `(0, 0)`, as before the ruling | none expected: the range check is the same single compare, against a bound read from startup state (cold path: login accounting only) | registered |
| COMPAT-10 | An invalid x87 encoding (pseudo-NaN, pseudo-infinity, unnormal) as an operand of a `long double` / `_Float64x` function (§10.3; D-10.20, X87-NAN-RULE-AUDIT-2, X87-INVALID-ENC-SWEEP, X87-INVALID-ENC-CPLX, owner ruling 2026-10-23, #902, #945). The rule covers every exported `long double` function; the functions where glibc differs are those in the x87 invalid-encoding row of `docs/differences-from-glibc.md` (`fmaxl`, `fminl`, the four `_numl` selections, `nextafterl`, `nexttowardl`, `powl`, `remquol`, and the complex functions), and the exceptions the standard makes are the `EXEMPT` table of `crates/math/tests/x87_invalid_sweep.rs` | Beside a number the result differs by function (the number operand, a neighbouring number, +0, −0, or an invalid encoding), invalid raised; the complex functions give `7fffc000000000000000` in their NaN parts | The default NaN with the invalid flag raised (every NaN part of a complex result), as every other `long double` operation | A tunable read at startup selecting glibc's results for the functions where glibc differs; the check sits on the path that already tests for an invalid encoding, so the default path gains no branch | none today (the flag does not exist; any flag must cost nothing on the default path or stay registered only) | registered |
| COMPAT-11 | `__libc_freeres` releases internal allocations (§29.4; LG-11 MALLOC-COMPAT, coordinator ruling #1317, provisional) | Frees libc's internal allocations (stdio, locale, iconv and other caches), so a leak checker run at exit sees no blocks still reachable from libc | Releases nothing: it returns at once and every internal allocation stays, so a call mid-run cannot tear down live state; leak checkers may report Liella's internal allocations as still reachable | A tunable read at startup making `__libc_freeres` run the internal teardown of the caches at exit. | COMPAT-12 | UDP RPC client: replies from an address other than the called one (§29.1; D-29.2, owner ruling 2026-10-23, #1643) | Accepts a reply with the matching transaction ID from any source address; a call with no reply ends in `RPC_TIMEDOUT` | Takes replies only from the called address and port; others are dropped whatever their transaction ID; a reply-shaped datagram from another address during a call that times out gives `RPC_CANTRECV` with `EREMCHG` | `GLIBC_TUNABLES=liella.compat.rpc_reply_any_source=1`, parsed once at start-up into `liella::config::Tunables` and stored by `s29_rpc_clnt::compat_from_start`; ignored in a secure (`AT_SECURE`, setuid/setgid) process because it weakens behaviour. | COMPAT-11 | `fnmatch` with `FNM_EXTMATCH` and `FNM_LEADING_DIR` together (§14.7; FNMATCH-EXTMATCH-LEADING-DIR-2, coordinator ruling #1823 2026-10-24, owner confirms) | For the 16 probed pairs (`!(a)` on `a/b`; `+([ab])c` on `ab/c`; listed in `docs/differences-from-glibc.md`) answers differ from the documented `FNM_LEADING_DIR` rule: `!(...)` patterns lose matches that the whole string gives, and `+(...)`/`*(...)` patterns match across a `/` that the group cannot contain | The documented rule for every pattern kind: the whole string, or an initial segment followed by `/`; `FNM_LEADING_DIR` only adds matches | A tunable read at startup selecting the reference's answers for extmatch patterns under `FNM_LEADING_DIR`. Rules for adding a row: give the behaviour, both sides, the way a flag would restore glibc's,
its default-path cost, and the decision row. Mark `implemented` only when the flag exists and a
test forces it both ways. Do not add security-relevant glibc behaviours here (SECURITY-PRIVATE).
