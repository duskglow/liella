#### §13: File system

| ID | Spec | Ann. | Decision |
|---|---|---|---|
| D-13.1 | §13 | PATH | **Internal:** the file-system API is directory-relative only (`Dir` handle plus relative `KPath`). Path forms are translations passing `AT_FDCWD`. |
| D-13.2 | §13.2 | HIST, ARB | **Internal:** `Dir::entries()` yields borrowed entries. **Boundary:** `struct dirent` packing. `readdir_r` copies into the caller's buffer (compat). Names never exceed 255 bytes on Linux (NAME_MAX ⚑ KERN). **Removed directory (owner ruling 2026-10-03, three-way rule):** `readdir`, `readdir64`, `readdir_r` and `readdir64_r` report the kernel's `ENOENT` (`getdents64` fails with it on ext4 and tmpfs once the directory is removed: `spec/behaviour/fstree.md`): `readdir` returns NULL with `errno` `ENOENT`, the `_r` forms return `ENOENT`; entries already buffered are returned first. glibc ends the stream silently (a recorded difference). |
| D-13.3 | §13.2 | KERN | `telldir`/`seekdir` pass the file system's 64-bit cookie directly. `long` is 64 bits on this ABI, so the mapping table is not needed. |
| D-13.4 | §13.3 | HIST, COMPAT | **Internal:** walkers use `openat`-relative traversal and never change the cwd. They have no depth limit and no `nopenfd` tuning (P-lift). **Boundary:** where the contract makes cwd changes observable (fts without `FTS_NOCHDIR`, `FTW_CHDIR`), legacy performs the `fchdir` calls. **fts paths (FTS-SHARED-PATH, ruling #615, reverses #557):** one path buffer per stream, as fts(3) allows and as the reference does: every `FTSENT`'s `fts_path` points at it with `fts_pathlen` as the entry's length; only the entry `fts_read` returned last is NUL-terminated there, and its ancestors (valid while the walk is inside them) are its prefixes. `fts_accpath` is `fts_path` (`FTS_NOCHDIR`, `FTS_LOGICAL`, roots) or the entry's own `fts_name` (chdir mode). When the buffer grows, every live entry is re-pointed. Behaviour change: entries kept past fts(3)'s validity rules, entries from `fts_children`, and entries the comparison sees show whatever path the buffer holds now (the reference behaves the same way). Gain: the per-entry copy of the parent path was ~225 of ~280 user instructions per entry at 2 KiB paths (FTS-DEEP-PROFILE). **fts instructions (FTS-INSTR-DIRECT, -2):** fts acts on the `fts_instr` an entry holds, written by `fts_set` or by the caller directly, as the reference does. On an entry `fts_children` listed, only what fts(3) defines is compared with the reference: `FTS_SKIP` on a listed directory means none of its descendants is visited, and `FTS_FOLLOW` on a listed root shows the target. The rest is Liella's own behaviour, tested in `s13_3_c_4`, because fts(3) does not define it or the reference does not do what fts(3) says: a listed directory marked `FTS_SKIP` is never returned (the reference returns one only when it heads the list), a listed non-directory so marked is returned with `fts_instr` 4 (fts(3): `FTS_SKIP` concerns descendants only), a listed link marked `FTS_FOLLOW` is returned showing its target, or `FTS_SLNONE` when the target is missing (fts(3)), and a listed entry marked `FTS_AGAIN` is returned twice, as the reference returns it. |
| D-13.13 | §13.3 | HIST | **Walkers never abort (owner ruling 2026-10-03, binding).** Where the reference library aborts or crashes, Liella returns an error with a documented `errno`: `nftw` with `FTW_CHDIR` on a tree whose paths outgrow the walk (glibc fails an internal assertion past about 4.2 KB, and passes the callback an empty path one level earlier) returns -1 with `ENAMETOOLONG` only where a path the walk must form or pass cannot be represented, and otherwise walks on (D-13.4: `openat`-relative, no depth limit); `fts_open` with an empty argument list returns NULL with `EINVAL`; `fts_children` after the walk has ended returns NULL with `errno` 0, as at the end of a directory. Each is a deliberate difference (`docs/differences-from-glibc.md`). |
| D-13.14 | §13.1–13.3, §13.8–13.9 | HIST, ARB | **Implemented (phase 12); decisions.** *cwd:* `getcwd` asks the kernel, and on `ENAMETOOLONG` walks `..` (`openat`/`getdents64`/`fstatat`, by inode then `stat`); an unreachable directory is `ENOENT` with the kernel's `(unreachable)…` text left in the buffer; `getcwd(NULL, n)` allocates n bytes; `getwd` beyond `PATH_MAX` is `ENAMETOOLONG` (getwd(3); glibc `ERANGE`), NULL `EINVAL`; the `_chk` forms terminate per D-C0.5 literally. *Streams:* a 32 KiB buffer; `readdir` returns the kernel record in place; `opendir` uses `O_NONBLOCK\|O_CLOEXEC\|O_DIRECTORY`; `fdopendir` refuses `O_PATH` and write-only descriptors (`EBADF`), sets close-on-exec and keeps the position; a NULL `DIR*`/`FTS*` is `EINVAL`, a closed one `EBADF`; `readdir_r` with a name over 255 bytes is `ENAMETOOLONG`; `getdirentries` with a NULL `basep` is `EFAULT`; `scandir`'s sort is stable and `*namelist` is written only on success. *Walks:* `nftw` reports each directory once (a global dev/inode set only when following links); `EACCES` from `stat` gives `FTW_NS`, `ENOENT` on a symlink `FTW_SLN`, an `EACCES` open `FTW_DNR`, other `stat` errors end the walk with -1; `nopenfd` is ignored (D-13.4; descriptors are closed and reopened on `EMFILE` with a dev/inode check); with `FTW_CHDIR` the caller's cwd is always restored through an `O_PATH` descriptor; fts: an empty `argv` is `EINVAL`, NULL `EFAULT`; `fts_set` accepts only 0, `AGAIN`, `FOLLOW`, `SKIP` (else -1 `EINVAL`, fts(3); glibc 1); `fts_cycle` points to the ancestor (fts(3); glibc too: FTS-SHARED-PATH found the earlier "glibc the entry" record was the shared path buffer read through the ancestor); `FTS_NOSTAT` skips `stat` unless `d_type` is `DT_DIR`/`DT_UNKNOWN`; a path over 65,535 bytes or a level over 32,767 is `FTS_NS` `ENAMETOOLONG`; `fts_read`/`fts_children` set `errno` to 0 when returning NULL without error, as fts(3) requires (**an exception to X3**). *realpath:* at most 40 links per call; `..` is applied without examining the directory it leaves; the allocating form has no limit (D-13.5), a caller buffer `PATH_MAX`; on failure the buffer holds the resolved prefix including the failing component for `ENOENT`/`EACCES` and is untouched otherwise (as glibc; §13.8 amended 2026-10-03 by owner ruling: the contents are unspecified after any failure). *Temporary names:* 238,328 (62³) attempts, then `EEXIST`, the template keeping the last name tried; names from 64-bit `getrandom` (`GRND_NONBLOCK`) with a clock fallback; the access mode is replaced by `O_RDWR`; a negative suffix length is `EINVAL`; `mktemp` empties the template on failure (mktemp(3)). **Owner rulings (2026-10-03):** `get_current_dir_name` accepts `$PWD` only when it is absolute, has no `.` or `..` component and names the working directory (same device and inode), else the physical path; `$PWD` is ignored in secure-execution mode (`spec/security/threat-model.md`, environment list). Compat-only `nftw@GLIBC_2.2.5`, `nftw64@GLIBC_2.2.5`, `realpath@GLIBC_2.2.5` wait for phase 15. |
| D-13.15 | §13.13 | HIST, ARB | **Mount tables and fstab (phase 12); decisions.** *Format:* fields split at runs of space/tab; a first non-blank `#` is a comment; missing strings are empty and missing numbers 0; fields after the sixth are ignored (fstab(5)). *Escapes:* `\040 \011 \012 \134` and `\\` are decoded, every other backslash kept (§13.13 corrected 2026-10-03); `addmntent` writes the four octal forms. *Numbers:* `freq` and `passno` each from their own field (optional sign, decimal prefix, 0 without digits); a value outside `int` makes the line not an entry (glibc wraps it, and zeroes `passno` when `freq` is malformed). *A line containing NUL* is not an entry and the next line is kept (glibc loses it). *No line-length limit* (P-lift; glibc keeps 4095 bytes silently). *`getmntent_r`:* the buffer holds only the four strings; too small (0 and 1 included) is `ERANGE` with nothing written and the stream back at the line's start (glibc truncates silently, and hangs with 1 byte); a negative size `EINVAL`, NULL arguments `EFAULT`/`EINVAL`. *End of table:* NULL with `errno` untouched (X3). *Result storage:* `getmntent` and the fsent functions return the calling thread's result block (kinds `MNT`, `FS`). *`setmntent`:* `fopen` with close-on-exec added. *`endmntent`:* 1 always (getmntent(3)); NULL a no-op. *`addmntent`:* seeks to the end before each write, writes and flushes one line; `EINVAL` (1, nothing written) for a NULL entry or field, an empty string, or a source starting with `#` (entries that would not read back). *`hasmntopt`:* a query without `=` matches an option by name (`name` or `name=…`), one with `=` matches exactly, a comma in the query matches nothing; NULL arguments give NULL with `EINVAL` (glibc crashes). *`fs_type`:* the last of rw/rq/ro/sw/xx by option name (a later option overrides an earlier one, mount(8)), `??` if none. *fsent:* a process-wide cursor opened on first use (getfsent(3)); `setfsent` rewinds, and gives 0 with `EISDIR` for a directory; `getfsspec`/`getfsfile` search from the start through their own descriptor and leave the enumeration where it was (glibc moves it). Thread-block result slots grew for the two kinds (`SLOTS` 17, `RECORDS_AREA` 224 bytes; D-16.7). |
| D-13.5 | §13.8 | HIST, ARB | **Internal:** `canonicalize(dir, path) -> TryVec<u8>`, with no length limit. **Boundary:** `realpath` with a caller buffer assumes `PATH_MAX`, per the contract. `__realpath_chk` uses the real size. |
| D-13.6 | §13.9 | ARB | The template must end in exactly six `X`s (contract, kept). Internally, the random suffix length is a parameter. |
| D-13.7 | §13.7 | HIST | Internally, `umask_get()` reads `/proc/self/status` (race-free). `access` keeps real-ID semantics. `euidaccess` prefers `faccessat2(AT_EACCESS)`. |
| D-13.8 | §13.10, §13.13 | HIST | `statvfs` flags come from `statfs.f_flags` (kernel ≥ 2.6.36, OD-5). There is no `/proc/mounts` scan fallback. Mount tables are parsed from `/proc/self/mountinfo` internally, and `getmntent` keeps its text format. |
| D-13.9 | §13.7 | KERN | `lchmod`/`fchmodat(AT_SYMLINK_NOFOLLOW)`: **accepted 2026-10-01.** `EOPNOTSUPP` only for a symlink; every other file has its mode changed. **Kernel dependency:** Linux 6.6 and later answer through `fchmodat2` (one system call, symlink refusal by the kernel). Linux 5.10–6.5 (the supported minimum is 5.10, OD-5) take the spec's glibc fallback: `openat(O_PATH \| O_NOFOLLOW)`, `fstatat(AT_EMPTY_PATH)` to refuse a symlink, then `fchmodat` on `/proc/self/fd/N`. The fallback therefore needs `/proc` mounted (OD-5 requires it); without `/proc` it fails with `EOPNOTSUPP` where 6.6 would succeed (**changed 2026-10-05, milestone 6**, three-way rule: fchmodat(2)'s `EOPNOTSUPP`, the flag "is not supported", and the reference agree; it was `ENOENT`, which said the file does not exist). It is chosen per call by `fchmodat2`'s `ENOSYS`. On success `errno` is untouched (X3); the reference leaves its failed `fchmodat2`'s `ENOSYS` there on kernels before 6.6 (recorded, `noproc_products.rs` checks it only on such kernels). |
| D-13.10 | §13.13 | HIST | **Schedule (phase 5):** the mount-table functions (`setmntent`, `getmntent`, `getmntent_r`, `addmntent`, `endmntent`, `hasmntopt`, the `fsent` set) return or take `FILE *`, so they move to phase 12, after the streams (phase 8). |
| D-13.11 | §13.7 | HIST | `faccessat` with `AT_EACCESS`/`AT_SYMLINK_NOFOLLOW` uses `faccessat2`; where that is `ENOSYS` (a seccomp filter), glibc's emulation from `fstatat` and the credentials. The emulation allocates nothing (D-17.6), as an async-signal-safe function must. |
| D-13.12 | §24.4 | HIST | `pathconf`/`fpathconf` follow glibc's per-file-system tables (`_PC_LINK_MAX`, `_PC_FILESIZEBITS`, `_PC_2_SYMLINKS` by `statfs.f_type`). The ext2/3/4 family, which shares a magic number, is told apart by the mount's type in `/proc/self/mountinfo` (D-13.8). `_PC_PIPE_BUF` is 4096 for every file, pipes included, as glibc 2.39 answers. |
