#### §12: Buffered streams

| ID | Spec | Ann. | Decision |
|---|---|---|---|
| D-12.1 | §12.1 | HIST | **Internal:** the buffering engine (`liella::stream`) works over a `Backing` (a descriptor, a fixed memory buffer, a growing buffer, caller callbacks) and one buffer whose role switches automatically between reading and writing, so there is no "flush between input and output" restriction internally (phase 8 refinement: one buffer, as the ABI's single window exposes, instead of two). The first `RESERVE` bytes of the buffer are pushback room, so `ungetc`'d bytes stay inside the read window header-inline `getc` reads. Errors are reported, not retried (`EINTR` included); a failed write drops the unwritten bytes, as the reference library does. Input that flushes the line-buffered streams (ISO C) holds its own stream's lock, so it never waits for another stream's: a line-buffered stream in use by another thread is skipped, and so is the whole flush while another thread runs `fflush(NULL)` or `_flushlbf` (which may be waiting for the caller's stream); an `fopen` or `fclose` in progress is waited for. `__fbufsize` reports a caller buffer's size as given (the reserve is inside it). |
| D-12.2 | §12.1, §12.13 | HIST, COMPAT | **Boundary:** `FILE` is `abi::layout::FILE`. Its ABI-visible prefix (the buffer-window pointers used by header-inline `getc`/`putc` and `__uflow`/`__overflow`) aliases the stream's current window (F10). The rest is a pointer to the internal stream. `stdin`/`stdout`/`stderr`/`_IO_2_1_*_` are exported objects of that type. |
| D-12.3 | §12.2 | HIST | The mode-string mini-language is parsed by `legacy::stdio_compat::parse_mode` into typed `OpenOptions` (logic stays out of translation). `freopen` with a NULL path changes only what `fcntl` can (§12.2): the descriptor's access mode must allow the new mode (`EBADF` otherwise, as POSIX names it), `O_APPEND` follows `a`, `e` sets close-on-exec, and nothing is reopened or truncated. |
| D-12.4 | §12.6 | HIST | **Internal:** formatting is typed (`Arg` enum, `Spec`), with no `%n`. **Boundary:** `legacy::printf_va` decodes `va_list` by format. `%n` is honoured in the plain family. In `_chk` forms it is rejected when the format lies in writable memory: the format pointer is checked against the loader's read-only segment map (`ld`), and before phase 14 against the executable's read-only segments from `AT_PHDR`. |
| D-12.5 | §12.6 | HIST | The internal formatter returns `usize`. The boundary gives `EOVERFLOW` above `INT_MAX`, per the contract. **Owner ruling R3 (2026-10-05, validation T15):** a width or precision written in the format beyond `INT_MAX` fails every member of the family with `EOVERFLOW` before anything is output, as the reference does (it leaves the text before the conversion in a caller's buffer, Liella nothing: unspecified on failure); `*` counts are `int`s. |
| D-12.6 | §12.7 | HIST, COMPAT | **Internal:** the scan engine reports range errors per conversion. **Boundary:** three exported dialects. Overflowing integer conversions store the clamped value (the contract permits "wrapped or clamped"; clamped is chosen and documented). |
| D-12.7 | §12.10 | HIST | **Internal:** a stream is bytes plus an optional codec layer. **Boundary:** orientation locking is enforced in legacy (contract). |
| D-12.8 | §12.11 | HIST | Implemented under the clean-room rules of §1.4 (item 1) in a fresh session, from the spec, `spec/behaviour/printf-registry.md` and black-box probes. **Internal:** the engine knows registrations only through two hooks, `printf::Registry` while parsing (modifiers, and the arguments a registered letter takes) and `Env::custom` while rendering (the handler's output); the format language has no global state. **Boundary:** the registry is process-wide in legacy (contract): `legacy::printf_registry` keeps letters 0–255 (handler and argument function), sixteen modifiers (one `user` bit each; characters below 256, at most 64; a re-registered text gets a new bit and wins) and types 8–255 (`ENOSPC` beyond) in atomics; registration takes one lock (observable, stricter than MT-Unsafe), formatting takes none. A modifier is matched once, longest first, after the precision and before the length. An argument function is called with room for one type and again with room for all (for `parse_printf_format`, with the caller's room from its position); -1 or none means the built-in rules. A positional registered conversion takes arguments p to p+k-1 (the reference reads only p). Registered types are read by their own function on the caller's `va_list`, into objects the handler sees through a pointer. A handler gets a memory stream oriented like the destination and a `struct printf_info` whose length bits follow observation (`q` is `L`; `ll`, `w64` and `wf16`+ set `is_long_double` and `is_long`); what it writes is the whole field and is counted as written (its return value is ignored); -2 falls back to the built-in conversion (or the text as written); other negatives fail with its `errno` (`EINVAL` if it left 0, spec over reference). While anything is registered, stream output is collected and written at the end, so no handler runs while a stream record is borrowed. `printf_size` and `__printf_fp` (legacy, over `printf::float_text`) follow the observed rules (scaling by 1024/1000 by repeated correctly rounded division, units ` kmgtpezy`/` KMGTPEZY` by letter case, default precision 3). Reference behaviours matched that may be historical (candidates for a later cleanup): `__printf_fp`'s non-`f`/`e` letters use `%g` form with the exponent letter two below the conversion letter; `parse_printf_format` reports `PA_INT` for `%Li`/`%qi`; `printf_size` never scales negative values and drops the sign of a negative NaN. `registry_products.rs` compares the reference end to end with an empty KNOWN list. |
| D-12.9 | §12.12 | HIST | Internally, only exclusive creation of temporary files is offered. `tmpnam`/`tempnam`/`mktemp` are legacy. |
| D-12.10 | §12.5a | ARB, HIST | **Internal:** transfers report bytes. **Boundary:** `ret::elements(bytes, size)` gives the element count. |
| D-12.11 | §12.1, §12.13, C.7, C.9 | HIST, COMPAT | **The `FILE` object** (phase 8; refines D-12.2). A `FILE *` addresses 28 words: `struct _IO_FILE` and the vtable word of the exported `_IO_2_1_*_` objects. The buffer window and `_flags` (`_IO_EOF_SEEN`, `_IO_ERR_SEEN`, `_IO_USER_LOCK`, the public bits) are always current, so header-inline `getc`/`putc`/`feof`/`ferror` work; before each operation the engine re-reads the window (C code may have moved it). `_lock` points to the stream's recursive lock and `_codecvt` to Liella's record (state, backing, buffer); `_fileno`, `_mode` (orientation) and `_chain` (the open-streams list headed by `_IO_list_all`) are kept as glibc keeps them. Other `_flags` bits are not set: glibc's private meanings are not in the spec (gnulib reads some of them; revisit at the coreutils acceptance, phase 15). Streams the library opens live in slots that are recycled, never freed, so every `FILE *` it handed out stays readable. The standard streams are set up at first use: `stdout` line-buffered on a terminal, else fully buffered; `stderr` unbuffered; buffers sized by `st_blksize` (else `BUFSIZ`). The list lock is taken before stream locks; the ISO C flush of line-buffered output before input try-locks, so it never waits for a stream while holding another. `exit` flushes after the exit handlers; `fork` holds the list lock and the child frees stream locks held by threads that are gone. stdio functions are not cancellation points (§12 lists none). The stream data objects (`stdin`, `stdout`, `stderr`, `_IO_2_1_*_`, `_IO_list_all`) are exported by the products only: in the test pass with exports, the host library's own exit-time flush reads its objects of those names. `fmemopen` follows the reference library's observed rules (`w`/`a` keep room for a NUL after the data, `r+` does not; `w+` alone stores a NUL at open); its `GLIBC_2.2.5` compat contract comes with phase 15. Missing `fopencookie` callbacks are errors, as the reference library behaves. |
| D-12.12 | §12.6 | HIST | **The printf engine** (phase 8; IP-22, refines D-12.4). `liella::printf` parses a format once into literal runs and conversions; each conversion names its argument's index (and its `*` width's and precision's), so positional and sequential formats share one model, and the argument classes (integer register, `double`, x87 `long double`) are known before any is read. `legacy::printf_va` reads them through `abi::va::VaSource`, which the boundary implements with the C layer's `va_arg` accessors (`liella_va_long`, `liella_va_double`, `liella_va_ldouble`); the variadic names are C adapters forwarding the `va_list` by address to private entries, one per destination (stream, descriptor, caller buffer, allocation, obstack, and the wide forms). Rendering produces each conversion's body in the destination's units (bytes, or wide characters for `wprintf`) and pads it, so width and precision count what the destination counts; the locale gives the radix (which may be several bytes), grouping, thousands separator and the `I` digits; `%m` uses `errno` at entry and the reference texts of `spec/abi/errmsgs.tsv` (D-2.2). Observed reference behaviour followed (`printf_products.rs`, about 47,000 formattings compared): `%a` keeps a rounding carry in the leading digit (`0x2p+0`); `%La` prints the x87 significand nibble by nibble (`1.0L` is `0x8p-3`); `%%` ignores flags and width; a format ending inside a specification fails with `EINVAL` after the text before it; an unknown conversion is output as written; on an error `snprintf` still terminates what it wrote. The fortified forms reject `%n` in a format outside the executable's read-only segments (D-12.4). |
| D-12.13 | §12.7 | HIST | **The scanf engine** (phase 8; refines D-12.6; rewritten under the clean-room rules of §1.4, item 8, in a fresh session from the spec, `spec/behaviour/scanf.md` and black-box probes). `liella::scanf::scan` runs a format (bytes or `wchar_t`) over an `Input` yielding one unit at a time with one unit of pushback: bytes for the narrow functions; characters decoded by the stream's codec for `fwscanf`, or the string's units for `swscanf`. A field ends at the first unit that cannot continue it, which is given back; a field that is then only the start of a number is consumed and the conversion fails, as the spec's §12.7 guarantee says (`1e`, `1e+`, `0x` and `.` as floating fields, `-`, `infin`, a field cut by its width such as `%2lf` on `0x1p3`). Integer fields read like `strtol` (`d`, `i`) or `strtoul` (`o u x X b p`; `-` negates modulo 2^N) at the destination's width; out of range stores the nearest bound (D-12.6). The `0` of `0x`/`0b` is a digit (`0x` alone is 0); `0b` is a prefix for `%b` in every set and for `%i` in the `__isoc23_` set. Floating fields accept decimal and hexadecimal forms, `inf`/`infinity` and `nan` (not `nan(...)`) with the locale's radix, converted by the exact float engine (D-8.5) to `float`, `double` or x87 `long double` in the current rounding mode; with `'` the locale's thousands separator is accepted after a digit, without grouping validation. Text: `%c` stores what is there if input ends early; `%[` keeps a reversed range as three characters and `]`/`-` as literals first or last; byte input to `%ls`/`%lc`/`%l[` is tested byte by byte, decoded, the width counting characters; wide input to `%s`/`%c`/`%[` is encoded, with **one** terminator (the reference writes a second zero byte past it, which can overrun a buffer sized for the string: a deliberate difference, §1.4 goal). An invalid or incomplete sequence fails the conversion with `EILSEQ`, keeping what was stored. `%m` (and in the plain set `%a` before `s`/`S`/`[`) stores a `malloc`ed copy, and NULL when the conversion fails. `%n` stores the units consumed and is not a conversion. The result is the count of assignments, or `EOF` when end of input, a read error or an encoding error comes before the first conversion, suppressed ones included (spec over reference: the reference ignores suppressed ones); read and encoding errors also set `errno`. An invalid specification (`%y`, `%5%`, an unclosed `%[`, a trailing `%`) stops the scan without `EOF`. Pointer arguments are read on demand by `legacy::scanf_va::Pointers` through `abi::va::VaSource`, kept for positional access (up to `NL_ARGMAX`, 4096); positional and sequential conversions have separate counters. `boundary::scanf` provides strings and locked streams; a byte-oriented stream refuses `fwscanf` with `EINVAL` (D-12.14). The variadic names are C adapters forwarding to `liella_v{f,s,fw,sw}scanf4`; the exports return through `ret::int_or_eof`. `scanf_products.rs` compares about 40,000 scans across the three symbol sets and three locales; the recorded differences are the partial fields (KNOWN), the clamped integers (`clamped`) and the single terminator (`one_terminator`). |
| D-12.14 | §12.1, §12.10, §12.2 | HIST, ARB | **Wide streams** (phase 8; refines D-12.7). A stream's wide layer (`stdio_compat::Wide`, in its `Ext`) holds the codec, the input conversion state (`fgetpos` saves it), and up to four characters given back. The codec is fixed when the stream becomes wide-oriented: the calling thread's locale encoding then, `wchar_t` units for `open_wmemstream`, or the charset of `fopen`'s `,ccs=` (any `iconv` charset, converted through UCS-4 descriptors; output transliterates and writes UTF-16/UTF-32 little-endian without a BOM, as the reference library does). Input decodes byte by byte through the byte engine: an invalid sequence is `WEOF` with `EILSEQ` and the error indicator, its first byte left unread; an incomplete character at end of file is end of file. Characters given back are read before any byte; `ftell` and relative `fseek` count them by their encoded length, and positioning forgets them. **Mixed orientation** (ARB; ISO C leaves it undefined, the spec fixes the orientation): every byte operation on a wide-oriented stream fails (`EOF`, `0`, or `-1` with `EINVAL`, no indicator) and every wide operation on a byte-oriented one fails (`WEOF`, `EINVAL`). The reference library is irregular there (`fputc` and `ungetc` pass, and `fclose` after the latter corrupts its heap); `wstream_products.rs` records the `fputc` case. `wprintf` and `wscanf` go through the same layer. Memory streams (`open_memstream`, `open_wmemstream`) follow the reference library: a seek back moves the end of the data there (the published size and `SEEK_END`), the bytes after it stay in the buffer and reappear if a later write passes them, and `fclose` (not `fflush`) writes a terminator at the published size. |

| D-12.19 | §12.5, C.7 | PERF | **The front path of byte output** (PJ-24 P5, 2026-10-07; refines D-12.11). `fputc`/`putc`/`putchar` (and their `_unlocked` forms), `fputs` and `fwrite` first try the window store alone, before `with`'s plumbing: a stream already set up (`_lock` and `_codecvt` set; a standard stream's first use goes the general way, which sets it up), its orientation already byte (`_mode` < 0; undecided goes the general way, which decides it, wide the general way, which refuses), its lock taken exactly as `with` decides (not for the `_unlocked` forms, `FSETLOCKING_BYCALLER` or the only thread; else the stream lock, so a `flockfile` holder is waited for), and room in the open write window (`window_put`, unchanged: open only on a fully buffered stream that is writing, so line-buffered and unbuffered streams, reading, a full window and every memory or cookie stream whose window is closed go the general way and keep its flushes). Anything else returns to today's path unchanged, out of line. Answers and side effects are the general path's (`window_put` was already its first step). Tests: `front_corners` in the putc/fputs/fwrite forms (a wide stream with an open window, line-buffered, fully buffered), the open-window precondition of the lock checks, `conformance/c/s12_stdio_front.c` (the single-threaded case). **P5b (2026-10-07, owner-approved scope): cheaper checks and a validated record.** (1) *Window-closed invariant*: `store` publishes an open write window only on a byte-oriented stream that is writing (fully buffered, as before); in every other state (not set up: words 0; undecided or wide orientation; idle, reading, line-buffered, unbuffered, read-only, closed) `_IO_write_ptr == _IO_write_end`. `store` is the only writer of `_IO_write_end`, so every transition (open/`setup`, `freopen`, `fwide`/first wide or byte output, `setvbuf`, repositioning, reading, flush, close) goes through it; the wide layer's bytes use the engine's window (`state.wend`) inside the operations and move both published words together. So the front path's first test `ptr < end` (room for the data) replaces the set-up, orientation, role and buffer-null checks. The general path is `#[cold]` out of line. (2) *Bounds*: `ptr - buf < len` on the record's buffer (one subtract and compare, wrapping, through the slice check) instead of power-of-two buffers: the same cost as a mask test with no alignment padding, so zero memory; decided locally (P5b report). (3) *The record is validated* (owner ruling 2026-10-07). P5 finding: neither path validated `_codecvt` or `_lock`; both trusted the words as the library stored them, so a crafted `FILE` naming a fake record (its own `buf`) steered writes through the front path and the general path alike; P5's slice bound only held for corrupted window words over a genuine record. Now every slot holds a *seal* in the word before its record: the address of the `FILE` the record serves xor the pointer guard (`ThreadBlock::pointer_guard`, read with one `%fs`-relative load), written when the slot is handed out (`new_slot`) or bound to a standard stream (`set_up_standard`). `Env::record` (behind `stdio_compat::parts`, which every operation, `with`, the front path, `flush_all` and `close_every` use) accepts `_codecvt` only if it is 8-aligned and its seal equals `fp ^ guard`; the lock is then the record's slot neighbour, so the `_lock` word is no longer consulted (it keeps its meaning and value). Anything else is not a stream: `EBADF` (EOF), nothing written. **What a corrupted `FILE` can and cannot do**: it cannot make the library write anywhere but the record, lock and buffer of a stream the library opened *for that same `FILE` address* (a fake record, or another stream's genuine record, is refused by both paths and skipped by the flushes at `exit`); with its genuine record, corrupted window words move bytes only inside that stream's own buffer (front: `ptr - buf < len`; general: `load` clamps). It can: crash the process (a wild `_codecvt` is read, never written, before the check); garble its own stream's buffered data or indicators; get bytes through the front path after the program itself writes `_mode` or the window words; and a party that can read the process's memory (the pointer guard, or any seal with its `FILE` address) can forge a seal, the same bound as `setjmp`'s pointer mangling. Header-inline `putc`/`getc` in C code use the window words directly, outside any library check. Cost: one word per stream slot, no per-thread cost. Tests: `window_states` and `front_crafted` (in `front_corners`, all three forms). STDIO-HOT (2026-10-09): `vfprintf` holds the engine's write window for the whole call (`stdio_compat::Window`: the conditions and bounds of `window_put`, checked once at open; the buffer slice bound stays on every piece); `_IO_write_ptr` is published before every general write and at the end, and the window reopens after it (closed after an error). The unbuffered stage is passed by reference (no 128-byte move per call). `putc_c`: the fputc family's slow cases are one tail call (no frame on the front path); `alone()` is tested before the flags word (one thread: the flags are not loaded). Seal check unchanged. **STDIO-2 (2026-10-09): the read front path.** `fgetc`/`getc`/`getchar` and their `_unlocked` forms (not `__uflow`/`__underflow`) first try `stdio::read_front`: published `_IO_read_ptr < _IO_read_end`, then the sealed record (`Env::record`, unchanged owner ruling), then the lock decision as for output (`_unlocked` / `alone()` / `by_caller`, else `getc_locked` re-reads everything under the lock), then `sc::get_front`: `_mode < 0` (byte-oriented; the read window is not kept closed on wide streams, so the orientation is tested here - one load), the byte's offset below the engine's own `state.rend` and inside the buffer slice, then `_IO_read_ptr += 1`. The engine's window holds pushed-back bytes (`ungetc` moves `rpos` back and publishes it), a byte in the window never flushes line-buffered streams (`input_flushes` needs `rpos >= rend`) and changes no indicator, and every general operation re-reads `_IO_read_ptr` (`load`), so the answers stay the engine's. Anything else falls to the unchanged general path (`getc_general`, `#[cold]`); the export's C result comes from a tail-called `getc_slow`. Tests: `read_front`/`read_crafted` in s12_stdio_symbols (every getc form) and `getc_window` (checks 110-117) in conformance/c/s12_stdio_front.c.
