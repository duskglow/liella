**Sources read.** The "Deviations" lists of `plan/06-phases/` phases 3, 5, 6 and 7, which the first batch did
not read (it read phases 8-13). Also the adapters in `crates/boundary/src/posix/s08_numeric.rs` and `s20_signals.rs`,
and which `crates/*/tests` files already test `EINTR`, `ENOMEM` and `RLIMIT_AS` (a grep, file names only).
- Phase 7, deviation 4, said grouping "arrives with printf's `'` flag in phase 8". scanf has it now
  (`scanf.rs`, `Spec::group`). The compat `__strto*_internal` / `__wcsto*_internal` entry points still
  ignore their `group` argument (`_group: c_int`, and the module note still says "every locale is the C locale
  until phase 7"). That gap is row 1.
- Phase 5, interim 7: `strsignal`'s buffer is per thread now (`SLOT_STRSIGNAL`). But `psignal`/`psiginfo` still
  write through `process::stderr` and not through the `stderr` stream. That is row 2.
- `EINTR` tests exist for low I/O, processes (`waitpid`), terminals, file system, IPC and §22.7 semaphores
  (one clause line). There are none for stdio, `popen`/`pclose`/`system`, or the other thread waits.
  `ENOMEM` under `RLIMIT_AS` is tested only for diagnostics, memory, strings, time and regex. No test covers
  the file-system walkers, stream growth, or `qsort`/`hsearch`/`tsearch`. These are rows 3-8.
- Row 9 (syslog over a stream socket) and row 10 (a plants runner) come from the "tooling that removes a
  repeated failure" ranking. The plants failures repeat in thread_common and the brief: missing products in
  the RAM copy (three jobs on 10-23), stale mtimes after rsync (ENVIRON-TABLE-CONTRACT-2), unanchored `.S`
  plants (STRCHR-SHORT), and scripts that always exit 0 (GETTEXT-FOUND).

**No perf row.** Every hot-path row with a measured gap is already in register sections 13/14 (in flight), or
waits on a ruling (gettext no-catalog). The first batch's BENCH-ROWS-UNMEASURED covers the unmeasured claims.

**Independence.** Each row adds its own new test file. Two rows (1, 2) also change one boundary adapter file.
Row 10 changes xtask. No two rows edit the same source file. Rows 3-8 are test only. A defect one of them finds
becomes a new story, so the shared modules (`stream.rs`, `system.rs`, the heap, `search.rs`) are not edited by
them. Exception, as in the first batch: a fix of five lines or fewer in a file that no row of either batch and no
in-flight story touches. `stream.rs` is excluded from that exception because the getc/putc perf rows touch it.

**Rules for every row.** The same as `plan/next-batch-1024.md`:
- the clean room (black-box probes only, no libc or libm source);
- the direct-tier gate, plus plants on the code or tests the story adds, run from a RAM copy, one new
  directory per run, with `cargo xtask so` in the copy;
- `cargo xtask static` with the traceability rule;
- no file-system dependence, so listings are sorted or compared as sets;
- `unshare -r -m` is a standing yes, and nothing probes `sudo`;
- differences from glibc follow glibc unless they gain something;
- SECURITY-PRIVATE for a suspected weakness, with no reproducers;
- the stressful-environment rule.

`RLIMIT_AS` rows (6-8): set the limit only in a forked child. Leave enough headroom for the child to report,
through a pipe written with no allocation. The run must not depend on how much address space the host has
mapped: calibrate the limit in the child (current mapped size plus a margin) rather than fixing a number.
