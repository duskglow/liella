#### §1: Program startup, termination and environment

| ID | Spec | Ann. | Decision |
|---|---|---|---|
| D-1.1 | §1.1 | HIST, KERN | Entry captures an immutable `ProcessStart { args, env, auxv }`. The kernel `argv`/`envp` layout is used only at entry and in `execve` (⚑ KERN). |
| D-1.2 | §1.2 | HIST, PATH | One `ExitHandlers` registry of closures tagged by owning object (DSO) and by kind (`exit`/`quick_exit`/thread). `atexit`, `on_exit` and `__cxa_atexit` are three translations. The `on_exit` status parameter is captured at exit. The two POSIX lists stay distinct because the contract makes them distinct. |
| D-1.3 | §1.3 | HIST | **Internal:** `Env` is an ordered multimap. "First match wins" for lookups and "remove all" for unset reproduce the contract for duplicate `execve` entries. **Boundary:** `environ` is an exported array the caller may read or replace (F7). `legacy::environ` treats that array as authoritative, and `putenv` stores the caller's pointer (contract). `setenv` keeps replaced values alive, as the contract requires ("leaks by design"), but they are tracked in one arena so `clearenv`/exit can release them. |
| D-1.4 | §1.4 | HIST | Both identities are offered: `argv[0]` as given, and the verified executable path (`AT_EXECFN`, `/proc/self/exe`). |
| D-1.5 | §1.5 | ARB | **Internal:** `auxv::get(key) -> Option<u64>`. **Boundary:** 0 plus `ENOENT`. |
| D-1.6 | §1.6 | HIST, COMPAT | Rewritten under the clean-room rules of §1.4 (item 2) in a fresh session, from the spec, `spec/behaviour/getopt.md` and black-box probes. **Internal** (`liella::getopt`): a re-entrant parser over a caller-owned `State` (next element, letter cursor, pending block of skipped operands, ended flag, `optopt`), working through `Args` (count, text, swap) and `Longs` (entry by index) traits and returning an `Event`, so it neither allocates nor prints. Permutation is lazy: skipped operands are rotated (block swaps) behind the options found after them at the next element boundary, and `--` moves in front of them. Nothing latches the end: each call reads from the position (`optind`), as POSIX describes, so after `--` a further call parses the elements behind it, as glibc does (COLD-REWRITE2-W-far-07; `State::ended` only reports the last call). Orders: a leading `-` returns operands in place as code 1; a leading `+`, `POSIXLY_CORRECT` or `__posix_getopt` stops at the first operand; otherwise operands are permuted. A `:` (first, or after `+`/`-`) makes the parser quiet and returns `:` for a missing argument. Long options match an exact name, else a unique prefix; entries equivalent to the first match (same `has_arg`, `flag`, `val`) are not ambiguous for `getopt_long` and `-W`, but are for `getopt_long_only`'s `-`/`--` forms (as observed). `getopt_long_only` tries one-dash elements as long options unless the element is a single letter of the option string, falling back to letters only when nothing matches. `W;` with a table makes `-W name` a long option. **Boundary** (`options.rs`): one process-wide state under a spin lock; each call reads `optind` and `opterr` and writes `optind`, `optarg` and `optopt` (the state's, changed only on errors, as observed); `optind = 0` or the first call starts a new parse and reads `POSIXLY_CORRECT`; any other change to `optind` continues from that element and forgets the cursor and the skipped operands (deliberate). An `argv[optind]` pointer replaced between calls inside a cluster is read as it is now (glibc keeps reading the old string): placeholder compat flag COMPAT-7 in `docs/compat-flags.md` (owner ruling 2026-10-21; not implemented, behaviour unchanged). The GNU permutation is applied to the caller's `argv` words; diagnostics use the observed texts with `argv[0]`, through the `stderr` stream. Behaviours kept from the reference that may be historical (candidates for a later cleanup): `optopt` overwritten from the parser state on every call, the long-only ambiguity of equivalent entries, the letter fallback searching the raw option string. |
| D-1.6a | §1.6a | HIST | Rewritten under the clean-room rules of §1.4 (item 2). Internally a non-destructive reader (`liella::getopt::subopt`) giving the token index and the offsets of the name end, the value, the suboption end and the next start. The boundary does the destructive part as the spec says: it overwrites the `,` and, for a recognised suboption with a value, the `=` with NUL (glibc leaves the `=`: a recorded difference); it advances the cursor and sets `*valuep` to the value (NULL without one), to the whole unchanged suboption when it is unrecognised (as glibc does), or to NULL for empty text (glibc leaves it unset: deliberate). |
| D-1.7 | §1.7 | HIST | Written under the clean-room rules of §1.4 in a fresh session, from the spec, the public header, `spec/behaviour/argp.md` and black-box probes. **Internal** (`liella::argp`): a tree of parsers in preorder plus the standard options (`-?`/`--help`, `--usage`, hidden `--program-name` and `--HANG`, `-V`/`--version`, merged at the root in group -1), combined into one table (a name already taken goes to the first claimant); `parse` runs `liella::getopt` over it (permuting by default, operands in place with `IN_ORDER`, `NO_ARGS` ending the options at the first operand, `POSIXLY_CORRECT` honoured) and returns `Result<Parsed, Failed>`; callbacks, standard options and diagnostics go through a `Host` trait. Events: `INIT` preorder; options to their owner; each operand as `ARG`, then `ARGS`, to each parser in turn; `NO_ARGS` preorder to parsers with no operands; `END`/`SUCCESS`/`FINI` in reverse preorder; on error `ERROR` preorder then `FINI` in reverse; an operand no parser takes stops the parse (success with an index, `Too many arguments` without one). `help` builds usage, documentation, option list, notes and bug line as clusters and sections, one blank line between sections, with the observed sort and columns; `Format` reads `ARGP_HELP_FMT` (invalid values reported and ignored) and `COLUMNS` (right margin COLUMNS − 1, as the spec says; the reference ignores it). **Legacy** (`liella_legacy::argp`): when messages print and the process exits (`NO_ERRS` silences everything, `NO_EXIT` prevents exits, `--version` exits unless `NO_EXIT`). **Boundary** (`argp.rs`): reads the C tree, keeps `struct argp_state` on its stack (`name` set before `INIT`), calls parsers, filters and the version hook through `liella_machine_call3`, writes help to the given stream and getopt-style errors with `argv[0]` to `stderr`, exits with `argp_err_exit_status`. The four program-wide objects are weak C definitions (`adapter/runtime.c`), so a program's own definitions replace them; `argp_error` and `argp_failure` are variadic C adapters. Deliberate differences (listed in `docs/differences-from-glibc.md`; probe lines recorded in `argp_products.rs` `KNOWN`): a blank line between every section (option groups separated as the reference: only once a header has appeared, ARGP-HELP-FILTER-KEYS-2), a short option `+`, `:` or `-` listed first not read as a getopt option-string control character (owner ruling #458 for `+`, ruling #703 for `:` and `-`), documentation entries left out of usage, shadowed names hidden, names wider than the margin start their text on the next line, invalid `ARGP_HELP_FMT` values rejected (the reference loops for ever on some), `name` valid during `INIT`, real indices under `PARSE_ARGV0|NO_ERRS`, NULL state or name handled. Spec gaps decided without evidence: the `POST_DOC` filter for a parser without post text, `ARGP_KEY_HELP_DUP_ARGS_NOTE`, `argp_domain` ignored (no gettext yet), `--HANG`'s duration; `_argp_unlock_xinl` is named in §1.7 but absent from the ABI tables. |
| D-1.9 | §1.2 | — | **`exit`'s order** (ERRATA E9): the calling thread's `thread_local` destructors, then the registered handlers most recent first (including those registered while running, and a static program's `.fini_array`/`_fini`, registered at startup), then `exit_group`. Each handler is taken before it is called, so a nested `exit` runs only the rest. The first 32 registrations live in the registry itself (the ISO minimum needs no memory); later ones go to a lazily mapped extension of up to 2^20. |
| D-1.10 | §1.7 | ARB, HIST | **argp core: one compiled option table, explicit parse phases, a returned result** (COLD-REWRITE2-W-far-01-REWRITE, 2026-10-21; record `liella-historic:handoff/decisions/COLD-REWRITE2-W-far-01-REWRITE.md`). (1) *Table:* `Table::new` compiles the parser tree once, in preorder with the standard options last, into one ordered table: entries (owner, key, argument, flags, text, group), names with a `shown` bit (the first claimant of a name wins in parse and help alike), `by_letter` (O(1) short lookup), the getopt view (`longs`, `optstring`) and the help order; all storage `TryVec` (ENOMEM, never a panic). A glibc-shaped design keeps per-parser getopt tables. (2) *Parse phases:* INIT (preorder; `view.next` 0), options through `getopt::next` over the table, operands (`ARG` then `ARGS`, preorder; an operand nobody takes, or any under `NO_ARGS`, stops the parse: `Parsed{index, stopped}` with an index, else EINVAL), finish (`NO_ARGS` to parsers with `arg_num == 0`, `END` reverse preorder), then `SUCCESS`/`FINI` or `ERROR`/`FINI`. Probe-settled accounting: `ARGS` accepted consumes every remaining element; `ARG` with `next` raised by k counts `1 + k`; `next` lowered to the operand's own index resumes at `i - 1` (coordinator ruling #397: follow the reference). (3) *Help and usage:* each entry's place key (group rank, own entries before child clusters, cluster preorder) computed once; sections sort by first shown name ignoring case, long-only first on a tie, documentation entries not starting with `-` last; exactly one blank line between sections; usage `[-abc]`, then shorts with an argument, then longs; `ARGP_HELP_FMT` values decimal up to 65535, `rmargin` at least 1, `COLUMNS` sets `rmargin = COLUMNS - 1`. `POST_DOC` filters are called for every parser with a filter (NULL when it has no post text), as probed. (4) *Error exit:* the core never prints or exits; `parse` returns `Result<Parsed, Failed>` and reports through `Host`; exit policy stays in `liella_legacy::argp`. Run 2: `ARGP_PARSE_ARGV0` starts at element 0 only with `ARGP_NO_ERRS`; an `INIT` error takes the error path; a short option shows its argument without `dup-args` when it has no shown long name; the `Longs` view's `val` is a name index. |
| D-1.11 | §1.6, §1.6a | ARB, HIST | **getopt core: caller-owned state, no latch, block-swap permutation** (COLD-REWRITE2-W-far-07-REWRITE, 2026-10-21; record `liella-historic:handoff/decisions/COLD-REWRITE2-W-far-07-REWRITE.md`). (1) *State:* one caller-owned `State`; the core keeps no statics, `next(&mut State, ...)` returns an `Event` and never prints or allocates; the boundary maps `optind`/`optarg`/`opterr`/`optopt` onto a `State` under its lock; argp runs its own. A moved index forgets the cursor and the skipped operands (D-1.6). (2) *End of options:* not latched; each call works from the position (POSIX describes the result only in terms of `argv[optind]`): after `--` a further call parses what follows (probed). `State::ended` is informational. (3) *Permutation:* lazy, at the next element boundary (probed `optind` values); block swaps (Gries-Mills), O(k+m) per boundary, `argv` in order between calls (a program may stop calling early and read `argv`). `--` with operands pending is rotated in front of them. (4) *Option string:* a linear scan per call (the string may change between calls); the first occurrence of a letter wins (probed); `:` and `;` are never letters; `W;` is the long escape only with a table. (5) *Long options:* one pass, no allocation; an exact name returns at once; ambiguity when another prefix match differs from the first (any other match when strict); an empty name is a prefix of every entry. (6) *getsubopt:* a non-destructive reader returning offsets; the boundary writes (D-1.6a). PROOF-2: an element cut under the cursor is read again from its start at the same index (probed); a replaced pointer is read as it is now (difference, D-1.6, COMPAT-7). |
| D-1.8 | §1.8 | HIST | Tunables are parsed once at entry into a typed `Tunables` value, with the secure-mode filter applied (S8). Tunable names are namespaced `liella.*`, and the `glibc.*` names that apply to our design are accepted as aliases. Unknown names are ignored, per the contract. **Amendment (R15-6, LEGACY-TUNABLES-POLICY, 2026-10-23):** the full syntax is parsed as glibc 2.39 does (black-box probes): `:`-separated entries, a trailing entry without `=` makes the whole string malformed, numbers in base 0 with leading spaces/tabs and a sign, each tunable's listed range (out of range ignored). Honoured: `glibc.cpu.hwcaps`, `glibc.cpu.x86_rep_{movsb,stosb}_threshold`, `glibc.pthread.rseq`, `glibc.malloc.perturb`; every other name ignored silently; secure mode honours none (threat model, `GLIBC_TUNABLES` row). Table: `docs/tunables.md`. |
| D-1.12 | §1.3 | — | **The environment contract** (ENVIRON-TABLE-CONTRACT; owner rulings #519, #520, 2026-10-22): a Liella extension, off by default, where `getenv` is exactly the reference's (an early-reject scan of the live `environ`). `int32_t liella_environ_contract(int32_t on)` (LIELLA_NATIVE_1) turns it on or off and answers the previous state; `void liella_environ_reload(void)` rebuilds. While on, `getenv` answers from a hashed index of the names (first entry per name, linear probing, at most half full; a hit is re-read at its entry, a miss is trusted), which `setenv`, `putenv`, `unsetenv`, `clearenv` and `liella_env_*` keep current under the environment lock (an append is indexed; anything else rebuilds). A change made any other way (a slot stored, a `putenv` string's name edited) may be unseen until reload; a replaced `environ` is seen at once (the index answers only for its own array). Lookups take no lock and never build or allocate (a sequence word; a lookup racing a writer scans), so `getenv` stays async-signal-safe. The slots are allocated from the library heap when the contract is turned on (none reserved statically) and grown by a new block; old blocks are never freed (a lock-free reader may still be probing one), at most twice the final size. No environment variable switches it (it would pass across `exec` to programs that never agreed); secure mode needs no special case (`secure_getenv` is unchanged and still scans). `fork` children inherit the table (the environment lock is held across `fork`); `exec` starts a new image with the contract off. Off-mode cost: one load and a predicted branch per `getenv` and `setenv`/`putenv`/`unsetenv`/`clearenv`. Documented in docs/interfaces.md §2; not a differences row (the default is unchanged). Run 1's exact default-mode cache was dropped: glibc sees a `putenv` string's name edited in place, so an exact cache must scan for every miss. |
| D-1.13 | §1.1 | HIST, KERN | **RELRO in a static program** (STATIC-RELRO, 2026-10-22): before the first constructor (`.preinit_array`), `__libc_start_main` makes the executable's `PT_GNU_RELRO` pages read-only with one `mprotect(PROT_READ)` over `[page_down(vaddr), page_down(vaddr + memsz))`: a partial last page stays writable (the linker ends the segment on a page boundary, so in practice the whole segment). Black-box probe of the reference library (static, non-PIE, strace + /proc/self/maps, 2026-10-22): `mprotect(0x4a5000, 20480, PROT_READ)` for vaddr 0x4a5f30 memsz 0x40d0, after its own start-up and before the constructors' output. The only start-up relocations to finish first are the program's own `R_X86_64_IRELATIVE` entries (STATIC-IRELATIVE; static PIE is refused): they are applied before the protection, since their target words lie in `.got`, inside RELRO (RELRO-IRELATIVE-ORDER, test `conformance/c/s01_irelative_relro.c`: the ifunc's `.got` slot holds the resolver's choice and is read-only when the constructors run; a write to it faults in a child). A dynamically linked program's RELRO belongs to its loader: the host's `ld.so` now, Liella's at phase 14. |
