| D-23.1 | §23.1 | HIST | **Internal:** `Timespec{sec: i64, nsec: u32}` (validated) and `Duration`. `time`, `gettimeofday`, `ftime` and `clock` are translations of `clock_gettime` (vDSO). The `tz` argument is zero-filled, per the contract. |
| D-23.2 | §23.4 | HIST, KERN | Written under the clean-room rules of §1.4 in a fresh session, from the spec, `spec/behaviour/timers.md` and black-box probes. `alarm`, `ualarm` and the itimers are the kernel's shared timers (⚑ KERN): `alarm` is the `alarm` system call, `ualarm` translates `ITIMER_REAL` (`clock_compat::ualarm`: either argument ≥ 1 s is `EINVAL`; a remainder beyond `useconds_t` saturates at `UINT_MAX-1`, where glibc wraps), and `setitimer` with a NULL value is `EFAULT` (S6; the kernel would take it as zero). POSIX timers notified by the kernel (`SIGEV_SIGNAL`, `SIGEV_THREAD_ID`, `SIGEV_NONE`, NULL) are the kernel's timers, and their `timer_t` is the kernel id; a NULL setting in `timer_settime` is `EINVAL` (as glibc), and a NULL id in `timer_create` is `EFAULT` (glibc crashes). `timerfd_*` are the system calls. Internal timers use `timerfd`. |
| D-23.3 | §23.4 | HIST | `SIGEV_THREAD` timers (`boundary::timer`) are `timerfd`s (no internal signal, D-H18), with `timer_t` = `1<<62 | serial` (serials never reused). The clock is checked as the kernel's timers check it; clocks a `timerfd` cannot measure (CPU-time clocks, `CLOCK_TAI`) are `ENOTSUP`, where glibc accepts them. A NULL function is `EINVAL` (glibc crashes at the expiry), and descriptor limits are `EAGAIN`. One helper thread per process, made lazily with every application signal blocked and not counted as running (`thread::create_service`), waits on an epoll set (`EPOLLONESHOT`). Each expiry gets a **new detached thread** (§23.4: "a new thread") with a copy of `sigev_notify_attributes` taken at `timer_create` (stack size, stack address, guard, scheduling, affinity; owner ruling 2026-10-04), always detached, every application signal blocked (as glibc), calling the function with `sigev_value`. **One notification at a time per timer:** the descriptor is armed again in the notification thread's exit sequence, however it ends (return, `pthread_exit`, cancellation); expiries meanwhile become the next notification's overrun (`count - 1`, saturating at `DELAYTIMER_MAX`), which `timer_getoverrun` reports. **A notification thread that cannot be created** (owner ruling #269, 2026-10-21; glibc drops the expiry silently, a deliberate difference with a compat-flag placeholder) is retried by the helper with a back-off doubling from 10 ms to a 1 s ceiling, until a thread starts or the timer is deleted: the descriptor stays disarmed meanwhile, so the notification that starts counts every expiration since in its overrun; `timer_settime` (lock-free: whoever clears the record's retry flag owns the descriptor) drops the pending retry and arms the descriptor for the new setting, `timer_delete` cancels it. A notification that waited for its caller-supplied stack and then could not be started (`boundary::stacks` hands it back: `timer::abandoned`; TIMER-ABANDONED-ONESHOT, 2026-10-22) takes the same retry with its expirations owed; it used to re-arm the descriptor only, which lost a one-shot timer's notification for good (nothing more expires) and delayed a periodic one's to its next expiry. The helper, asleep without a timeout, is woken through an `eventfd` in its set (`WAKE`), made with the first timer whose attributes name a stack (`EAGAIN` at `timer_create` when no descriptor is left), so other timers pay nothing; the helper drains it at each wake-up (tested through its count in `/proc/self/fdinfo`: a level-triggered event left set would make the helper spin; NOTIFY-ABANDONED-MQ-AIO). glibc has no such case (it never waits for a stack: it starts every notification at once, on the one stack; a refused thread drops the expiry, the #269 difference). Test: `timer_abandoned_notification_retried` (one-shot and periodic control). The helper waits with a timeout only while some retry is pending. The helper also runs the message-queue and AIO `SIGEV_THREAD` retries (ruling #680, #695; D-25.5, D-11.11): `timer::retry_others` calls `mqueue::retry_due` and `aio::retry_due`, with the same back-off and episode reset (`timer::back_off`, `timer::recovered`; episodes counted per notifier, only timers report on the `timers` diagnostic topic). A process's first `mq_notify` `SIGEV_THREAD` registration or AIO `SIGEV_THREAD` request makes the helper and its `eventfd` (ruling #691; `EAGAIN` if it cannot), since a helper made only after a refusal would itself be refused. Test: `timer_retry_back_off_ceiling_and_reset` (a refusal held past the ceiling is notified within it once threads are allowed; a second episode on one timer starts again from 10 ms). Each failure episode (first refusal to the next start) is noted once in a counter a test reads (`selftest::timer_thread_episodes`); the library has no diagnostic channel for a user-visible warning (RULING NEEDED, TIMER-SIGEV-THREAD-NOSPAWN-2). glibc instead starts a thread per expiry, concurrently (a spec gap: §23.4 does not say). After `timer_delete`, no function starts; a running one finishes, and `timer_delete` does not wait. Records are on a grow-only list and reused, never freed, so `timer_settime`, `timer_gettime` and `timer_getoverrun` are async-signal-safe: a lock-free lookup pins the record, and `timer_delete` waits for pins before closing. A caller-supplied stack serves one notification at a time, across timers and the other notification paths (owner, 2026-10-04; `boundary::stacks`, shared with D-25.5 and D-11.11): the key is the stack's address range, and a notification starts only when no thread is on an overlapping stack and none is queued for one (so they start in the order they became due); otherwise it is queued with a copy of its attributes, and one service thread (made the first time a notification waits; every application signal blocked, not counted as running) waits for the leaving thread's TID word to clear and starts it. Threads on caller stacks are made with `thread::create_kept`; their exit sequence marks them leaving; gone ones are reclaimed at the next use. The party that made a notification due (the timers' helper, the message queues' helper, an AIO helper, worker or `close`) never waits for a stack, since the thread on it may be waiting for that party. A queued notification that then cannot be started is handed back: a timer takes the #269 retry with its expirations owed (above), a message-queue record or an AIO block takes the same retry (#680; D-25.5, D-11.11). A `fork` child closes the descriptors and has no timers or helper. Under another `ld.so` (D-22.10), `SIGEV_THREAD` is `EAGAIN`. |

| D-23.5 | §23.5 | HIST, ARB, PATH | **Internal:** `Zone::resolve` returns `Result<(i64, Local)>`: the fields other than the seconds give a wall time, the candidates are the instants whose local time shows it, and `tm_sec` is then added as elapsed seconds (as glibc). `tm_isdst<0` takes the earliest candidate, and in a skipped hour reads the wall time with the offset in force before the change; `tm_isdst>=0` takes the earliest candidate with that flag, else reads it with the offset of the nearest period with that flag; DST asked of a zone without DST reads one hour ahead (as glibc); standard time asked of a zone without it is ignored. | D-23.6 | §23.6 | HIST | **Internal:** IP-23, `liella::time::Zone`, from TZif v1–v4 (RFC 8536, leap seconds included; the footer after the last transition, type 0 before the first) or from a POSIX rule. Rule grammar: RFC 8536 v3 times of ±167 h; a missing std name or offset (hh 0–24) makes the value invalid, which gives UTC named by its leading valid name; an invalid DST name means standard time only; an invalid or missing DST offset or date takes its default (one hour east; `M3.2.0`, `M11.1.0` at 02:00). Rules apply in every year (glibc keeps the 1970 state for earlier times), and out-of-range dates or offsets are invalid (glibc clamps or computes odd transitions); both are recorded differences. Selection (`time::load`): TZ unset is `/etc/localtime`, else UTC; TZ empty or `:` is UTC named "Universal"; otherwise, after one leading `:`, the regular TZif file at the path or under `TZDIR` (default `/usr/share/zoneinfo`; ignored in secure mode), else the value as a rule. **Process state:** `legacy::time_compat` keeps every selected zone for the life of the process (keyed by TZ, TZDIR and file identity), so `tm_zone` and `tzname` stay valid; an implicit tzset (`localtime`, `mktime`, `timelocal`, `ctime`) re-selects when TZ or TZDIR change (TZ-FRESH, owner ruling 2026-10-09: both are read from the `environ` array at every implicit tzset with the shared environment scan and compared by value, so a raw write into the array or an in-place edit of the string is seen, as in glibc; no cache is keyed on a change counter or the array's address; TZDIR is read only when TZ changed and by the explicit tzset: with an unchanged TZ the current zone stays whatever TZDIR becomes, as glibc, which reads TZDIR only when it loads a file) or when the zone file's identity (dev, ino, size, mtime, ctime) changes: `/etc/localtime` with TZ unset, as §23.6 says, and a file TZ names (glibc never re-reads one). The file is checked at most once per second by an implicit tzset (the vDSO monotonic clock, one atomic word per kept zone, no lock when nothing is due), at once by the explicit `tzset` and when the selection moves to another kept zone (owner ruling 2026-10-05, `legacy::recheck`; probed: glibc checks `/etc/localtime` at every implicit tzset but misses a replacement within the same mtime second); Reload on request: `liella_tz_invalidate` (D-X.13) makes the next implicit tzset check every kept zone file at once, whatever the time of its last check. the `_r` forms use the current zone; one lock, held across `fork`. **Globals:** `tzset` writes `tzname`/`timezone`/`daylight` (C objects with glibc's aliases in the products; private statics in test builds) on every explicit call and on zone changes, never from the converted period (glibc's `localtime` rewrites them from the period it converts, an artifact): for a file, each flag's abbreviation from the last transition with that flag, the footer's names first; `timezone` the footer's or the last standard offset; `daylight` set if any type is DST; a zone without DST repeats its standard name. `tm_gmtoff` and `tm_zone` are always filled. |
