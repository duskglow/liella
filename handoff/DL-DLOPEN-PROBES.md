**Answers in one line each** (details in dynlink.md)
- P-1: `NOW|LAZY` = lazy. Every swept unknown bit is refused with `invalid mode parameter` before the search. The
  P-1 sweep leaves out `0x40000000`; Liella refuses it like every other unknown bit.
- P-2: identity by inode (symlink, hard link, `./`, `..`). A bare `DT_SONAME` matches a loaded object before any
  search; a copy with the same soname opened by path is a second object. `l_name` keeps the first name.
- P-3: `RTLD_GLOBAL` and promotions append the root and its dependencies; promoting a dependency promotes only it.
- P-4: siblings and the root are visible to a dependency.
- P-5: `RTLD_NEXT` = the caller's load scope after the caller. `RTLD_DEFAULT` from a `dlopen`'d object = the global
  scope, then the caller's local scope (ruling #5127: follow). Failure texts name the caller.
- P-6: a successful `dl*` call clears the pending text (ruling #5127: follow). Texts are per thread.
- P-7: an inner `dlopen` of an initialising object returns its handle without running its constructors again.
- P-8: `dlsym` and `dlopen` in another thread wait while a constructor runs; `dl_iterate_phdr` does not, and
  already lists the object. Liella's readers never wait (plan §4).
- P-9: after a fork made during a constructor, the child can use the loader.
- P-10: an IFUNC resolver runs in a `dlopen` that fails (the object is processed before the failing one).
- P-11: older threads see the initial values of the surplus TLS block.
- P-12: handle == link map; the program's `l_name` is `""`.
- P-13: the program by path is refused; libc by any path is the start-time handle. `ld.so` by its real path gives a
  second object.
