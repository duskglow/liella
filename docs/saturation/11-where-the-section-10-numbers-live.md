## 11. Where the section 10 numbers live (BENCH-REFRESH-1023-3, 2026-10-23)

`bench/parity-measure.tsv` keeps its 47-column schema (ruling #1067). `cargo xtask bench --compare` now always writes those 47 columns to `measure.tsv`; groups for builds the run did not make are `-`. The `cbench_hot` rows (Ivy Bridge host A, 2026-10-23) and `cbench_fstree` rows (Ivy Bridge host B, 2026-10-23) replace nothing and carry no old number: the `liella_v3_*` and `liella_sorted_*` cells are `-` (not measured: v3 needs AVX2, which Ivy Bridge lacks, and a the AVX2 timing hosts booking was not made for a column the register's rows do not decide on). Uops columns are dropped (they were never in the table). Per-bench date, host and basis are in `bench/parity-measure-meta.tsv`. The other five benches' rows (`opt`, `locale`, `patterns`, `stdio`, `time`) were measured on Ivy Bridge host A/Ivy Bridge host B in run 1, but run 1's measure.tsv was lost, so those rows in the table are the OLD rows and the meta file says `not refreshed`; their fresh time ratios are only in section 10's table. Rows that moved materially are flagged in section 10 (MOVED).
