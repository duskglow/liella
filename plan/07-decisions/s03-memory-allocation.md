#### §3: Memory allocation

| ID | Spec | Ann. | Decision |
|---|---|---|---|
| D-3.1 | §3.1 | — | **Two allocation domains.** Library-internal memory uses the internal heap directly. Memory handed to C callers (`strdup`, `getline`, `open_memstream`, `asprintf`, `scandir`, ...) comes from the *exported, interposable* `malloc` through the PLT, so that a user-interposed `free` can release it (spec §3.3; F23). |
| D-3.2 | §3.1 | ARB, HIST | `malloc(0)` returns a unique freeable pointer. `realloc(p, 0)` frees and returns NULL. Both are the contract's glibc choices, kept for compatibility. |
| D-3.3 | §3.1 | HIST | Internal deallocation passes size and alignment (`free_sized`-style), so there is no per-block header for internal allocations. C `free(p)` recovers the size from the size-class map. |
| D-3.4 | §3.2 | HIST, COMPAT | Introspection is implementation-neutral. `mallinfo2` reports in-use, held and releasable bytes in the fields whose meaning is neutral, and zero elsewhere (observable). A block freed by another thread counts as free once its `free` has returned, collected by its owner or not (D-3.11), in every report (`mallinfo2`, `mallinfo`, `malloc_stats`, `malloc_info`): the reader subtracts pending remote frees, so the result does not depend on when collection runs. `mallinfo` saturates at `INT_MAX` instead of wrapping (observable, stricter). `mallopt` returns 1 for every parameter, known or not, as glibc (owner ruling 2026-10-22, #412), and 0 only for `M_MXFAST` outside 0 to 160; only `M_PERTURB` takes effect, the others are ignored. `malloc_info` emits the same XML element structure with neutral content. |
| D-3.5 | §3.3 | HIST | The hook variables are inert compat data (as in 2.34+). `mcheck`/`mtrace` semantics come with the debug library (phase 13). `malloc_get_state`/`malloc_set_state` fail. **Phase 13 (owner ruling 2026-10-04: kept; phase 14 ships an empty `libc_malloc_debug.so.0`, and preloading it gives no hooks):** Liella's libc provides the `libc_malloc_debug` semantics itself (`mcheck`, `mcheck_pedantic`, `mprobe`, `mcheck_check_all`, `mtrace` with `MALLOC_TRACE` read through `secure_getenv` and never written in a secure process, `M_PERTURB`): checked blocks carry 16 guard bytes before and 8 after, tracked in a library-owned table; `mcheck` succeeds only before the first block the C family hands out; a freed block reports `MCHECK_FREE`; the mtrace log follows the reference's format. Off, the cost is one relaxed load of one atomic word per call (`Heap::alloc`/`free` are `#[inline(always)]` so the check does not stop the fast path being inlined: 13.7 ns per 64-byte pair). The hook variables stay inert. `malloc_info` options other than 0 give -1 `EINVAL` (malloc_info(3), §3.2 since 2026-10-04; glibc returns 22); `malloc_trim` returns 1 only when pages were released; `mallopt` returns 0 for parameters it does not honour (D-3.4). |
| D-3.6 | §3.5 | HIST | **Internal:** `Arena` (obstack semantics) returns `Result`. **Boundary:** `obstack_alloc_failed_handler` (default: exit) is called by the legacy adapter, per the contract. |
| D-3.7 | §3.7 | HIST | The allocator never uses `brk`: pages come from `mmap` only. So `brk`/`sbrk` (thin wrappers) cannot corrupt the heap (observable: no interaction with `malloc`). |
| D-3.8 | §3.4 | HIST | `alloca` is a compiler builtin. Nothing to implement. |
| D-3.9 | §3.1 | — | **S8 is enforced by lint.** `clippy.toml` lists the infallible `alloc` methods (`Vec::push`, `with_capacity`, `reserve`, `extend_from_slice`, `insert`, `resize`, `append`, `vec![x; n]`, `Box::new`, `String::push_str`, `to_vec`, `to_owned`, `Extend::extend`, ...). Every library crate root denies `clippy::disallowed_methods` outside tests. Host tools (`xtask`, build scripts) and tests are exempt. **Accepted by the owner (2026-10-01).** **Manual review obligations**, since no lint can catch them: (1) `Iterator::collect` into a `Vec`, `String` or other collection; (2) `format!` and `alloc::fmt::format`; (3) `Clone` of a collection (`Vec`, `String`, `Box`). In library code each of these is either replaced by a fallible equivalent (`TryVec::from_slice`, `try_clone`, a fallible collect helper) or carries a comment explaining why it cannot fail. Every review of a library crate checks for all three. |
