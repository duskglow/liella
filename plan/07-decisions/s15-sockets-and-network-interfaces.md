#### §15: Sockets and network interfaces

| ID | Spec | Ann. | Decision |
|---|---|---|---|
| D-15.1 | §15 | HIST | **Internal:** addresses are typed byte values (`[u8;4]`, `[u8;16]`, `interim_db::Ip`) and interfaces are `liella::net::iface::{Link, Addr}`; socket addresses exist only at the boundary (`SockAddrBuf`, `net_compat`), so no `SocketAddr` enum was needed. **Boundary:** `sockaddr` packing and the `socklen_t` in-out protocol (D-15.5). `getifaddrs` and `if_nameindex` each return one caller-owned block (the structures, then the names and socket addresses they point to), freed whole; NULL is accepted. Truncation is reported, per the contract. |
| D-15.2 | §15.3, §15.5, §15.7 | HIST, ARB | **Internal:** the strict texts are `liella::net::addr` (RFC 4291 in, RFC 5952 out, mixed notation for `::ffff:0:0/96`, and for `::/96` when the upper half of the last 32 bits is non-zero); the historical texts (aton, network, classful, CIDR, NSAP, RFC 2292) are `liella_legacy::inet_compat`. **Boundary:** `inet_aton`/`inet_addr` keep the lenient grammar, including the address ending at white space (callers may rely on it; `inet_pton` is the strict form), and the `INADDR_NONE` ambiguity. `inet_ntoa`, `ether_ntoa` and `ether_aton` use per-thread slots (D-H3); `inet_nsap_ntoa`'s NULL-buffer result is process-wide, and at most 255 bytes are formatted either way. `inet_network` keeps the classful results. **Deliberate differences (phase-10 probes):** `inet_network` refuses a part beyond 32 bits (glibc wraps it; KNOWN in `netaddr_products`); `inet_neta` keeps interior zero bytes (glibc's `10.1` for `0x0a000100` is lossy) and needs only the text's size; `ether_line` requires white space after the address (`ethers(5)`); RFC 2292 is followed where glibc departs from it (NULL `*tptrp` at the end of a walk, no pad types in `inet6_option_append`, no negative `inet6_option_alloc` length); `if_freenameindex(NULL)` is a no-op. |
| D-15.3 | §15.4 | KERN | Interface enumeration uses netlink only. Each call opens a private `NETLINK_ROUTE` socket and sends an `RTM_GETLINK`/`RTM_GETADDR` dump; `if_nametoindex`/`if_indextoname` ask for a single link. It works in any process, Liella-started or not. `getifaddrs` gives one `AF_PACKET` entry per link (`IFLA_STATS` as `ifa_data`), then the addresses in the kernel's order; the broadcast/destination field is `IFA_BROADCAST`, or else `IFA_ADDRESS` when `IFA_LOCAL` is given (127.0.0.1 for `lo`, observed). Unknown names give `ENODEV`, unknown indexes `ENXIO`. |
| D-15.4 | §15.8 | HIST | The rcmd family is implemented per contract in `liella_legacy::rcmd` and documented as insecure. Trust checks as observed: `hosts.equiv` owned by root; `.rhosts` owned by root or the user and read under the user's file-system identity; regular file, not writable by group or others, one link; `__rcmd_errstr` carries the reference's messages. `ruserpass` follows `netrc(5)` where glibc's parser fails (`account` values skipped, `macdef` bodies end at a blank line, `password` before `login`). `rexec` without a name or password uses `.netrc` and then fails (no terminal prompt until phase 11), and never blocks for ever on the error channel. Diagnostics go to stderr; a silent close is reported as `short read`. Untested: the privileged-port success paths (no test uses `sudo`). Netgroup entries (`+@g`/`-@g`) match through `innetgr`: a host field matches the official name or an alias of the remote address, a user field the remote user; without a netgroup database nobody is a member (phase 10 part 3). |
| D-15.5 | §15.1, §15.2 | KERN, HIST | Address and option results (`accept`, `getsockname`, `getpeername`, `recvfrom`, `getsockopt`) are received into `SockAddrBuf` and copied back truncated to the caller's `socklen_t`, with the full length reported; the kernel's addresses are at most `sizeof(struct sockaddr_storage)`, so this equals passing the caller's buffer. `struct msghdr`/`struct mmsghdr` have the kernel's layout and are viewed in place, so the kernel reads and writes the buffers they name. `setsockopt` at a level that registers caller memory goes through `raw` (D-X.9 b). The source-filter calls build `struct ip_msfilter`/`group_filter` in library memory for the typed `getsockopt`/`setsockopt` (`IP_MSFILTER`, `MCAST_MSFILTER`); the caller's list receives at most its capacity, and the count reports the kernel's. |
| D-15.6 | §15.7, §15.8, §16, §17, §24.5 | ARB | **Interim lookups retired (phase 10 part 3).** ethers, hosts (rcmd, gethostid), users, groups, shadow, gshadow, netgroups, group lists and getlogin go through the NSS engine (`legacy::nss`, `netdb_compat`; D-16.1), with path parameters kept through `nss::Paths` for fixture tests. `interim_db` keeps only re-exports of the `files` source primitives (`nss_files`) and cursors (`cursors`) for the parts 1–2 clause tests; nothing in the library uses it. |
