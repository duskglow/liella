# Phase 14 design: the dynamic linker

Status: PROPOSED. Rulings it depends on are in `open-questions.md` (R14-n); local decisions taken
here are numbered L14-n and listed at the end. Milestones: `milestones.md`. Threat-model text:
`threat-model-draft.md` (DRAFT FOR OWNER).

## 0. Shape of the products

| Product | Crates | Role |
|---|---|---|
| `ld-linux-x86-64.so.2` | new product crate `crates/ld-so` over `liella-ld` (logic, `forbid(unsafe)`), `liella-rt`, `liella-kernel`, and `liella-boundary` with a new feature `ld` (only the conversions and exports the loader needs) | interpreter, symbol resolution, TLS, rendezvous, `ld.so` as a program |
| `libc.so.6` | unchanged crate graph; gains a small client of the loader's private interface (§14) | `dlopen` family exports (versions.tsv puts them in `libc.so.6`), threads, malloc |
| placeholders | generated by `cargo xtask so` from versions.tsv | `libpthread.so.0`, `libdl.so.2`, `librt.so.1`, `libutil.so.1`, `libanl.so.1`, `libc_malloc_debug.so.0` |
| `libthread_db.so.1` | `liella-thread-db` + boundary feature `thread-db` | debugger agent (F30) |

**Separate interpreter (R14-2, recommended).** `ld.so` is its own small object with *no*
`DT_NEEDED`, no undefined symbols and only `R_X86_64_RELATIVE`/RELR dynamic relocations
(checked by xtask at link time, L14-1). That one invariant is what makes its bootstrap provable
(§1). The merged alternative (libc.so.6 acting as its own interpreter) is recorded in R14-2.

**Symbol placement follows versions.tsv** (R14-12): `__tls_get_addr@GLIBC_2.3`,
`_r_debug`, `__libc_stack_end`, `__rseq_offset/_size/_flags@GLIBC_2.35`, `_dl_mcount`,
`__rtld_version_placeholder@GLIBC_2.34` live in `ld.so`; `dlopen`..`dl_iterate_phdr`,
`_dl_find_object`, `__x86_get_cpuid_feature_leaf` in `libc.so.6`. `libc.a` keeps all of them
for static programs. GLIBC_PRIVATE names (25 in ld.so, `_thread_db_*` in libc) are not
exported; our own private interface is a version node `LIELLA_PRIVATE` (§14).

**Unsafe surface (S1-S4).** All logic is in `liella-ld` (`forbid`). The `ld` feature of the
boundary adds only existing categories: *slice* (the loader's own image during bootstrap; the
initial stack, as `runtime.rs` already does; file headers read into owned buffers need none;
mapped segments as `&[u8]` for parsing and `&mut [u8]`/`&[AtomicU64]` for relocation targets),
*export* (`_r_debug`, `__tls_get_addr`, the private interface), *extern* (syscalls),
*tb-field* (dtv pointer). Calling code at an address uses `machine/call.S` (OD-C1). New machine
primitives (R14-8): program entry transfer, TLSDESC return and fallback, lazy-binding
trampoline, audit PLT trampolines.

## 0a. Architecture seam (A-1 `ARCH-PH14-NEUTRAL`, provisional ruling RL-5)

x86_64 is still the **only** implementation. Ledger item OD-10 (aarch64 next) is planned in
`plan/06-phases/20-post-release-ledger-and-experiments.md`, stories A-0..A-13. So from the
first DL story onwards, every part of the loader that changes per architecture goes behind
**one** seam, and the rest of `liella-ld` never names an architecture. This section covers
design only. No aarch64 code is written in phase 14. Anything below that describes aarch64
comes from public documents (AAELF64, AAPCS64, the GCC manual) and is NOT VERIFIED: the A-stories
check it under qemu once RL-2/RL-3 are ruled.

**Shape.** In `liella-ld` (logic, `forbid(unsafe)`): a module `liella_ld::arch` that holds a trait
`Arch` (associated constants and pure functions on a zero-sized type), its one implementation
`arch::X86_64`, and `pub type Native = X86_64` under `cfg(target_arch = "x86_64")` (on any
other target, a `compile_error!` until A-12). The code that varies per arch takes `A: Arch`
(or uses `Native` where a generic adds nothing), so A-4 and A-12 can test a second table on the
x86_64 host as pure logic. In the boundary (`ld` feature): one module `boundary/src/arch/`
holds the thread-pointer write and the `extern` declarations of the loader's machine
primitives. In `csys/src/machine/`: the primitives themselves (K2: fixed sequences, no logic).

ELF reader (apart from identity), mapper, search order, symbol lookup and versions, the
dlopen family, RCU lists, namespaces, init order and the debugger rendezvous are written
once. The loader **must not** hard-code `GLIBC_2.2.5`, a relocation number, a path, or a TP
offset outside the table. The seam check that A-0 (`ARCH-SEAMS`, `ARCH(x86_64): why` tags)
adds treats `liella_ld::arch`, `boundary/src/arch/` and `machine/*.S` as the allowed modules for
the loader.

**Cost.** A few lines per DL story, with no runtime cost on x86_64: `Native` is a constant type, `classify` is a
`match` the compiler inlines, and the hot `__tls_get_addr` path (§7) reads the same fields as
before.

### Arch review checklist (each DL story ticks it in its handoff)

A DL implementation story (DL-1 onwards) writes `arch seam: ticked`, or lists each exception with
its reason, in its handoff and report:

1. No `R_X86_64_*`, `EM_X86_64`, `ld-linux-x86-64`, `x86-64-v*`, `%fs`, `arch_prctl`, `XSAVE`/`FXSAVE`
   or `GLIBC_2.2.5` literal outside `liella_ld::arch`, `boundary/src/arch/`, `machine/*.S` and
   tests marked x86_64-only.
2. Relocation code matches on `RelocKind`, never on a raw `r_type`. The L14-1 link check of
   `ld.so` also uses `RelocKind` (`Relative` + RELR).
3. TLS offsets, TCB placement and the canary/pointer-guard slots come from `Arch` (no
   "block ends at TP" written into a formula).
4. Any new assembly is one of the fixed-name primitives above: no logic (K2), declared once in
   `boundary/src/arch/`, register convention in the file header.
5. CPU features and hwcaps come only from `Arch::features`. Nothing else reads HWCAP bits or
   CPUID.
6. Paths, the interpreter name, `$LIB`/`$PLATFORM` and the cache arch flag come from the table.
7. Tests that depend on an x86_64 fact are `cfg(target_arch = "x86_64")` or take an `Arch`
   parameter, and say so in a comment. Pure-logic tests of the table are written so that a second
   `Arch` implementation can run them unchanged.
8. Any new arch-specific item that the table does not cover yet is added to the table (in this
   section and in `liella_ld::arch`), not open-coded.

## 1. Bootstrap (`boundary/src/bootstrap.rs` + `liella_ld::boot`)

* **Inputs:** the initial stack pointer (from the `ld` variant of `machine/entry.S`), the
  loader's own `_DYNAMIC` and load base (from `AT_BASE`, or the PC-relative `__ehdr_start` when
  `ld.so` is run as a program).
* **Steps:** (1) self-relocate: RELA `R_X86_64_RELATIVE` and RELR only, over a `&mut [u8]` view
  of the loader's own writable segment (R14-1); (2) install a provisional thread block in
  `.bss` (`arch_prctl(ARCH_SET_FS)`, L14-2) so any `%fs`-relative access (tb-field, canary) is
  defined from the first Rust call; (3) parse argc/argv/envp/auxv with the existing
  `liella_kernel::auxv` and `liella_rt::start` code; (4) decide secure mode once (S10) and apply
  `rt::start::UNSECURE` before *any* `LD_*` read (threat model rule 1/8); (5) tunables (D-1.8,
  secure filter) and CPU features (`liella_rt::cpu::Features`, the same decision libc uses,
  D-4.25); (6) RELRO of the loader itself.
* **Invariants:** no code before step 1 dereferences a relocated pointer (no `&'static`
  data with addresses, no vtables, no panics with `Location`); xtask checks the linked `ld.so`
  for: zero undefined symbols, zero `DT_NEEDED`, relocation types ⊆ {RELATIVE, RELR}, no
  `DT_TEXTREL`. The csys objects linked into `ld.so` are built `-fno-stack-protector` (L14-3).
  The loader never writes `errno` (internal `Result` only; X3).
* **Failure:** a malformed own image cannot happen post-link (checked); everything else is a
  diagnostic on fd 2 and `exit_group(127)` (probe the reference's status, M14-0).
* **Clauses:** prerequisite of all s27; threat model rules 1, 8.
* **Tests:** ASLR is the oracle: a bootstrap that used an unrelocated pointer faults on the
  first run at any non-zero base; run 100 starts with `setarch -R` off and on; planted bug
  (skip one RELR word) must fail. Static-PIE `libc.a` start reuses the same relocator (closes
  the phase-4 "static PIE refused" deviation; IRELATIVE included).

## 2. ELF reader, IP-24 (`liella_ld::elf`; the vDSO subset in `liella-kernel` stays)

* **Inputs:** `&[u8]` (file prefix or a mapped segment), never raw addresses.
* **Covers:** ELF header (class, data, `EM_X86_64`, `ET_DYN`/`ET_EXEC`, OS ABI incl.
  `ELFOSABI_GNU`), program headers (`PT_LOAD`, `PT_DYNAMIC`, `PT_INTERP`, `PT_TLS`,
  `PT_GNU_RELRO`, `PT_GNU_STACK`, `PT_GNU_EH_FRAME`, `PT_GNU_PROPERTY`, `PT_NOTE`), dynamic
  entries, string/symbol tables, `DT_GNU_HASH` and `DT_HASH`, `DT_VERSYM`/`VERDEF`/`VERNEED`,
  relocation iterators (`DT_RELA`, `DT_JMPREL`, `DT_RELR`), init/fini arrays, notes
  (`NT_GNU_PROPERTY_TYPE_0`: x86 ISA level, CET bits; `NT_GNU_ABI_TAG`).
* **Invariants:** every offset/count/size checked with checked arithmetic against the slice
  before use (threat rule 4); iterators yield `Result`; no allocation proportional to an
  untrusted count without a cap.
* **Failure:** typed `ElfError` → `dlerror` text ("invalid ELF header", "wrong ELF class",
  ...; exact texts from M14-0 probes).
* **Clauses:** s27_1_f_0 (wrong ELF class), threat rule 4.
* **Tests:** objects built by the system linker (`cc -shared`, `-Wl,-z,pack-relative-relocs`,
  `--hash-style=gnu|sysv|both`, versioned symbols via version scripts) parsed and compared with
  `readelf` output; a malformed corpus (truncation at every header boundary, overflowing counts,
  overlapping segments) + a fuzz target (security pass).

## 3. Mapper (`liella_ld::map`)

* **Inputs:** an open descriptor, the first 4 KiB read with one `pread` (L14-4), `fstat`
  (dev, ino) for identity.
* **Steps:** one `PROT_NONE` reservation of the span of all `PT_LOAD`s aligned to the largest
  `p_align` (honoured even above the page size, L14-5); each segment `MAP_FIXED` inside the
  reservation (never outside it); `.bss` tail zeroed and anonymous pages mapped;
  `PT_GNU_RELRO` made read-only after relocation; never writable and executable at once
  (`DT_TEXTREL`: segment RW for relocation, then RX before any code of it runs, L14-6).
* **Invariants:** segment file ranges inside the file; vaddr ranges sorted, non-overlapping,
  inside the reservation; permissions exactly as requested; `PT_GNU_STACK` with X refused
  (R14-13).
* **Failure:** unmap the reservation, close, typed error → `dlerror`.
* **Clauses:** s27_1_c_1 (load), threat rule 4.
* **Tests:** `/proc/self/maps` checked after loading the corpus (permissions, no W+X); large
  `p_align` (2 MiB) object lands aligned; truncated file refused without a crash.

## 4. Search, cache and hwcaps (`liella_ld::search`, new `liella_ld::cache`)

* **Order for a name without `/`** (s27_1_c_1_1): `DT_RPATH` of the requester and its loaders
  (only when the requester has no `DT_RUNPATH`), `LD_LIBRARY_PATH`, `DT_RUNPATH` (requester only),
  the cache, the default directories. Names with `/` are opened as given (relative ones against
  the cwd, threat rule 3).
* **Liella's own sonames are pinned** (R14-3): `libc.so.6`, `libm.so.6`, the placeholders and the
  loader resolve to `<prefix>/lib` before any search, so a host cache can never pair our loader
  with the host's libc.
* **Dynamic string tokens:** `$ORIGIN` (directory of the requester; `LD_ORIGIN_PATH` only when
  not secure), `$LIB` (`lib64`/`lib/x86_64-linux-gnu`, to be probed), `$PLATFORM`
  (`x86_64`/`haswell`-style string: probe). Secure-mode limits: threat draft rule 2.
* **hwcaps:** for each directory, try `glibc-hwcaps/x86-64-v4`, `-v3`, `-v2` (only levels the
  masked `Features` supports) before the directory itself. Same `Features` value as libc's
  dispatch (D-4.25), so `glibc.cpu.hwcaps=-AVX2` also selects a lower subdirectory.
* **Cache:** `<prefix>/etc/ld.so.cache` (R14-3), format inspected and recorded in spec Appendix D
  (OD-3 approval) in M14-4; mapped read-only once, parsed as untrusted (threat rule 5): any
  inconsistency means "no cache" (fall back to default dirs), never an out-of-bounds read.
* **Failure:** not found → `dlerror` "cannot open shared object file: No such file or directory"
  (text probed).
* **Clauses:** s27_1_c_1_1, D-27.3.
* **Tests:** a temp tree with the same soname in RPATH/RUNPATH/LD_LIBRARY_PATH/cache dirs; ldd
  (`LD_TRACE_LOADED_OBJECTS=1`) lists compared with the reference for the non-Liella libraries;
  corrupt-cache corpus (every truncation point, wild offsets).

## 5. Symbols and versions (`liella_ld::symbols`)

* **Lookup:** GNU hash (bloom filter, buckets, chains) or SysV hash; one hash computation per
  distinct referenced symbol per object (L14-7: memo by symbol index during a relocation pass).
* **Scopes:** global scope = main program, its load-order dependencies, `RTLD_GLOBAL` objects
  in order; a dlopened object's local scope = its dependency tree; `RTLD_DEEPBIND` puts the local
  scope first; `RTLD_NEXT` = global scope after the caller's object (caller found by return
  address through the address index of §8).
* **Versioning** (GNU symbol-versioning document): `VERNEED` entries checked against the
  provider's `VERDEF` at load (missing version → failure with the probed text); lookup with a
  version matches that name or, for a reference without a version, the base/default definition;
  hidden (non-default) versions only by explicit version (`dlvsym`).
* **Binding rules:** `STB_WEAK` undefined resolves to 0; `STB_GNU_UNIQUE` one definition per
  namespace (a table keyed by name+version; the object becomes non-unloadable);
  `STT_GNU_IFUNC` definitions return the resolver's result at bind time (§6 ordering);
  protected/hidden visibility respected; copy relocations bind the program's copy.
* **Clauses:** s27_1_g_0, s27_1_c_3, s27_1_f_0 (undefined symbol, version mismatch).
* **Tests:** interposition corpus (preload overrides, `RTLD_NEXT` chains, DEEPBIND), versioned
  libraries with two versions of one name, unique symbols across two dlopens.

## 6. Relocation (`liella_ld::reloc`)

* **Types:** `RELATIVE`, RELR, `64`, `GLOB_DAT`, `JUMP_SLOT`, `COPY`, `IRELATIVE`, `DTPMOD64`,
  `DTPOFF64`, `TPOFF64`, `TLSDESC`, `PC32`/`32`/`32S` only in `TEXTREL` objects (others refused
  with a diagnostic).
* **Order (L14-8):** objects in reverse load order (dependencies before dependents; cycles in
  load order); inside an object: RELR, RELA, then `JMPREL`; `IRELATIVE` and references bound
  to IFUNC definitions after every non-IFUNC relocation of that object, so a resolver only
  runs once the object (and its dependencies) are fully relocated (threat rule 6); `COPY`
  relocations of the program after its providers are relocated; RELRO last.
* **Target memory:** before publication, a `&mut [u8]` of the object's writable segment (boundary
  slice conversion, dropped before `mprotect`). After publication (lazy fix-ups), GOT slots are
  written through `&[AtomicU64]` with Release stores (L14-9) because other threads may read them.
* **Failure:** `RTLD_NOW` undefined symbol → unwind the whole dlopen (unmap all newly loaded
  objects, nothing published, no constructor run); `RTLD_LAZY` → function slots left to the
  lazy resolver (§12), data references still fail.
* **Clauses:** s27_1_c_1_2 (LAZY/NOW), s27_1_g_0 (IFUNC at bind time), s27_1_f_0.
* **Tests:** one corpus object per relocation type (built with the system toolchain); IFUNC
  resolver that calls into a dependency; copy relocation of a versioned data symbol; a planted
  bug (skip IRELATIVE ordering) must fail the resolver test.

## 7. TLS (`liella_ld::tls`, extends `liella_rt::tls`)

* **Static layout (variant II):** thread block at TP (D-4.15 layout, unchanged), the program's
  block ending at TP, then initial modules in load order, then a surplus (R14-4) for dlopened
  modules that need static TLS (`DF_STATIC_TLS`, `TPOFF` relocations) and, when it fits, any
  dlopened module (fast path, see below).
* **dtv:** `TB.dtv` (0x08, already reserved) points to a per-thread vector: generation +
  per-module block pointer. Module IDs reused after dlclose with a generation bump.
* **`__tls_get_addr`** (exported by ld.so): read dtv (tb-field), compare generation, return
  `block + offset`; slow path (allocate the block, update the dtv) in Rust. Hot for C++
  `thread_local` in shared libraries: Rust first, measured against the reference
  (`cbench_tls` rows, M14-6); asm only under the HOT-KERNEL ruling if a measurement requires it.
* **TLSDESC:** the descriptor function has a special convention (preserves all registers but
  `%rax`), so it cannot be Rust: `tlsdesc_static` is `movq 8(%rax),%rax; ret`; the fallback is a
  branch-free trampoline that saves every caller-saved and vector register, calls the Rust slow
  path, restores (R14-8). Modules placed in the surplus always get the static form.
* **Per-thread allocation for libc:** `__liella_tls_layout()` (sizes, alignment) and
  `__liella_tls_init(block)`/`__liella_tls_release(block)` in `LIELLA_PRIVATE` (§14): libc's
  `pthread_create` places the static area next to its stack as today and asks the loader to
  copy the images and build the dtv. This closes the D-22.10 interim gap.
* **dlopen with existing threads:** a module placed in the surplus is initialised in every live
  thread's block before the dlopen returns (no thread can reach it earlier); otherwise blocks are
  allocated lazily on first access from the loader's arena (R14-5); allocation failure aborts
  (s27_3_f_0).
* **Clauses:** s27_3_c_0, s27_3_f_0, s27_1_c_4 (TLS in use), s27_1_c_7 (dlinfo TLS module/ block),
  s27_1_f_0 (static TLS exhaustion).
* **Tests:** TLS in exe/needed/dlopened objects across GD, LD, IE, LE and TLSDESC models; threads
  created before and after a dlopen; dlclose/re-dlopen reusing a module ID; exhaustion of the
  surplus gives the dlerror text.

## 8. Object lists, RCU and lookups by address

* **D-27.1:** the list of loaded objects is an immutable snapshot (Arc-like, published with one
  Release store); `dl_iterate_phdr` and `_dl_find_object` read the current snapshot without a
  lock; `dlopen`/`dlclose` serialize on one writer lock. An object's memory is unmapped only after
  every reader that may see it has finished (a grace period: per-thread reader epochs in the
  thread block), so a callback never sees freed memory.
* `dl_iterate_phdr` fills `dlpi_adds`/`dlpi_subs` (unwinders use them to invalidate caches),
  `dlpi_tls_modid`/`dlpi_tls_data`.
* `_dl_find_object` and `dladdr`: a sorted array of (start, end, object) in the snapshot,
  binary search; `PT_GNU_EH_FRAME` precomputed per object.
* **Deviation:** spec s27_1_c_8 says the loader lock is held during the callback. Without the
  lock a callback that calls `dlopen` does not deadlock and a concurrent `dlopen` proceeds; this
  needs a `docs/differences-from-glibc.md` row (R14-6, INFORMATIONAL since D-27.1 decided it).
* **Clauses:** s27_1_c_8, s27_1_c_9, s27_1_c_6.
* **Tests:** `dl_iterate_phdr` during concurrent dlopen/dlclose loops (phase plan test surface),
  `_dl_find_object` from a signal handler, libgcc unwinding through dlopened code.

## 9. Constructors and destructors

* **Init:** after relocation of the whole new set: `DT_PREINIT_ARRAY` of the program (start
  only), then each new object's `DT_INIT` then `DT_INIT_ARRAY`, dependencies first (topological
  over `DT_NEEDED`, ties and cycles in load order). Called with `(argc, argv, envp)` through
  `liella_machine_call3`.
* **Fini:** reverse of the init order, at `exit` (libc calls the `rtld_fini` the loader passed
  in `%rdx`) and at the last `dlclose`; `DT_FINI_ARRAY` (reverse) then `DT_FINI`; `__cxa_atexit`
  handlers registered with a DSO handle run at its unload (libc's `__cxa_finalize`).
* **Recursive loader calls from constructors** (a constructor calling `dlopen`) are allowed: the
  writer lock is re-entrant for the same thread; the object list is published *before* its
  constructors run (as needed for `dlsym` from a constructor) with a per-object "initialised"
  state.
* **Clauses:** s27_1_c_1, s27_1_g_0 (dependency order), s27_1_c_4.
* **Tests:** the constructor/destructor order corpus (diamond, cycle, dlopen from constructor,
  dlclose in destructor), each run against the reference and compared line for line (M14-0
  records the reference order; the corpus is black-box).

## 10. dlopen / dlclose / dlsym family (`liella_ld::api`; exports in `libc.so.6`)

* **Handles:** pointer to the object's link map (public prefix `l_addr`, `l_name`, `l_ld`,
  `l_next`, `l_prev` exactly as `<link.h>`; private fields after). `dlopen(NULL)` = main program
  handle (global scope).
* **Refcounts:** per object, counted per direct `dlopen` plus per dependent; `RTLD_NODELETE`,
  unique symbols, and TLS in use (s27_1_c_4) pin it; `RTLD_NOLOAD` only bumps an existing
  object; `RTLD_GLOBAL` on a re-open promotes it into the global scope.
* **dlerror:** per-thread state (D-27.2) in a Liella thread-block slot, text built at failure,
  returned once then cleared.
* **dladdr/dladdr1** (`RTLD_DL_SYMENT`, `RTLD_DL_LINKMAP`), **dlinfo** (all `RTLD_DI_*`
  requests of `<dlfcn.h>`; `RTLD_DI_SERINFO` sizing protocol).
* **Clauses:** s27_1_c_1..c_7, s27_1_f_0.
* **Tests:** the `RTLD_*` mode matrix; refcount sequences; dlerror per thread; dlinfo outputs
  compared with the reference by probe.

## 11. Namespaces (`liella_ld::namespaces`)

`dlmopen(LM_ID_BASE|LM_ID_NEWLM|lmid)`: each namespace has its own object list, global scope and
unique-symbol table; libc.so.6 is loaded once per namespace (its own heap and state, as an
"isolated copy" requires). Number of namespaces: R14-11 (recommend no fixed cap). `r_debug`
version 2 lists namespaces (§13). Clauses: s27_1_c_2, s27_1_c_7. Tests: two copies of a library
with a global counter; dlsym across namespaces fails; libc state isolation.

## 12. Lazy binding

`JUMP_SLOT` entries initially point at the object's PLT stub as linked; `GOT[1]` gets the object,
`GOT[2]` the trampoline (`machine/lazy.S`, R14-8): save argument and vector registers (XSAVE or
FXSAVE variant chosen once at startup, as the CPU-variant ruling allows), call the Rust resolver
(lookup, atomic GOT store, L14-9), restore, jump to the target. `LD_BIND_NOW` / `DF_BIND_NOW` /
`RTLD_NOW` bind eagerly. `LD_BIND_NOT` (cleared in secure mode) skips the GOT store.
Clauses: s27_1_c_1_2. Tests: a function defined by a later `RTLD_GLOBAL` dlopen is found at first
call; vector arguments survive the trampoline; forced-variant test of both save forms.

## 13. Debugger rendezvous (`liella_ld::debug`)

`_r_debug` (40 bytes, `r_version` 2 = `r_debug_extended` with `r_next` per namespace),
`r_map` = the base namespace's list, `r_brk` = `_dl_debug_state` (an empty, never-inlined
function), `r_state` `RT_ADD`/`RT_DELETE` before and `RT_CONSISTENT` after each change,
`r_ldbase` = loader base; `DT_DEBUG` of the program set to `&_r_debug`. The link-map list the
debugger walks is the public prefix. Clauses: s27_4_c_0. Tests: GDB (`info sharedlibrary` after
start, after dlopen/dlclose, in a second namespace) scripted in batch mode on Zen 1.

## 14. libc.so.6 under Liella's ld.so (startup path)

Today (static programs): `_start` → `__libc_start_main` steps 1-6 (`liella_rt::start`).
Dynamic programs cannot run (host loader refuses our libc; D-22.10 threads `EAGAIN`).

With our loader:

| Step | Who | What changes |
|---|---|---|
| Kernel maps program + `ld.so`, jumps to ld.so | kernel | `AT_BASE`, `AT_SECURE`, `AT_RANDOM` read by ld.so |
| Bootstrap (§1) | ld.so | provisional TB; secure decision; `UNSECURE` clearing (the same list; libc's later pass is then a no-op) |
| Load + TLS layout + **final TB** | ld.so | thread pointer, canary (`AT_RANDOM`), pointer guard, `TB.flags` "Liella runtime", dtv; static TLS images copied: libc's step 1 moves here for dynamic programs |
| `__rseq_*` objects and initial rseq registration | ld.so | values published in ld.so's data; libc's `pthread_create` reads them |
| Relocation (§6) | ld.so | libc.so.6 is relocated first (deepest dependency) |
| **`__liella_libc_early_init(&StartInfo)`** (LIELLA_PRIVATE) | ld.so calls libc | libc's steps 3-4 move here: `environ`, program names, tunables, CPU paths (`cpu::init_with`, the D-4.25 flag), the NULL-folding guard (S6). Runs before *any* constructor, `.preinit_array` included, so constructors see a fully initialised libc |
| Init (§9) | ld.so | preinit (program), then shared objects' init, dependencies first |
| `_start` → `__libc_start_main` | program | detects the Liella-runtime flag + `rtld_fini`: skips steps 1-4, registers `rtld_fini`, runs the program's `DT_INIT`/`INIT_ARRAY` when `init` is NULL (new crt1) or calls `init` (old crt1); order confirmed by the M14-0 corpus |
| threads | libc | `pthread_create` gets static TLS + dtv through `__liella_tls_*` (§7): full threads |
| malloc | libc | unchanged (libc's heap; lazy init). The loader keeps a separate small arena (mmap-backed) for link maps and dynamic TLS (R14-5) and never calls the interposable `malloc` |

**Hot-path dispatch survives unchanged.** The D-4.25 `AtomicBool` and the scanners' D-4.14 flag
need no relocation and start `false` (SSE2 baseline, correct) until early init sets them; they
are now set before any constructor rather than at `main`, so more code runs the selected
variant, never less. In a `glibc-hwcaps/x86-64-v3` build of libc (P4/F46) the flags can fold to
compile-time constants (the loader only picks v3 when the masked `Features` say AVX2 is active,
so the constant is never wrong): a further saving, proposed as an experiment row. The NULL
folding guard (S6) defaults to the explicit checks until early init has read
`vm.mmap_min_addr` (ASSUMED: to be verified by a test that calls `memcpy(NULL, ..)` from a
`.preinit_array` function). Function alignment and code layout of `libc.so.6` are link
properties: the mapper honours `p_align`, so they survive. What changes for hot calls: a
program calls libc through its PLT (`jmp *GOT`), exactly as with the reference, so dynamic
benchmark rows compare like with like (R14-16); calls inside libc stay direct (the
`copies.rs` GOTPCRELX relaxation is unchanged).

**Private interface `LIELLA_PRIVATE`** (version node of ld.so, never in public headers):
`__liella_libc_early_init` (libc → called by ld.so), `__liella_tls_layout/init/release`,
`__liella_dl_open/close/sym/addr/info/iterate/find_object/error` (libc's exports forward to them,
one call each), `__liella_rtld_main_map`. A version mismatch between the two files (built from
different commits) is refused at load with a diagnostic (a build-ID-like constant compared once,
L14-10).

## 17. libthread_db (`liella-thread-db`, F30, §22.10)

## 18. NSS modules (F27)

libc's NSS engine (D-16.1) gains a "module" service kind: `libnss_<service>.so.2` loaded with
`__libc_dlopen`-style internal `dlopen` (`RTLD_LAZY|RTLD_LOCAL`), only from the trusted
directories, service names plain identifiers (threat rule 7); functions `_nss_<service>_<db>_r`
called per the GNU C Library manual's "NSS Module Interface" (the documentation, not source);
`__nss_hostname_digits_dots` exported for them (§16.1). Tests: a test module built by the suite;
`libnss_systemd`/`sss` smoke runs on Zen 1 if installed.

## 19. `ld.so` as a program

`ld.so [--list] [--library-path P] [--preload L] [--inhibit-cache] [--argv0 S] [--audit A]
[--verify] PROGRAM ARGS` per ld.so(8), and `LD_TRACE_LOADED_OBJECTS` (what `ldd` uses). This is
also how the gate runs unmodified host binaries (R14-14).

## 20. Optimization levers (owner rule; one line each)

* SIMD: no (loader work is pointer chasing and hashing; bloom filter is one word test).
* Precompute/cache: the GNU hash is already the precomputed index; memoise per relocation pass
  (L14-7); worth a look later: a persistent per-machine "prelink-like" resolution cache — a
  trust and invalidation problem, experiment row only.
* Dependent-load chains: symbol lookup is hash → bucket → chain → symtab → strtab; keep per-object
  table pointers in one cache line of the link map.
* Branches → arithmetic: no material case.
* GOT/PLT: programs call libc through the PLT as with the reference; rewriting PLT code: no
  (writable text, breaks page sharing, W^X).
* Cache lines / NUMA: object snapshot read-mostly and immutable; loader data per process, no
  NUMA concern.
* Read-mostly lock-free: yes (§8, D-27.1).
* Syscalls: per object one `openat`, one `pread`, one `fstat`, one reservation `mmap`, one `mmap`
  per segment, `mprotect` for RELRO, `close`; count against the reference with `strace -c`
  (M14-13); io_uring: no (secure/seccomp risk, few calls).
* Worth a look: 2 MiB-aligned `libc.so.6` text + `MADV_HUGEPAGE` on its text mapping (needs a
  kernel with read-only file THP) to cut iTLB misses on hot rows: per-machine page-cache cost,
  no per-process cost; proposed as an experiment row once dynamic benches exist.
