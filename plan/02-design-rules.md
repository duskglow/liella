## 2. Design rules (normative)

These rules are what makes 3,943 symbols consistent. Every rule is checked mechanically where
possible (the last column).

### 2.1 Safety and the unsafe policy

| # | Rule | Enforced by |
|---|---|---|
| S1 | **No `unsafe` Rust outside `liella-boundary`.** Every other crate (`liella`, `liella-legacy`, `liella-math`, `liella-rt`, `liella-kernel`, `liella-abi`, `liella-ld`, `liella-thread-db`, `spectest`, `xtask`, products) carries `#![forbid(unsafe_code)]` without exception. The one exception is the native Rust facade `liella-native` (D-X.10), a library for programs rather than part of the C library: its C-ABI declarations are in one file under category *native* (§3.2). | The compiler (`forbid` cannot be overridden); `cargo xtask unsafe-audit` checks that the attribute is present |
| S2 | **Inside `liella-boundary`, unsafe is permitted in exactly six categories**, because the language gives no safe way to do these things (verified against Rust 1.98, edition 2024): <br>**extern**: declaring the C syscall layer's functions (`unsafe extern "C"`). <br>**export**: exporting C symbols (`#[unsafe(no_mangle)]`, `#[unsafe(export_name)]`). <br>**slice**: converting a C pointer (with a length) into a Rust slice or reference. <br>**allocator**: `unsafe impl GlobalAlloc`. <br>**tb-field** (owner ruling 2026-10-06, PJ-21): reads of the current thread's own `ThreadBlock` fields by a fixed, compile-time checked offset, as one `%fs`-relative `mov` in `tb::read` (`crates/boundary/src/tb.rs`), the only inline assembly in Rust code. Callers name a field through a sealed marker type (`tb::Locale`), never an offset or a type; `field!` checks that the field is an 8-aligned `AtomicUsize` inside the block, so the load is that field's `Relaxed` atomic load. Evidence: perf annotate on Haswell-EP after PJ-19 put ~39% of `toupper` in the call to `liella_machine_tp` and ~15% more on the dependent load of `ThreadBlock.locale` (0xa8). Owner: "We want to limit unsafe code to what's absolutely necessary. This sounds like it's necessary for performance reasons, and can still be gated by rust's type safety." Nothing else qualifies: writes, other threads' blocks and any other machine access stay in `csys/` (S3).  <br>**hot-kernel** (owner ruling 2026-10-08, MEM-K1, D-4.22): the small-size copy and fill kernels in `crates/boundary/src/hot.rs`, the only file where the category is permitted: unaligned loads and stores (SSE2 intrinsics, `read_unaligned`/`write_unaligned`) over ranges the entry has already validated (size class, NULL), no checks inside, no inline assembly. The module comment states the kernel contract (valid ranges in, nothing outside them touched); each kernel needs an oracle test, a sweep and a planted-bug test proving a wrong byte or length fails it. Owner: "unsafe/asm/C allowed in hot paths, very bounded; Rust validates once at the entry." <br>The crate is `#![deny(unsafe_code)]`. Each site carries `#[allow(unsafe_code)]` directly after a comment `// UNSAFE(<category>): <why this cannot be avoided>`, and each unsafe block's comment also contains clippy's `SAFETY:` justification. Each category is allowed only in the files named in §3.2. | `cargo xtask unsafe-audit` (category, file, documentation), clippy `undocumented_unsafe_blocks` and `multiple_unsafe_ops_per_block` (deny) |
| S3 | **Everything that needs the machine is in the C syscall layer** (`csys/`): system calls, and the assembly primitives Rust cannot express safely (§2.5). The C layer contains no logic. *Exception (owner ruling 2026-10-06):* the one S2 *tb-field* load of the current thread's own block; `unsafe-audit` rejects inline assembly anywhere else in Rust and a second *tb-field* site. | `cargo xtask csys-audit`; `cargo xtask unsafe-audit` (inline assembly) |
| S4 | **Foreign declarations are sound by construction.** Every `ffi` item is declared `safe`. Items taking pointers are private to `liella_boundary::ffi` and wrapped there by functions taking Rust slices or references, so no code can pass an arbitrary address. The soundness argument lives on each declaration. | Review; `unsafe-audit` limits category *extern* to `ffi.rs`/`caller_alloc.rs` |
| S5 | **No UB reachable from the internal API.** Its signatures are safe Rust, so any input is memory-safe by construction. | The compiler |
| S6 | **The C boundary defines outcomes for contract violations wherever detection is O(1).** A NULL where the contract has an error channel gives that error (`EFAULT`/`EINVAL`). Where it has none, it gives a diagnostic plus abort, not UB. Fixed-size objects are received as `Option<&T>`/`Option<&mut T>` parameters, which are safe Rust with NULL handled by type. What cannot be detected from a C pointer (a buffer shorter than claimed) stays the caller's responsibility (F2). Compare extension (owner ruling 2026-10-10, "ruling: exception granted. As with the others, safety still must be maintained at some level in the process."; MEMCMP-FOLD, D-4.23/D-4.41 amendments): `memcmp`, `bcmp` and `__memcmpeq` let a NULL fault on page zero for 8 <= n <= 64 only, in the head probe of their direct entries in `csys/src/machine/fold.S`, under the same startup guard word (folding on only while `vm.mmap_min_addr` >= 64 KiB); 1-7, n > 64, and every size with the guard off or unreadable keep the explicit abort. Safety in the chain: the guard, the Rust tail entered only after both 8-byte loads succeeded (debug assertions), and the child-process tests (fold on: SIGSEGV; off or outside 8-64: abort). memchr extension (owner ruling 2026-10-11, "memchr: yes, same caveat, there must still be safety at some level."; MEMCHR-FOLD, D-4.48 amendment): `memchr` lets a NULL fault on page zero for 1 <= n <= isize::MAX in its direct entry (`csys/src/machine/scan.S`), under the same startup guard; its first load always lies in [s & -64, s + 64), page zero for a NULL s. n > isize::MAX and every n with the guard off keep the explicit abort; rawmemchr and memrchr keep it always. Exception (owner rulings 2026-10-08, NULL folding, scope option B; D-4.22): the small copy and fill entries (`memcpy`, `memmove`, `mempcpy`, `memset` and their `_chk` forms) let a NULL fault on page zero (SIGSEGV, as glibc observably does) instead of the abort for 1 <= n <= 64 only, in assembly (`csys/src/machine/fold.S`: no Rust code performs a deliberate NULL access, which is UB), and ONLY while the startup guard finds `vm.mmap_min_addr` >= 64 KiB; below that, unreadable or malformed, the explicit abort stays. 65 <= n <= 128 and larger sizes always keep the explicit abort. A CAP_SYS_RAWIO process may map page zero despite the sysctl; it then gets glibc's silent page-zero access, never worse. | Tests in `crates/boundary/tests` |
| S7 | **Panic-free.** The library never panics on any input. A panic is a bug that aborts. | clippy `unwrap_used`, `expect_used`, `panic`, `indexing_slicing`, `arithmetic_side_effects` (warn now, deny from each phase's exit) |
| S8 | **Fallible allocation only.** Allocation failure is `ENOMEM`, never an abort. | Review; disallowed-method list (phase 3) |
| S9 | **No `static mut`, and no unsynchronised shared state.** Exported data objects are `#[repr(C)]` structs of atomics with the Appendix C.5 sizes (F45). Async-signal-safe functions take no locks and allocate nothing. | Review; AS-safety tests (phase 5) |
| S10 | **Secure-execution mode** is decided once at startup and consulted through one API. | Tests (phase 4) |
| S11 | **Unwinding.** No Rust frame is ever unwound through. Cancellation is an explicit error that propagates to the boundary (D-22.2). Foreign exceptions through callbacks are covered by OD-6. Exception (OD-6 revised 2026-10-21): a `pthread_once`/`call_once` routine runs in an assembly frame (machine/once.S) whose personality routine resets the object during the cleanup phase and lets the exception pass to the caller, as glibc does; no Rust frame is on that path. Exception 2 (CALLBACK-UNWIND, OD-6 revised): a C++ exception thrown by a search/sort/tree/`ftw`/`nftw`/`scandir`/`fts` callback passes the library's Rust frames, which have no landing pads, by their call-frame information (D-14.6); state those frames hold is put back by an undo routine that machine/guard.S's personality runs during the cleanup phase (`s22_threads::guarded`). | Design |

### 2.2 Errors

| # | Rule |
|---|---|
| X1 | One internal error type: `liella::error::Error`, which is an `Errno` (the kernel's numbering, ⚑ KERN) plus an internal `Canceled` marker. Non-error alternative outcomes are typed results (`Parsed::NoDigits`, `Lookup::NotFound`, `Written::Truncated { needed }`). |
| X2 | The *translation layer* owns every C convention, one `liella_abi::ret` function per convention. |
| X3 | `errno` is written only on failure, and never on success. The C layer never touches `errno`: it returns the raw kernel result, and `liella_kernel::errno` decodes it. |
| X4 | `EINTR` is surfaced (⚑ KERN, C0.3), with no hidden retries except where a contract requires completion. |
| X5 | **The kernel is a value.** Every kernel-touching function in the Rust library is generic over `S: liella_kernel::Sys` (and `Machine`). Production uses `liella_boundary::CSys`, zero-cost after monomorphisation. Tests wrap any kernel in `liella_kernel::testing::Faulty` to inject `EINTR`, `ENOSPC`, `EMFILE`, `ENOMEM` (and, from phase 3, short transfers) into chosen calls. This is also what keeps the crate graph acyclic (§3). |

### 2.3 Speed

| # | Rule |
|---|---|
| P1 | Translation is zero-cost: each export is one expression, inlined, with LTO across crates. Release products also use cross-language LTO (clang at rustc's LLVM version, `-Clinker-plugin-lto`), which inlines the C wrappers completely (OD-C3, measured). |
| P2 | No double scans of C text where avoidable (F1, revised for the new constraints). |
| P3 | No system call when the kernel publishes the answer (vDSO clocks and `getcpu`, rseq CPU id, auxv). Nothing the kernel may change is cached (credentials are per thread, PIDs change on fork). |
| P4 | **Vectorisation without runtime dispatch.** Runtime CPU dispatch (the IFUNC equivalent) would need `unsafe` calls to `#[target_feature]` functions, which S1 forbids. So hot paths are written as safe SWAR (word-at-a-time within known bounds) and auto-vectorisable loops, and `libc.so.6` is built several times: baseline x86-64, and `x86-64-v2/v3/v4` builds installed in the `glibc-hwcaps` subdirectories, which our `ld.so` selects (spec §27.1). Statically linked programs get the baseline build (F46). *Amended by P7:* the C layer's machine primitives may select instructions by CPU feature themselves; Rust code stays free of dispatch. |
| P5 | Single-threaded fast paths skip atomics until the first thread is created (`__libc_single_threaded`, spec §22.1). |
| P6 | Performance budgets per function class are asserted by `cargo xtask bench` (from phase 0). A phase cannot exit with a budget regression. |
| P7 | **Performance floor** (owner, 2026-10-01). If an implementation cannot meet its budget in safe Rust, it may use guarded C or assembly in the C layer's *machine* class. That code is optimised for single-operation speed with the best instructions the CPU offers: it may check CPU features itself (CPUID, OD-C1) and choose among AVX2, SSE2 and ERMS paths. Rust owns the safety contract. It validates every bound before the call: pointers, lengths within `isize`, region arithmetic, overlap. It checks every postcondition that is checkable in constant time, so memory safety on the Rust side does not rest on the assembly being correct. For terminator scans the one postcondition Rust cannot check cheaply is "this is the *first* NUL". For that, the scanner is held to exhaustive tests: every alignment, every length, the terminator at every offset relative to a page boundary followed by an unmapped guard page (D-4.14, phase 4). A failed check aborts only for answers no concurrent writer can cause (an index past its bound); a reported byte that changed under the call is rescanned once (D-4.21). `benchmarks/progress.md` records Liella against glibc at each phase exit. |
| P8 | **Modern hardware** (owner, 2026-10-02). Remaining phases and the optimization pass assume modern hardware: abundant memory, fast SSD storage, many cores with NUMA topology. Do not waste resources, and do not constrain designs for limits that no longer exist. Frequently used data that rarely changes (time zones, locales, character-set tables) may be loaded once, pinned in memory and treated as constant until explicitly reset; large read-only data may be memory-mapped (the page cache is a feature); data legitimately shared between processes (locale and zone tables) may live in shared memory, loaded once per machine; precomputed tables are preferred over runtime computation where they fit comfortably; cache-line alignment and NUMA-aware placement are first-class design considerations. Code written before this rule is not retrofitted: where P8 suggests a better approach, it is recorded as an optimization-pass target (`benchmarks/progress.md`). |
| P9 | **Standing performance review** (owner, 2026-10-02). Before each phase, the profiled gaps of completed phases are reviewed: a gap closed by a small, targeted fix (a cache, a type change, a fast path, a few lines in one or two functions) is fixed then; one needing architectural change or significant work is deferred to the optimization pass (before the first release since 2026-10-04, P10). Budgets are loose sanity bounds unless the owner sets targets. |
| P10 | **Optimization stage rules** (owner, 2026-10-04; the optimization pass now runs before the first release, with a short final pass after phase 15). Scope: changes that keep the present ABI contract; anything needing an ABI change goes on the "could not improve" list. (1) Safe, then fast, then scalable: never remove a check or add `unsafe` for speed; code that already meets glibc is left alone. (2) glibc's number shows a task is doable in that time: it is the target, algorithms first; a gap that survives the algorithmic work is reported with its reason, not forced. (3) Preference: algorithmic change; memory and NUMA trades; helper threads; assembly or SIMD last. (4) Memory is targeted and bounded: each use states its cap and what it scales with (process, thread, machine); read-only shared data lives once per machine in the page cache; compute must not expand to fit the available cores. (5) "Helper threads are only helpers. The serial path is always complete and correct on its own; never rely on a helper for work that would be fine on the calling thread. Use them sparingly, when needed." Results bit-identical to serial (tested, also under `taskset` on one core); no nondeterminism; a small pool created lazily on the first large job, with a threshold keeping small jobs serial; creation may fail (`RLIMIT_NPROC`, cgroups, seccomp) and the serial path then runs; helpers block all signals, are counted in the credential-change broadcast, are quiesced across `fork`, never work inside fork/exec/exit windows, and are never used by async-signal-safe functions; user callbacks (comparators, `ftw`/`scandir` functions) run on the calling thread; the rounding mode is propagated to helpers and exception flags and `errno` merged back. The first use of a helper thread is an owner ruling (with a recommendation); if the pattern is approved, later uses are decided and reported. (6) Assembly or SIMD is unsafe-class under the current policy: only when everything else is exhausted, at the bare minimum, each use an owner ruling, tested as D-4.14 tests the scanner (every alignment and length, the terminator at every offset around a guard page). (7) Observable behaviour is frozen (output, error codes, ordering, stability, kernel-visible effects a correct program could depend on); a change to one is an owner ruling; the glibc comparison tests are the gate. (8) Cold start and first-call cost are measured, not only steady state; a table costing more to load than a short program runs is a loss (load lazily or map). (9) Method: the pre-optimization numbers first, on the benchmark machine; one commit per change with before and after; medians with min and max, the same-run glibc ratio as the headline; a warm-up run discarded; a result within about 10% of a budget re-run; realistic inputs (validation profiles) as well as microbenchmarks; this stage's tables are working numbers (release-grade numbers later, on a quiet machine). (10) Stop within about 10% of glibc, or with a documented reason. (11) Targets: `printf`/`snprintf`, `strcmp`/`strcoll`, iconv, `strftime`/`mktime`, the regex lazy DFA, `fnmatch`, `wordexp`, gettext's `stat` per lookup, and what validation profiles show; not `vfork` (it touches the unsafe policy: an owner ruling with a recommendation). (12) Leftovers go on the "could not improve" list, each classed: needs an ABI change, a policy change (unsafe or assembly), an architectural change, or glibc uses assembly we cannot match under our rules. (13) The stage is timeboxed (the cutoff stated in `benchmarks/progress.md`). Machines: the result names the machine and CPU model; absolute numbers are never compared across machines, only the same-run glibc ratio; nothing runs on a machine while another agent is timing on it. (14) Any cache (owner, 2026-10-05): its benchmarks use inputs that vary across iterations or follow recorded traces of real programs, so a cache cannot flatter a repeated-call loop; cold and warm numbers are reported separately. |

### 2.4 Scalability and consistency

| # | Rule |
|---|---|
| C1 | **One contract per need.** Variants (`_r`, `_l`, `64`, `_chk`, `__isoc99_`, `__isoc23_`, type suffixes, exec forms, BSD and SVID aliases) are translations of one internal function (spec H3, H5, H7, H13, H14). |
| C2 | **Explicit context.** Locale, time zone, environment, allocator domain, cursors, seeds, parser state *and the kernel itself* (X5) are parameters or values, never ambient (H4, H15). |
| C3 | **Generic numerics.** One implementation per operation over all formats and widths (H14). |
| C4 | **Every exported symbol has a manifest row** (`spec/symbols.tsv`, with versions from Appendix C.3) and a translation test. **Every spec clause and every Appendix C layout has a test ID.** |
| C5 | **Historical semantics are quarantined** in `liella-legacy`. `liella` never imports it (H8). |
| C6 | **P-lift:** ARB limits are lifted when no correct program can depend on the limit. They are kept when ABI-visible (Appendix C) or kernel-forced (⚑ KERN). |
| C7 | **P-scope:** hidden state the contract describes as process-global stays process-global (synchronised) where cross-thread use is plausible and legal, and becomes per-thread where cross-thread use was already a data race. |

### 2.5 The C syscall layer

| # | Rule |
|---|---|
| K1 | **Classes.** The layer's classes:<br>• **sys**: one wrapper per system call, returning the raw kernel result (value or `-errno`).<br>• **machine**: assembly primitives that Rust cannot express without `unsafe`. The approved set: process entry, signal restorer, setjmp/longjmp register save and restore, context switch, thread start on a new stack, thread-pointer read, vDSO call by address.<br>• **machine additions**, proposed (OD-C1): CPUID/XGETBV, MXCSR/x87, PKRU, the explicit-zeroing barrier, calling code at an address.<br>• **adapter**, proposed (OD-C1): variadic entry points and `va_arg` accessors. |
| K2 | **No logic.** Every function body is one statement: a system call, an assembly sequence, or a single forwarding call. No `if`/`else`/`switch`/loops/`goto`/`?:`, and no `errno`. Adapters may declare, start and end a `va_list` around their single forwarding call. |
| K3 | **Freestanding.** Includes only `liella_csys.h`, `<stddef.h>`, `<stdint.h>`, `<stdarg.h>`. Assembly only under `csys/src/machine/`. Built with `-ffreestanding -fno-builtin -Wall -Wextra -Werror`. |
| K4 | **Names.** `liella_sys_*`, `liella_mach_*` and `liella_va_*` for internal entry points. The variadic adapters carry the exported glibc names, and are compiled only for products (`LIELLA_EXPORT`), so test builds never interpose on the host libc. |
| K5 | **Header and declarations stay in step.** `csys/include/liella_csys.h` and `crates/boundary/src/ffi.rs` must match. From phase 1, `xtask` generates `ffi.rs` declarations from the header. |
| K6 | **Tested through Rust.** The layer has no logic to unit-test. It is exercised through `CSys` by the 281 kernel-primitive tests, plus the build (`-Werror`) and `csys-audit`. |

### 2.6 Multi-core and NUMA (normative; owner policy 2026-10-01)

| # | Rule |
|---|---|
| M1 | Multi-core and NUMA behaviour are primary design inputs for the allocator, the threading model, and every layer whose policy decisions affect them. glibc's single-core-era structures are not a constraint to reproduce. |
| M2 | Shared mutable state on hot paths is partitioned (per node, per CPU or per thread), and each partition sits on its own cache lines. Statistics counters are partitioned too and summed when read. |
| M3 | Memory is placed on the node of the threads that use it, as a *preferred* policy (`MPOL_PREFERRED`) and never a hard binding, so a full node degrades to remote memory rather than to failure. |
| M4 | Ownership is recorded with the data (for example, a slab's owner), so that memory freed by any thread returns to its owner's partition without global coordination. |
| M5 | Questions every thread must answer, such as "which partition owns this address", are answered without locks. |
| M6 | Each phase records its multi-core and NUMA decisions in the register below, and the phase's Delivered block summarises them. |
