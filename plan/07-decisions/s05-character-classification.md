#### §5: Character classification

| ID | Spec | Ann. | Decision |
|---|---|---|---|
| D-5.1 | §5.1 | HIST, ARB | **Internal:** `ctype::{is_class(u8, &Locale), is_wclass(u32, &Locale)}`. **Boundary:** the `int` domain is decided by the exported table, which covers -128..255 (`__ctype_b_loc` layout, ⚑ COMPAT), so negative `char` values have a defined result instead of UB (observable, stricter). `EOF` is in no class. |
| D-5.2 | §5.3 | HIST | **Internal:** full Unicode case mapping (one-to-many, contextual) is available. **Boundary:** `towupper`/`towlower` use the simple 1:1 mapping required by the contract. |
| D-5.3 | §5.1 | COMPAT | The per-locale 16-bit class tables and 32-bit case tables are generated with the locale data (IP-20). `__ctype_b_loc` returns a per-thread pointer to the current locale's table. |
| D-5.4 | §5.1–5.3, §6.5 | ARB (spec silent on derivation) | **Built-in `C.UTF-8` tables from the UCD** (phase 7; IP-19, D-X.4, D-7.2). `cargo xtask unicode-gen` derives classes, simple case maps, title case and widths from `spec/unicode/15.1.0` and commits compact tables (`crates/core/src/unicode/`); `--check` is a gate like `csys-gen`. The derivation rules are chosen so the results equal the reference system's compiled `C.utf8` for every code point; a test compares them with `/usr/lib/locale/C.utf8/LC_CTYPE` when present and names any difference. The tables also serve the internal Unicode API (full case mapping, D-5.2; normalization for transliteration, D-6.9). `C.UTF-8` collates in code-point order. |
| D-5.5 | §5.1, §7.3 | COMPAT, PERF | **The per-thread ctype table pointers are always current, and every byte-classification entry reads them** (APPROVED by the owner 2026-10-06; the probes below come first). **Evidence (Haswell-EP, perf, Liella's own binary):** `toupper` resolves the locale on every call: thread pointer, the thread's `uselocale` word, the global handle, the interned object, its kind and table length, then the table: about 5 dependent loads and 5-6 branches; `toupper_c` is 2.4x glibc (about 1.3x expected after PJ-21). The ABI already has a per-thread cache: `__ctype_b_loc`, `__ctype_tolower_loc`, `__ctype_toupper_loc` return the address of the calling thread's pointer to the active table (spec §5.1 COMPAT note; table layouts `u16[384]` / `i32[384]`, index -128..255), and the headers' inline `is*`/`to*` forms read through it. Liella keeps those three words in `ThreadBlock` but fills them lazily (`locale::ctype_slot` re-resolves and stores on every `*_loc` call), and its own `toupper`/`is*` functions do not use them. **Decision:** (1) the three words hold the active tables at all times: `uselocale` stores this thread's; `setlocale` stores them for every thread that follows the global locale (or whatever semantics the probes below establish); thread creation initialises them; (2) `__ctype_*_loc` return the word's address without re-resolving; (3) `isalpha` ... `toupper`/`tolower` (and their internal callers) read the word through the typed thread-block read (PJ-21) and index: one `%fs` load, one range check (EOF and -128..255; other values as today), one table load. Tables are immutable and interned (never freed), so readers take no lock; each word is one aligned atomic store/load (Release/Acquire). **Three-way questions, settled FIRST by black-box probes (glibc vs Liella):** (a) after `p = __ctype_b_loc(); uselocale(l2);` does `(*p)[c]` classify by `l2`? (b) after another thread's `setlocale(LC_CTYPE, ...)`, does this thread's already-fetched `*p` follow it, and when? (c) `uselocale(LC_GLOBAL_LOCALE)` then `setlocale`. If Liella's lazy fill answers differently from glibc today, that is a correctness bug this row fixes (a differences row if the spec says otherwise). **Out-of-the-box follow-up (not in this row):** a per-table flag "ASCII-identical case and class for 0..127", computed when a locale is interned, so bulk internal users (`strcasecmp`, `FNM_CASEFOLD`, `REG_ICASE`, case-insensitive collation in C/C.UTF-8) take an AVX2 path folding 32 bytes per instruction where the flag holds. **Expected:** `toupper_c` and `isalpha_c` about 1.0-1.1x glibc on Haswell-EP; compiled programs stop paying a full resolution per `*_loc` call. **Implemented (PJ-22, 2026-10-07).** Probes (spec/behaviour/ctype-words.md): glibc keeps a fetched pointer current across `setlocale` in the same thread and `uselocale`; a new thread starts on the global locale; another thread's `setlocale` does not reach other threads (glibc), where Liella keeps D-7.8 (every thread on the global locale, at once; differences row updated). Liella before PJ-22 left fetched pointers stale until the next `*_loc` call: a correctness fix. Local decisions: (i) writers are `uselocale` (own words), `setlocale`/`liella_locale_invalidate` (every listed thread whose choice is the global locale, plus the caller, `thread::each_block`), thread listing (`list_insert`); every store of the global tables and every switch to or from the global locale holds the thread-list lock and reads the global handle inside it, so the last update is the newest locale; object-to-object `uselocale` and processes that certainly have one thread take no lock; no new lock order (the lock is taken with nothing held and nothing taken under it). (ii) Readers index the word through `conv::mapped_bytes` (the existing slice site that already serves locale file bytes): no new unsafe, tb-field stays 1. (iii) A word of 0 (a thread the runtime does not list: test processes, D-22.10) takes the old resolution path; `*_loc` fills it once. (iv) `pthread_create` clears the new block's `locale` word (a reused mapping could hold the old thread's). Cost: no memory per process or per thread; `uselocale` to/from the global locale in a multi-threaded process takes the thread-list lock once; `setlocale` walks the thread list once. |
| D-5.6 | §5.3, §4.3, §14 | PERF | **ASCII case folding without tables where the locale allows it** (PJ-23, D-5.5 follow-up; local decisions, no observable change). (1) `CtypeFile::parse` computes once per loaded `LC_CTYPE` a flag `ascii_case`: the byte maps (`tolower`/`toupper`) and the wide maps (`towlower`/`towupper`) of every character 0..127 are ASCII's. Built-in `C` and `C.UTF-8` always qualify (Unicode's simple case maps of U+0000..U+007F are ASCII's). `tr_TR` (Turkic `I`/`i`) does not, and keep the table path everywhere. The flag deliberately covers case maps only, not class masks: no fast path reads classes (`is*` is one load through the per-thread word since D-5.5), so a class difference must not disable folding. (2) Where it holds, `to_lower`/`to_upper` and `wtrans` (Lower/Upper) of a character below 128 use arithmetic instead of the file tables (`wtrans` used to re-parse a 3-level table header per call); `fnmatch` `FNM_CASEFOLD` and `REG_ICASE` gain through these. (3) `strcasecmp`, `strncasecmp` and the `_l` forms call `ctype::compare_folded`: with the flag, `bytes::compare_text_ascii_folded` compares 8 bytes per step in safe Rust (SWAR): equal words are skipped, ASCII words are lowered arithmetically, a differing word with a byte >= 128 and the tail go through the table fold byte by byte. Answers are the per-byte table fold's in every locale (differential tests: `bytes_exhaustive::ascii_folded_compare_equals_the_per_byte_fold`, `locale_data::ascii_case_flag_and_fast_folding_match_the_tables` over en_US.UTF-8, de_DE.ISO-8859-1, tr_TR.UTF-8, tr_TR.ISO-8859-9). Cost: one `bool` per loaded `LC_CTYPE` (per process), 512 table reads once at load; nothing per thread. Considered: AVX2 (32 bytes per step) needs assembly in csys/ (plan S2/S3): not proposed, see PJ-23 report for the measured share; fusing the two `strlen` scans of the operands into the comparison needs reads past the terminator (unsafe, page-crossing): not done. |
