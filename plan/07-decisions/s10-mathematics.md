#### §10: Mathematics

| ID | Spec | Ann. | Decision |
|---|---|---|---|
| D-10.1 | §10.0 | HIST | One generic implementation per operation. Formats that coincide are exported as aliases of one function (C3). |
| D-10.2 | §10.0 | HIST | **Internal:** `(value, Status)` with IEEE flags. No errno. **Boundary:** errno is set per `math_errhandling` (`MATH_ERRNO | MATH_ERREXCEPT`, kept). This is the only place math touches errno. |
| D-10.3 | §10.0 | — | Accuracy: correctly rounded where the contract requires it. For every other function, a documented ULP bound per function and format is established by the phase-M tests, and it must be at least as tight as the published bounds OD-1 records. **Owner addition (2026-10-05):** coefficients and tables are generated by project tooling (minimax or Remez fitting, high-precision evaluation) with the derivation recorded, never recalled from glibc's source (which is not read). Goal: results identical to glibc's wherever glibc is correctly rounded or the function is exact; elsewhere within glibc's documented error bound and as close to its output as the algorithms allow. Per function and format, the fraction of a large random sample plus the hard-case corpus on which Liella is bit-identical to glibc is measured; each mismatch is classified with the test oracle (glibc not correctly rounded, or a Liella error) and the table is recorded in `docs/differences-from-glibc.md`. glibc's particular approximations are not reproduced; a program found to depend on glibc's exact last bits is an owner ruling. |
| D-10.4 | §10.1, §10.3 | HIST, PATH | `isinf` returns ±1 (contract). `signgam` is an exported data symbol written by the `lgamma` translation. The internal `lgamma` returns `(value, sign)`. |
| D-10.5 | §10.6 | HIST, COMPAT | `fenv` keeps MXCSR and x87 in step. `__fpu_control`/`__setfpucw` set the startup x87 word. `__fpu_control` (GLIBC_2.2.5, 2-byte object, 0x037f) is its own csys member (`fpu_control.c`), so a static program that defines the name links; start-up applies a program's own value only in dynamic programs, as glibc (#810, #812, probe-settled). Proven now: export, archive member, static conformance (default and program-defined) and the glibc oracle of the dynamic programs. The dynamic hook's run on Liella and its "drop the hook" plant wait for Liella's ld.so (phase 14, #814); until then that run is a reported skip. |
| D-10.6 | §10.0 | COMPAT | `matherr` and `_LIB_VERSION` are inert compat symbols. |
| D-10.7 | §10.0 | — | **Products.** `crates/libm-so` links `liella-boundary` with feature `libm` (the math exports only) into a static library; `cargo xtask so` turns it into one relocatable object (unused sections dropped from the exports as roots), keeps only the math names global and archives it as `libm.a`, so its private copies of library code never collide with `libc.a`. Names glibc exports from both libraries (`frexp`, `ldexp`, `modf`, `scalbn`, `copysign`, `finite`, `__finite*`, `__signbit*`) are in both products, weak in `libm.a` (a static link takes `libc.a`'s). | D-10.8 | §10.0 | HIST | **Exports are generated** (`cargo xtask math-gen`): one body per family in `crates/boundary/src/posix/s10_math.tsv`, expanded over the default versions of `spec/abi/versions.tsv` and the C signatures of `spec/abi/prototypes.tsv` into `posix/s10_math_gen.rs`; symbols with `long double`/`_Float128` values get C forwarders (`csys/src/adapter/math_{libc,both,libm}.c`, OD-C4) compiled into the product that owns them. | D-10.9 | §10.0, §10.4 | — | **One soft-float core.** Every correctly rounded operation computes exactly (256-bit intermediates) and rounds once into the result format, so narrowing is the same code as `fma`. The rounding direction is an argument (C2), read by the translation from MXCSR (x87's control word for `long double`); x87 precision control is not honoured (results are always rounded to 64 bits; decided, reported). Flags travel in `Status` and are raised by `fpu::raise` (set in MXCSR; an SSE operation when the trap is enabled, which delivers `SIGFPE`); `feraiseexcept` sets overflow, underflow and inexact in the x87 status word as glibc does. Hardware `sqrt`/`fma` paths are for the optimization pass. |
| D-10.10 | §10.0–§10.2 | — | **glibc's observable conventions are matched** where the contract leaves them open and the result is exact (`spec/behaviour/libm-exact.md`): the default NaN's sign, which operand's NaN payload propagates (per function and format), `ERANGE` only for ±∞/±0 results, `lrint` of `_Float128` saturating, `fromfp`'s clamped values, the `fmin`/`fmax` choice between ±0, `significand`'s flags per format. Deliberate differences (predicates return 1; x87 unnormals are not finite; pseudo-denormals are canonicalized; `scalbl(NaN, −∞)`) are in `docs/differences-from-glibc.md`. |
| D-10.11 | §10.1 | — | Classification decodes through an optimisation barrier (`float::decode_opaque`): the compiler may otherwise turn bit tests back into floating comparisons, which raise invalid for a signalling NaN. |
| D-10.12 | §10.0 | — | **Oracle and tooling** (D-10.3): `crates/mathtools` (test and tool code; no product depends on it): arbitrary-precision arithmetic with correct rounding by Ziv's strategy, the Remez tool (`cargo xtask remez`, fit files in `crates/math/fits`, generated coefficients with their derivation in `crates/math/src/coeffs`, `--check` regenerates), and the measurement harness (`cargo xtask mathcmp FUNC FMT`: glibc and Liella built from one probe, bit-identical fraction, correct rounding and ulp error of each side against the oracle; exhaustive for `float`). The published bounds are `spec/abi/libm-ulps.tsv` (from the manual, `spec/tools/libm_ulps.py`). |
| D-10.13 | §10.3 | — | **Elementary functions of `float` and `double`** (milestone 2). Evaluated in double-double arithmetic (`math::dd`: error-free sum and Dekker product, no FMA) and rounded once from the exact sum of the two parts (`dd::round`, with the sign of the neglected remainder deciding ties and directed modes), so every result is correctly rounded in every mode; the binary32 forms run the same code on widened operands. The computation needs round-to-nearest: the translation (`mathret::elem`) switches MXCSR to its default for the call, restores it and raises the result's flags. Algorithms: table-driven `exp` (k·ln2/64), `log` (12-bit reciprocal table and an `atanh` series), `pow` as `exp(y·log |x|)` with exact powers detected, Payne–Hanek reduction for trigonometric arguments of 1500 and above (Cody–Waite below), `atan` by an `atan(j/64)` table, the hyperbolic functions from `expm1`/`exp`/`log1p` arranged without cancellation, `hypot` exactly in 256 bits in every format. Tables and series coefficients come from the oracle (`cargo xtask tables`, `crates/mathtools/src/tables.rs`, 400-bit evaluation; `--check` in the gate); no Remez fit was needed at this precision. Arguments where the second-order term is far below the double-double error (below 2^-30) or the function has saturated are rounded by the side of the deviation (`elem::near`). The `double` fast paths' result assembly (MATH-M6-F64-GAP-ASSEMBLY, register 13.5 #1 and #6) uses Fast2Sum where the magnitudes are ordered: `exp_kernel` forms `t + t·p` from one exact product and two Fast2Sums; the logarithms add `e·ln2` (a 42-bit `LN2H`, so `e·LN2H` is exact for `|e| < 2^11`, plus `e·LN2L`), `−ln c` and `log1p r` by Fast2Sum/2Sum and one low-part sum (`fast64::log_assemble`, below `2^-95·|e| + 2^-103` beside the series tail); `log_pow` takes `rh³/3` from the exact `rh²·rh` times the `double` 1/3 with one correction (`< 2^-115·|rh|`) and charges `2^-94·|e| + 2^-100` for the assembly. The bounds are restated term by term in `fast64.rs` and checked against the multi-precision oracle by its `bounds` unit tests. Measured (MATH-M6-F64-GAP-ASSEMBLY-2, on an AVX2-capable x86-64 build host, instructions:u per call, default and without AVX2 alike): exp and exp2 -24, log, log2 and log10 -60, pow -122; no row slower. The fast paths' argument reduction (MATH-M6-F64-GAP-EXP-REDUCE, register 13.5 #2): `exp` and `pow` subtract `k·ln2/64` with a three-part Cody–Waite constant of 36-, 35- and 34-bit parts (`fast64::reduce_ln2`; every `k·Ci` exact for `|k| < 2^17`), `x − k·C0` exact by Sterbenz, one Fast2Sum for `−k·C1`, the low part from `k·C2`, a renormalizing Fast2Sum, and no trailing `x.lo` add for `exp` (`pow` adds its `z.lo` there); both Fast2Sums are exact by the exponent condition, so tiny `r` next to multiples of ln2/64 is covered. `exp2` forms `r·ln2` by Dekker with `ln2` pre-split (`LN2A`/`LN2B`, `fast64::ln2_times`). Bounds, restated term by term in `fast64.rs`: `exp` r within 2^-106.5, `pow` within 2^-96.9, `exp2` within 2^-104·|r|, all inside the kernel's 2^-90; checked against the oracle by `fast64::bounds::exp_reduction_stays_within_its_bound` and `exp2_product_stays_within_its_bound`, each bound planted one bit loose and caught. `exp10` and the accurate path keep `exp_log::reduce`. `log2`/`log10` (MATH-M6-F64-GAP-LOG-TABLES, register 13.5 #7) assemble from `LOG2_L`/`LOG10_L` (-log_b c_i, double-double within 2^-104, generated by `cargo xtask tables`) and `LOG10_2_E` (log10 2 as 42 bits plus the rest, within 2^-97): `e·log_b 2 + (-log_b c)` exact by Fast2Sum, only `log1p r` scaled by one exact product `lh·(1/ln b)` instead of a final `Dd::mul`; bound `2^-49·|T|·scale + 2^-70·|y|` (`scale` the least double >= 1/ln b), restated term by term at `fast64::logb_assemble`; the near test keeps `RHO_LOG = 2^-69` where `|y.hi|` >= the least double >= 0.34·scale. Checked by `fast64::bounds::log_tables_cover_their_bounds` and the kernel oracle test; each constant and a table entry planted one ulp off and caught. |
| D-10.14 | §10.0, §10.3 | — | **Flags and `errno` of the elementary functions.** Inexact is raised exactly when the result is inexact, underflow when the rounded result is tiny and inexact (after rounding, x86), overflow as IEEE 754 defines it. glibc omits inexact for tiny arguments of `sin`, `tan`, `asin`, `atan`, `cos`, `acos`, `cosh`, `atan2` and raises it for some exact results (`cbrt(27)`, `log2(2^k)`, `pow(3, 4)`); C leaves both unspecified (F.10), so Liella follows IEEE 754 (decided, reported). Invalid, division by zero, NaN signs (positive domain NaN for `asin`, `acos`, `log10`) and NaN payload choice (`atan2`: `x`'s) follow glibc (D-10.10). `errno` follows §10.0 (`ERANGE` only for ±∞/±0 results); glibc also sets it for some subnormal and largest-finite results of `exp`, `exp2`, `exp10`, `pow` and not for others (three-way: the spec and C's implementation-defined rule against an inconsistent probe: the spec is kept and the difference recorded). |
| D-10.15 | §10.3 | — | **Special functions of `float` and `double`** (milestone 3). Evaluated in a 384-bit binary floating point of the library's own (`math::mp`: truncating add, multiply, division by small integers, Newton reciprocal and square root, `exp`, `ln`, `sin`/`cos` with Payne–Hanek reduction) and rounded once, so every result is correctly rounded in every mode: the series of `erf`, the `1 − erf` and continued-fraction forms of `erfc`, Stirling's series with argument shifting and reflection for `lgamma`/`tgamma` (exact factorials at small integers), and for the Bessel functions the power series below 100 (at most about 150 of the 384 bits cancel), Hankel's expansion above for orders up to √x, forward recurrence for `Y_n` and for `J_n` with `n < x`, Miller's normalised backward recurrence for `J_n` with `n ≥ x` (recurrences beyond 5000 steps in double-double). Constants (π, ln 2, γ by Brent–McMillan, ½ln 2π, 2/√π, 1/√π, 2/π, 130 Stirling coefficients from exact Bernoulli numbers) from `cargo xtask tables`. The oracle uses independent methods where it can (Spouge's formula for `lgamma`, the continued fraction with bracketing convergents for `erfc`). Tiny arguments whose deviation from a representable value lies beyond 384 bits (`erfc(tiny)`, `j0(tiny)`, `j1(tiny)`, `tgamma(±2^-k)`) are rounded by the side of that deviation. |
