#### §8: Numeric conversion and integer arithmetic

| ID | Spec | Ann. | Decision |
|---|---|---|---|
| D-8.1 | §8.1–8.3 | HIST, PATH | **Internal:** `parse_int::<T>(text, radix, dialect) -> Parsed<T>`, one of `Value{v, used}`, `NoDigits`, or `OutOfRange{clamped, used}`. **Boundary:** `endptr` and `ERANGE` come from `ret`. The `__isoc23_*` names select `dialect = C23`. |
| D-8.2 | §8.1 | HIST, ARB | Unsigned parsing of a leading `-` returns `Negated`. The wrap-around required by the contract is applied by `legacy::num_compat`. |
| D-8.3 | §8.2 | HIST | The radix character is an explicit parameter. `strtod` passes the current locale's, and `strtod_l` its argument's. The internal default is the C radix. Phase 7: the radix is the `LC_NUMERIC` decimal-point string, which can be several bytes (`ps_AF`'s `٫`), and for the wide functions the wide decimal point (`_NL_NUMERIC_DECIMAL_POINT_WC`). Parsing takes no grouping: the spec ties thousands grouping to printf's `'` flag (phase 8). |
| D-8.4 | §8.5 | HIST | `num::format_int` fills the gap the spec notes (no integer-to-text primitive). printf, syslog and diagnostics use it with no locale machinery. |
| D-8.5 | §8.2, §8.4 | HIST, PATH | One exact float engine (IP-18) serves `strtod`, `strfrom*`, printf, scanf and `ecvt`/`fcvt`/`gcvt`. The `ecvt`-family static buffers are per-thread slots. |
| D-8.6 | §8.6 | ARB | `abs(INT_MIN)` returns `INT_MIN` (defined wrap), and `div` by zero or `INT_MIN / -1` aborts with a diagnostic (S4; observable, defined instead of UB). Internally, `unsigned_abs` and checked `div` return `Result`. |
| D-8.7 | §8.7, §8.9 | HIST | `<stdbit.h>` is one generic implementation over five widths (70 exports). `ffs*` equals `stdc_first_trailing_one` on the unsigned reinterpretation. |
| D-8.8 | §8.10 | HIST | `l64a` uses a per-thread buffer: delivered in milestone 6 through the result area of D-C0.2 (it was process-wide until then). |
| D-8.9 | §8.4 | ARB (spec silent) | `%a` output follows the reference library (revised in phase 8, measured by `printf_products.rs`): a `float`/`double`/`_Float128` has a leading `1` (`0` for subnormals), and a rounding carry makes it `2` (`0x2p+0`), not renormalised; an x87 `long double` prints its 64-bit significand nibble by nibble, so the leading digit is its top nibble (`1.0L` is `0x8p-3`), and a carry out of `f` gives `0x1` with the exponent 4 higher. A NaN with its sign bit set prints as `-nan`. Underflow (`ERANGE`) means a tiny *and* inexact result. |
| D-8.10 | §8.4 | ARB (spec silent) | `ecvt`/`fcvt` details: fewer than one requested digit gives one for `ecvt`; zero gives `max(n, 1)` zero digits with `decpt = 1`; a value `fcvt` rounds to zero counts as zero; infinities and NaNs give `"inf"`/`"nan"` with `decpt = 0`; digits beyond the destination are dropped. The conversions honour the current rounding mode. **`ndigit` is reduced** to 17 for `double` and 21 for the `long double` forms (`ecvt`, `fcvt`, the `_r` and `q` forms; spec §8.4 corrected 2026-10-04 from ecvt(3) and a probe; for `fcvt` the places after the point), the digits staying exact where glibc's last is not always rounded; `gcvt` keeps `%.*g`'s any precision where glibc caps it at 17 (both recorded differences). |
| D-8.11 | §8.4, §12.6 | ARB | **Number-text conversion core** (COLD-REWRITE-W-far-05 and -2, 2026-10-14; record `liella-historic:handoff/decisions/COLD-REWRITE-W-far-05.md`; D-8.4, D-8.5, D-8.9). (1) Big numbers: u64 limbs with u128 products in a fixed array (`LIMBS` = 1024, 65,536 bits) plus a used length, so work follows the value's size; overflow saturates and sets a flag; no allocator (no ENOMEM for printf or strtod); long division by shift-and-subtract on parse's slow path only. (2) Digit generation splits the value at the binary point: the integer part by repeated division by 10^9 (two 64-bit divisions by a constant per limb), the fraction top down by multiplying by 10^9; both exact, no power-of-five tables, no floating point. (3) One rounding predicate serves binary, decimal and hex rounding in all four C modes; tininess is judged after rounding with an unbounded exponent (probed: `strtod("0x1.fffffffffffff8p-1023")` gives `DBL_MIN` without ERANGE); overflow is IEEE's (probed under `fesetround`); `%g` follows C's rule; `%a` as D-8.9, and a `float` prints as the `double` it converts to. Open since the record: with `#` and a rounding carry glibc prints `1.e+02` for `%#.2g` of 99.5 where C gives `1.0e+02`; Liella keeps C (owner ruling 2026-10-22, #573: correctness is a gain, though the owner called it borderline); recorded in `docs/differences-from-glibc.md` with the compat-flag placeholder COMPAT-8, pinned by `s8_4_c_3_hash_g_carry_keeps_c_digits`. (4) Run 2: `float::round` is one rounding step at a computed LSB exponent shared by normal and subnormal results; `q = 0` with sticky is a certain underflow; x87 invalid encodings read as documented; `%a` formats from the canonical encoding; digit rounding reads the discarded part as its first digit plus anything non-zero after. |
