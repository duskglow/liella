#### §17: Users, groups and credentials

| ID | Spec | Ann. | Decision |
|---|---|---|---|
| D-17.1 | §17.2 | KERN, HIST | Process-wide changes broadcast over the one internal signal (D-20.1). A partial failure aborts, per the contract. The per-thread forms are available internally. |
| D-17.2 | §17.2 | HIST | **Internal:** `setfsuid` returns `Result<Previous>`. **Boundary:** the contract's "previous value, no error" is kept. |
| D-17.3 | §17.3–17.4 | HIST, PATH | **Internal:** `liella::users` reads records as borrowed views over the line (`Passwd`, `Group`, `Shadow`, `Gshadow`, `List`) and writes lines (`put_*`). **Boundary:** the `_r` forms use `liella_abi::pack::Packer`: the buffer holds only the record's strings and pointer arrays (aligned inside it); on `ERANGE` an enumeration or stream stays on the refused record (the stream is sought back). Non-`_r` results go in a per-thread block per record kind (`SLOT_RECORDS` result slots), grown as needed and freed at thread exit; `getusershell` and `getpass` are process-wide. The `*ent` cursors are process-wide and locked (P-scope): an open file and an offset. At the end of a stream, `_r` forms return `ENOENT`, the others NULL with errno `ENOENT`; a record not found is NULL with errno unchanged, or 0 with a NULL result. Deliberate differences (phase-10 probes): numbers are decimal digits only (glibc also takes `+5`, ` 5`); empty names are refused; `sgetspent`/`sgetsgent` skip leading white space and treat comment or blank lines as no record (`EINVAL`), like the stream forms; `put*` refusals always set `EINVAL`, and a newline in a field is refused (glibc writes a space); `putpwent`/`putgrent` keep non-zero IDs on `+`/`-` entries so the round trip is lossless; `getgrouplist`/`initgroups` skip `+`/`-` entries (glibc's `+group` added GID 0) and list each GID once; at the end of an enumeration the `_r` forms return `ENOENT` and every form leaves errno unchanged, as glibc (owner ruling 2026-10-22, #409: the `errno = 0; loop; check errno` idiom). `fgetpwent_r` needs room only for the record's strings, not the whole line (KNOWN in `users_products`). |
| D-17.4 | §17.4 | HIST, ARB | `lckpwdf` creates or opens `/etc/.pwd.lock` (0600) and takes an OFD write lock, retrying with pauses of 1 ms doubling to 100 ms for 15 s in all, then `EAGAIN`; no `SIGALRM` (observable: no signal handler is installed). A second `lckpwdf` while this process holds the lock returns -1 without setting errno (observed); `ulckpwdf` returns -1 when the lock is not held. |
| D-17.5 | §17.6 | HIST, ARB | utmp records keep the ABI layout with the 32-bit `ut_tv` (the file format is shared; Y2038 is F38, a documented limitation, owner 2026-10-04); `liella::users::Utmp` keeps 64-bit seconds. **Unsigned seconds (owner ruling 2026-10-22, #415, option A; a deliberate difference, UTMP-Y2038-UNSIGNED):** the 32-bit `ut_tv.tv_sec` (and `ut_time`, which aliases it) is read and written as UNSIGNED seconds, so login times are correct until 2106-02-07 06:28:15 UTC (`users::ut_tv`, `users::ut_sec`, `users::UT_SEC_MAX`); the file layout and every byte of a time before 2038-01-19 03:14:07 UTC are exactly glibc's (proved by `users_products`: the same records, 0 to 2^32-1, written through utmp, utmpx, wtmp and wtmpx by glibc and by Liella compare equal byte for byte). Gain: correct login times for 68 more years. A time outside `[0, 2^32)` is written, and handed to C, as no time, `(0, 0)`, never wrapped; the times the library stamps itself (`logwtmp`, `logout`; `login` keeps the caller's) are `(0, 0)` after 2106-02-07 06:28:15 UTC or before 1970 (`accounting::stamp`). The C ABI type is unchanged (glibc's signed 32-bit member; sizes and offsets checked by `appendix_c_layouts` and `s17_6_c_3`): a C caller's 32 bits pass through unchanged both ways, and C callers must read the member as `uint32_t` after 2038 (Liella ships no headers, so there is no helper macro; the cast is the documented way, `docs/differences-from-glibc.md`). Readers on the host (black-box, records written by Liella): coreutils 9.4 `who`, util-linux 2.39.3 `last` and `utmpdump` read the member as signed and print 1901-12-13 to 1969-12-31 for a post-2038 time (none shows the correct date; before this change they printed 1970-01-01 for the `(0, 0)` record, equally wrong but with the time lost); `w` reads only the system utmp and `lastlog` only `/var/log/lastlog`, which Liella never writes (glibc has no lastlog interface; `struct lastlog`'s 32-bit `ll_time` is layout only), so neither was checked. Compat flag placeholder COMPAT-9 (`docs/compat-flags.md`) would restore `(0, 0)` after 2038; default-path cost: none (the range check is the same one compare with another bound). utmp and utmpx share one layout and one set of translations. The cursor (`accounting::UtmpDb`, process-wide, locked) opens the file read-write, else read-only, in which case `pututline` fails with the refusal's error (`EACCES`; glibc returns NULL without errno). Searches go forward from the position; `pututline` replaces the record `getutid` finds or appends. Missing files are never created (observed). Locks are OFD locks with a timed 10 s retry, then `EAGAIN`; no `SIGALRM`; they do not exclude programs that take classic locks on the same files. `updwtmp` appends and truncates back a partial write. `login`, `logout` and `logwtmp` use their own descriptors, not the cursor; `login` without a terminal writes `???` to wtmp only, as login(3) documents (glibc also writes an empty-line utmp record). `utmpname` with a name of `PATH_MAX` or longer gives `ENAMETOOLONG`. The 2.2.5 compat aliases of `login`/`logout`/`logwtmp` wait for phase 15. |
| D-17.6 | §17.1 | HIST | Supplementary-group membership (`group_member`, the `faccessat` emulation) allocates nothing: up to 64 groups in a stack buffer, a longer list scanned from `/proc/self/status` in fixed chunks. Found by the phase-5 AS-safety harness's review: `faccessat` is async-signal-safe. |
| D-17.7 | §17.2 | KERN | **The setxid broadcast** (D-17.1, D-20.1; phase 6). The caller takes the thread-list lock, performs the system call itself, and on success sends the internal signal (`tgkill`) to every other thread Liella runs, with the request (call number and arguments) in a process-wide request record and the operation bit in each thread's request word. Each handler performs the same raw system call on its own thread and reports its result through a counter the caller waits on (futex). Any thread failing where the caller succeeded aborts the process (the contract). Threads Liella did not create (D-22.10) cannot be reached; in a process Liella started there are none. |
| D-17.8 | §17.5, §17.5a | HIST, ARB | `getlogin`: the audit login UID through the user database, otherwise the utmp `LOGIN`/`USER` record for the session's terminal, which is the first of fds 0, 1 and 2 that is a terminal (glibc uses stdin only, which its man page calls a bug); `ENXIO` with no terminal, per the spec (glibc: `ENOTTY`); `ENOENT` with no record. `ttyslot`: `/etc/ttys` entries counted from 1, matched on the path below `/dev` (glibc compares the last component only); 0 when not found (the spec does not define the terminal table; approved by the owner 2026-10-03). `getpass`: `/dev/tty`, else stdin with the prompt on stderr; echo off (TCSAFLUSH) and restored; a newline after the line when echo was off; a **bound, never a truncation** (owner 2026-10-04, replacing the "no length limit" of 2026-10-03): at most 1 MiB of input before the newline by default (chosen by the coordinator: absurdly large for a pass phrase, but finite, so a runaway input cannot exhaust memory), changed per process by the native `liella_getpass_set_limit(bytes)` (LIELLA_NATIVE_1; the previous bound is returned; 0 restores the default; above `PTRDIFF_MAX` `EINVAL`; inherited by `fork` children, reset by exec). A longer line is read to its newline (or the end) and discarded, and `getpass` returns NULL with `EOVERFLOW` (POSIX's error for a `getline`/`getdelim` line beyond its bound; getpass(3) lists only `ENXIO`; a truncated pass phrase would be a wrong answer). Every buffer of the library's that held the line (the line buffer, before each growth and when dropped; the terminal read chunk; the previous result block when replaced; the result block before each new line) is zeroed with D-X.11's `secure_zero`; a stream's own buffer (standard input's, when there is no terminal) belongs to the stream and is not touched. The spec's HIST note "the length is limited" was corrected under the three-way rule (glibc probe: a 3 MiB line returned whole; getpass(3) NOTES: "There is no limit on the length of the password"). `setlogin`: `ENOSYS`. Shells: a line must start with `/` after white space and ends at white space or `#`; a missing `/etc/shells` lists `/bin/sh` and `/bin/csh`, an empty one nothing (observed). |
