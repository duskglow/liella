# x86_64 seams in the Rust code (ARCH-SEAMS, story A-0)

Every place in `crates/` where the Rust code depends on x86_64, and what replaces it on aarch64 (OD-10) in which
story of plan/06-phases/20-post-release-ledger-and-experiments.md. Written from `cargo xtask arch-audit --list`
at the ARCH-SEAMS head (base origin/next `6abb25d6`).

## The check

`cargo xtask arch-audit` (also a clause of `cargo xtask static`) scans every `.rs` file under `crates/`, with
comments and string literals stripped, for these tokens:

| Category | Tokens | Seams |
|---|---|---|
| cfg | `target_arch` | 9 |
| intrinsics | `arch::x86_64`, `arch::x86::` | 3 |
| asm | `asm!`, `global_asm!`, `naked_asm!` | 1 |
| machine-decl | `fn liella_machine_` (the extern declarations of `csys/src/machine/*.S`) | 89 |
| fpu | `mxcsr`/`MXCSR`/`Mxcsr`, `x87`/`X87` (not in a `0x87` literal), `fnstcw`, `fldcw`, `fnstsw` | 242 |
| thread-pointer | `arch_prctl`, `ARCH_SET_FS`/`GS`, `ARCH_GET_FS`/`GS`, `ArchGet` | 43 |
| reloc | `R_X86_64` | 2 |

Each seam must sit in an allowed module for its category (the `ALLOWED` table in `xtask/src/arch.rs`: a path, the
categories allowed there, the reason and the replacing story) or carry an `// ARCH(x86_64): <why>` comment on its
line or on one of the three lines above it. Anything else fails the check. `--list` prints every seam as
`category <tab> file:line <tab> module/tag <tab> source`.

Limits (labelled, not covered per site): a token check is a tripwire, not a proof. Code that depends on x86_64
without naming one of the tokens is listed by kind below, not per site: struct layouts from `crates/abi`, syscall
numbers from `csys/syscalls.tsv`, `long double` handled as raw 80-bit words, and callers of `liella_machine_*`
(only the declarations are seams). `xtask/`, `tools/` and `csys/` (C and assembly) are not scanned.

## Which crates build without csys

Only `boundary` has a build script, and it compiles `csys/` (C and the x86_64 assembly). The crates that do not
depend on `boundary` (normal dependencies, from their `Cargo.toml`) therefore build without csys: `kernel`, `mem`,
`rt`, `abi`, `math`, `legacy`, `core`, `ld`, `native`, `thread-db`, `mathtools`, `spectest`. `libc-so` and `libm-so`
link `boundary`. Of those, `rt` (fpu.rs), `kernel` (machine.rs, uapi.rs), `math` (x87 format, by type) and `abi`
(x86_64 layouts) carry seams above; whether each passes `cargo check --target aarch64-unknown-linux-gnu` is A-2's
job (not tried here: no aarch64 target installed, RL-1).

## String and memory kernels without a portable Rust path

The machine kernels are all x86_64 assembly: `scan.S` (49 labels) and `fold.S` (13) plus the copy/fill entry points.
By name, a portable Rust implementation exists for the memory family only: `liella-mem` holds plain loops behind
`memcpy`, `memmove`, `memset`, `memcmp` and `bcmp` (D-4.11). `hot.rs` serves the 1-64 byte classes of the fold
kernels in Rust (with AVX2 intrinsics, see above). No portable Rust function was found for `strlen`, `strnlen`,
`strcpy`, `strncpy`, `stpcpy`, `stpncpy` (and their `_chk` forms), `rawmemchr`, `memchr`, `memrchr`, `strchr`,
`strchrnul`, `strcmp`, `strncmp`, `strdiff`, the case-insensitive compares (`casecmp_ord_*`), `pairscan`,
`pairscan_ci`, `strpair`, `wcspair` or `env_slot` (`env_find` has a Rust search in `legacy/src/search_c.rs`).
This is a name-level search (`fn <name>` in `mem`, `core`, `rt`, `legacy`), not a per-kernel review; A-8
confirms each before writing the portable path.

Other machine entry points that need an aarch64 version (A-6): `tp`, `cpuid`/`xgetbv0` (HWCAP from auxv instead,
RL-1), `rdpkru`/`wrpkru` (POE, or none), `barrier`, `once`, `guard`, `call*`/`vcall*`, the vDSO calls, `clone_*`,
`syscall_cancel*`, the cancellable I/O wrappers, `setjmp`/`longjmp`, the context functions and the signal
`restorer`.
