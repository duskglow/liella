## The change

Decision row: D-NEW "Two-phase `double` elementary functions" (plan/07-decisions/s10-mathematics.md; the coordinator
assigns the id). Design and measurements: handoff/libm-rethink/DESIGN.md §3.2 A, §4, §4.1, §5. Add the quick phase of
`exp` as a new kernel in `crates/math` in a NEW file (for example `src/fast64/quick.rs`; never grow fast64.rs, 72 KB:
read it by `grep -n` and ranges only), with its proof and tests. Do not wire it into the C entry
(LIBM-F64-EXP-QUICK-WIRE does that). The prototype (`handoff/libm-rethink/proto/proto_exp.c`, and `PROTO_BODY_E` in
`proto_time.c`) is the measured experiment to follow; it is C at -O2, not product code.

Method (cite the sources in the D-row: Tang 1989, Cody & Waite 1980, Estrin 1960, Ziv 1991, de Dinechin, Lauter &
Muller 2007, Muller et al. 2018):
- t = x·128/ln2 + 1.5·2^52 (one FMA in the FMA build), kd = t − 1.5·2^52, k from t's bits (no conversion
  instruction); r = (x − kd·L1) − kd·L2 with L1 of 36 bits (k·L1 exact for |k| < 2^17, the subtraction exact by
  Sterbenz), the low part rl kept.
- T_j = 2^(j/128) as (h, l) within 2^-105: a 128-entry table (2 KiB) generated by `cargo xtask tables` from the
  oracle (P4), never typed in.
- e^r − 1 − r by the degree-6 Taylor polynomial (or a minimax degree 5 if its bound is proven), evaluated by
  Estrin's scheme (prototype LE/E: about −20% latency against Horner at equal instructions).
- y = T·(1 + r + q) assembled with Fast2Sum; SSE2 build: plain T·rh (bound 2^-61.50); FMA build: the exact low part
  of T·rh by one FMA (bound 2^-67.4).
- Rounding: `fast64::near` with c from the bound (c·(1 − 2^54·ρ) > 1 + u), result zh·2^m computed BESIDE the test
  (the test passes only when the rounding of zh + zl is zh); a miss returns `None` and the caller runs today's
  `exp_near` (tier 2, unchanged, then the accurate path).
- Domain: today's `exp_near` domain (2^-60 <= |x| < 708); outside it `None`.
- Builds: SSE2 and FMA kernels through the existing `kernels!`/`fused` pattern (D-10.25, D-10.50). Their bounds
  differ, so their fallback sets differ, but every returned value is correctly rounded: the results are bit-identical.

Design targets (state them in the doc comment and the hand-back): instructions per call (FMA <= 80, SSE2 <= 95 with
the fallback included), FP operations per call, and the critical path's length in dependent FP operations.

Proof: the error bound step by step in the doc comment (the prototype's terms: rounding of T·rh 2^-61.524 (SSE2
only), low sum 2^-68.2, polynomial evaluation 2^-69.4 (redo for Estrin's order of operations), neglected rl·rh
2^-70.5, truncation 2^-72, reduction 2^-76.5), and a bounds test like those in `fast64/tier_tests.rs` that recomputes
the bound from the constants.

## Tests (name the clause: §10.2 exp, D-10.3; plants for each)

- The existing exp accuracy tests and hard cases (the 432 operands e^(k·2^-53) next to midpoints in fast64's tests).
- Seeded random comparison with the correctly rounded path, >= 10^7 operands per build in the test tier, and a
  jobrun accuracy job at 10^8 per distribution (uniform [-10, 10], uniform bit patterns over the domain, uniform
  [-745.2, 709.8]) as `handoff/libm-rethink/proto/accuracy.c` did: 0 mismatches.
- Both builds return the same values; fallback rates within the model (SSE2 0.4-0.8%, FMA under 0.05% on the cbench
  operands); the measured maximal relative error of the quick result below the stated bound.

## Plants (`cargo xtask plants` only, `msg:` per plant)

A coefficient off by one ulp; the bound ρ (or c) too small (2^-64 for the SSE2 build: the hard cases must catch it);
an Estrin term on the wrong power; the table index off by one; rl dropped; the k-from-bits offset wrong.
