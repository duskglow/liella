**What the plan says** (plan/utilities.md, read it whole: §2 surface, §3 architectures, §4 per domain and order, §5
proofs, §6 stories, §7 questions).
* Recommended architecture (d): one Rust library per domain holding both sides of each file format (writer beside
  the existing reader: `liella-ld::cache`, `liella-core::time::tzif`, `liella-core::locale`, `liella-core::charmap`),
  one executable per domain chosen by `argv[0]` (`liella-tz`, `liella-locale`), ldconfig a freestanding static binary.
* Public: commands and file formats only; a Rust `tz` API in `liella-native` after zic/zdump are proven (owner's yes);
  no new C ABI.
* Order: UTIL-0 spec part, UTIL-1 transcript harness, UTIL-2/3 cache writer and ldconfig, then ldd/getent/getconf,
  iconv/locale, tz tools, localedef + `locales` commands, gencat/pldd, public `tz` API.
