| D-16.1 | §16.1 | HIST | **Internal:** `liella::names::nss` holds the typed configuration (`Database`, `Service`, `Spec`, `Config`) and the engine (`run`, `gather`). **Sources:** `files` is built in; `dns` is built in from phase 10 part 4; `compat` is `files` for passwd/group/shadow. | D-16.3 | §16.4 | ARB, HIST | **Internal:** the resolver configuration is unbounded (P-lift; `liella::names::dns::conf`). **Boundary:** the exported `_res` (568 bytes) shows the first 3 servers and 6 search domains, IPv6 servers in `_u._ext.nsaddrs`; while the state still holds exactly the file's first 3 servers or 6 domains, the file's further entries are used too. `_res` is per thread: the initial thread uses the `_res` object, other threads a state in thread-block word 0x130, freed at thread exit; a mark and generation (offsets 560, 564) re-read the thread state when `resolv.conf` changes unless `RES_NORELOAD`; caller-created states are never reloaded; a missing file means the defaults (options 0x2c1, server 127.0.0.1, domain from the host name). **Parsing (observed):** limits ndots 15, timeout 30 (0 allowed), attempts 5; `inet6` and `debug` ignored; `options` lines add up; the last `domain`/`search` wins; invalid `nameserver` skipped, `%zone` accepted; `sortlist` (at most 10, natural masks) applies to `gethostbyname` and `getaddrinfo`; `LOCALDOMAIN`, `RES_OPTIONS`, `HOSTALIASES` (dot-less names, not with `RES_NOALIASES`). **Transport (observed):** servers in order, an unreachable one skipped at once; the timeout per server without doubling, `attempts` rounds; SERVFAIL/REFUSED/NOTIMP/FORMERR move to the next server; `rotate` is a process-wide round-robin; EDNS payload 1200, DO with `RES_USE_DNSSEC`; AD set in queries and kept from responses only with `trust-ad`; A and AAAA in parallel on one socket (A first, a lost query resent alone) unless `single-request(-reopen)`; ID and question checked; TCP on TC or `use-vc`. **Failure:** `h_errno`/`res_h_errno` report failures only, a success leaves them unchanged; NXDOMAIN → HOST_NOT_FOUND, NOERROR without answers → NO_DATA, SERVFAIL/REFUSED/no response → TRY_AGAIN, FORMERR/NOTIMP/other → NO_RECOVERY; the same over UDP and TCP (a response to another question is no response, per §16.4 Guarantees). **Query IDs (owner, 2026-10-03, permanent):** each query's 16-bit ID comes from its own `getrandom` call. The ID and the source port are the only defence of a stub resolver without DNSSEC against off-path spoofing (RFC 5452): an attacker who can predict the next ID needs far fewer forged answers to poison a lookup. A generator seeded once would be faster (`res_mkquery` is 1.24× glibc) but makes every ID depend on one seed and on generator state that survives `fork` into children, which can then repeat each other's IDs; a system call per query costs well under a microsecond against a network round trip, so security wins. **Deliberate differences** (KNOWN in `dns_products`): `res_search` after a success leaves `h_errno` alone (glibc: 1); REFUSED and wrong-question answers over TCP as over UDP; `LOCALDOMAIN` with leading white space or empty gives no empty domain (resolv.conf(5)); LOC text uses the RFC 1876 ranges (glibc wraps). **Secure-execution mode (owner ruling 2026-10-03):** `HOSTALIASES`, `RES_OPTIONS` and `LOCALDOMAIN` are read through `secure_getenv`, so a set-user-ID or set-group-ID program ignores them (ld.so(8); the reference agrees, and also removes them from the environment, a question left to the loader's threat model); the cache keys hosts by the resulting configuration (`tests/secure_env.rs`). |

| D-16.10 | §16, §17 | ARB | **The integrated name-service cache** (owner requirement 2026-10-03, rulings on the design 2026-10-03, which supersede the requirement's inotify wording; replaces nscd, D-16.5). **Purpose:** speed only, never opacity: a cached answer is one the NSS engine gave for the same files, at most about one second before their last check (see Change detection), and one within the record's TTL for DNS data; disabling the cache, or `liella_nscache_invalidate`, makes the next lookup see every change. **What a key covers** (owner, 2026-10-03): the cache holds the sources' answers, keyed by category, query kind, the query exactly as given to the sources (a host name after IDNA conversion, an address with its family, a service with its protocol, a UID or name) and the lookup-steering environment (`LOCALDOMAIN`, `RES_OPTIONS`, `HOSTALIASES` values). Everything that depends on per-process state runs on every lookup after the cache, never inside it: IDNA conversion through the locale's character set, `AI_ADDRCONFIG` and RFC 6724 sorting (they depend on the interfaces and routes, which change without a file changing), `sortlist`, the `getaddrinfo` flags and the result packing. Per-process state that cannot be keyed bypasses the shared region: `__nss_configure_lookup` overrides and a program-modified `_res` bypass the cache entirely, and lookups through fixture paths are never cached. **What is cached:** answers of the built-in sources only (`files`, `dns`) for hosts (by name and by address, getaddrinfo's per-family lookups), passwd, group (including group lists for `initgroups`/`getgrouplist`), services, protocols and networks, including negative answers. Never cached: shadow and gshadow (password hashes must not persist in a tmpfs file), enumerations (`*ent`), anything answered while `__nss_configure_lookup` overrides are set, DNS answers when the program has changed `_res`, and lookups through fixture paths that the tests pass. **Validity:** an entry records the identity of every file its answer depended on (`nsswitch.conf`, `host.conf`, `resolv.conf`, the database files) and the environment that steers lookups (`LOCALDOMAIN`, `RES_OPTIONS`, `HOSTALIASES`). **Change detection (owner ruling 5): by `stat`, not inotify.** A file's identity is its inode, size, modification time and change time (an editor that replaces a file by rename changes the inode even when the modification time collides); a file appearing or disappearing is a change. **The first lookup in each process always validates** (it `stat`s the watched files before serving anything, so a process started after an edit sees it at once); later checks are rate-limited to about one per second per process, timed with the vDSO clock, and within that window cached answers are served without a system call (owner, 2026-10-03). **Watched set:** `nsswitch.conf`, `host.conf`, `resolv.conf` and `gai.conf`, whose change invalidates every category; and each category's database files (`hosts`, `passwd`, `group`, `services`, `protocols`, `networks`, and the file `HOSTALIASES` names), whose change invalidates that category. The process that detects a change increments the shared generation counter; other processes of that user see the counter move and discard their entries without `stat` calls of their own. `liella_nscache_invalidate` bypasses the rate limit. With the cache disabled the NSS engine behaves as before (D-16.1: configuration checked on every lookup). DNS entries expire at the smallest TTL of the answer (capped at one hour; TTL 0 is never cached); negative DNS answers per RFC 2308 (the SOA minimum, capped at 5 minutes). **Layers:** a per-process table, filled on the first lookup; and a shared region per effective user ID, `/dev/shm/liella-nscache-<euid>`, consistent with the locale and time-zone model (mapped, read-mostly). **Shared region security (owner amendments):** created with `O_RDWR\|O_CREAT\|O_EXCL\|O_NOFOLLOW\|O_CLOEXEC`, mode 0600, or opened with `O_NOFOLLOW`; then `fstat`: a regular file, owned by the effective user ID as the kernel reports it (correct in user namespaces and containers that share `/dev/shm`), mode exactly 0600, size within the cap; any mismatch means a private (per-process) cache and the file is never trusted or modified. The private cache is also used when `AT_SECURE` is set (setuid, setgid, file capabilities) or the real and effective user or group IDs differ. Any credential change at run time (the setxid family, `setgroups`, D-17.7) drops the mapping and re-keys before the next lookup. The region is untrusted input even within one user: a header with magic, layout version, the owner's UID, the boot ID and a validity stamp of the account (its user-database name and UID, so a reused UID does not inherit a stale cache), a generation counter, then a bounded hash table and entry arena; readers use a seqlock and verify each entry's checksum and every offset and length before use, and fall back to a real lookup on any inconsistency (a corrupt region is reinitialised by the next writer). Writers serialise with an OFD lock on the region file (released by the kernel if a writer dies). Size cap 8 MiB by default (tmpfs counts against memory); full regions evict the oldest entries. **Edge cases:** containers that share one `/dev/shm` mount but map UIDs differently see the same file name for different users; the ownership check compares the kernel's UID of the file with the kernel's effective UID of the process, so a file created through another mapping does not match and the process uses its private cache. In a user namespace the region name uses the process's own view of its UID while the check uses the kernel's, so two namespaces mapping the same kernel UID share safely and different kernel UIDs never do. A UID reused after an account is deleted finds the old file owned by it, and the validity stamp (account name and UID at creation, boot ID) makes it start afresh. **Shared invalidation:** the region's generation counter; an explicit invalidation by any process of that user increments it, and every process of that user discards entries of earlier generations. **Native API** (`LIELLA_NATIVE_1`, wrapped by `liella-native`): enable/disable process-wide (disabled: no mapping, no `stat`, no table: one relaxed atomic load per lookup); per-category enable/disable (hosts, passwd, group, services, protocols, networks); full and per-category invalidation (also of the shared region); a status query. The environment variable `LIELLA_NSCACHE=0` disables it at start (ignored under `AT_SECURE`). **Tests:** every differential test of phases 10–11 passes with the cache enabled and disabled; a process started after an edit to a watched file sees the edit on its first lookup, even when another process of the same user cached the old answer less than a second earlier; a change to each of `nsswitch.conf`, `host.conf`, `resolv.conf` and `gai.conf` invalidates every category; each key component (the query, the environment values) and each per-process step (locale and IDNA, `AI_ADDRCONFIG`, sorting, overrides, `_res` changes) is shown not to leak between processes or lookups; cached and uncached answers compared for each category; squatting (a file owned by another user, wrong mode, a symlink, a FIFO), corruption (random bytes, truncation, bad offsets), credential change and size cap all fall back without a wrong answer. **As implemented (phase 12):** (1) one table per process: the shared region when it is trusted, else a private table of the same format; (2) `nsswitch.conf`, `host.conf` and `gai.conf` are not checked per lookup inside the window, while `resolv.conf` keeps its per-lookup check for the `_res` reload (D-16.3); (3) host keys carry a fingerprint of the resolver's effective configuration and the `HOSTALIASES` text (where `LOCALDOMAIN` and `RES_OPTIONS` take effect), which also detects a program-modified `_res`; (4) the global files are checked on each due lookup, a category's files only when it is looked up; (5) the status generation is the sum of all generations; (6) a process's first cacheable lookup is answered by the sources and the table is attached and validated at the second (so a fresh process pays no attach cost; the first lookup reads the files themselves); (7) the account stamp is re-verified by a lookup only when the identities of `passwd` and `nsswitch.conf` changed since its last verification or a source other than `files` can answer; (8) any successful `unshare` or `setns` re-keys, and an effective UID equal to the overflow UID (65534) always uses a private table (in an unmapped user namespace every unmapped owner shows as 65534); (9) security fixes 2026-10-04 (validation T12, T13; coordinator: bugs against this design, not new defaults): the region's descriptor, like every descriptor the library keeps across calls (the syslog socket, the utmp file, the `lckpwdf` lock, database cursors, `mtrace`'s file, the timers' epoll set and `timerfd`s, the message queues' netlink socket, the AIO ring and its eventfd), is moved above 2 with `F_DUPFD_CLOEXEC` (`liella::io::above_standard`): with the standard output closed, `id` had opened the region as descriptor 1 and written its output into it; and a process outside the initial user namespace (`/proc/self/ns/user` is not inode 0xEFFFFFFD, or unknown) never uses a region: its IDs are the namespace's while `/dev/shm` is everyone's (a process with UID 0 in a namespace mapping it to 1001 had made `liella-nscache-0` owned by 1001). Region: 8 MiB, magic `LIELLANC`, layout 1, an 80-word header, hash slots, a ring arena. Native API: `liella_nscache_enable`, `liella_nscache_category`, `liella_nscache_invalidate`, `liella_nscache_status` (`struct liella_nscache_info`). **Known limits:** a process of the same user that truncates the region file makes readers fault (SIGBUS): the region cannot be size-sealed (`F_ADD_SEALS` gives `EPERM` on tmpfs files, which carry `F_SEAL_SEAL`); credential changes made by raw system calls that bypass Liella are not seen; TTLs use `CLOCK_REALTIME`. |
