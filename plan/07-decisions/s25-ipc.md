#### §25: IPC

| ID | Spec | Ann. | Decision |
|---|---|---|---|
| D-25.1 | §25.2 | HIST | **Internal:** typed SysV operations. **Boundary:** `semctl`'s `union semun` is received through a C variadic adapter and decoded per command by `legacy` (F11). |
| D-25.2 | §25.4, §22.7 | HIST | POSIX shared memory and named semaphores stay on `/dev/shm` (contract, Config). Internally, `memfd` is preferred for anonymous sharing. |
| D-25.3 | §25.3 | KERN | `mq_notify` `SIGEV_THREAD` uses the kernel's netlink protocol (⚑ KERN). |
| D-25.4 | §25.2 | HIST | The `*ctl` commands' untyped argument is decoded by command (`ipc_compat::*_shape`, then `conv`). The smaller statistics structures (`msginfo`, `seminfo`, `shminfo`, `shm_info`) are copied out of a full-size scratch structure, so no reference ever spans more than the caller's object. `shmat`/`shmdt` take the caller's address through `raw` (D-X.9). |
| D-25.5 | §25.3, §25.4 | HIST, KERN | **POSIX message queues and shared memory (phase 13); decisions.** Queue names: the one leading slash is stripped and the kernel judges the rest (`EACCES`/`ENOENT` as §25.3 now says); `mq_unlink`'s `EPERM` becomes `EACCES`; `mq_open` always sets `O_CLOEXEC`; `__mq_open_2` with `O_CREAT` is `EINVAL` (the reference aborts); send and receive are cancellation points. `SIGEV_THREAD` (D-25.3): one netlink socket and one service helper per process; each notification runs in a new thread with the attributes copied at `mq_notify` (stack size and address, guard, scheduling, affinity; always detached: owner ruling 2026-10-04) and an empty signal mask; a caller-supplied stack serves one notification at a time (owner, 2026-10-04; `boundary::stacks`, as D-23.3): a function that registers again and is still running when the next message arrives is followed by the next notification once its thread has left the stack; a notification whose thread cannot be made (thread limit, memory), at once or after it waited for its stack (`boundary::stacks` hands it back: `mqueue::abandoned`), is not dropped (glibc drops it) but retried, like a timer's (owner ruling #680, extending #269, NOTIFY-RETRY-MQ-AIO 2026-10-22; gain: a notification is delivered late instead of lost when threads or memory are short for a moment; a deliberate difference with a compat-flag placeholder, as #269's; such a flag would be read only after a refusal, so the default path would pay nothing): its record is kept and the timers' helper (D-23.3) retries it with the timers' back-off (10 ms doubling to a 1 s ceiling; `mqueue::retry_due`), once, until a thread starts; the helper is made with the process's first `SIGEV_THREAD` registration (one thread and two descriptors per process, shared with the timers; once made, a registration pays one atomic load), so the retry needs no thread after the refusal; the message used the kernel's registration up, so meanwhile the queue takes a new one (this process's or another's), `mq_notify(q, NULL)` does not cancel the pending retry, and a fork child does not inherit it (tests `mq_refused_notification_retried`, `mq_abandoned_notification_retried`); a NULL function is `EINVAL`; a fork child drops everything. Shared memory: any number of leading slashes; empty, a further slash, `.` or `..` is `EINVAL` (`ENOENT` for `shm_unlink`; the reference opens `/dev/shm` or `/dev` for `.`/`..`); over 255 bytes `ENAMETOOLONG`; opened `O_NOFOLLOW\|O_CLOEXEC\|O_NONBLOCK`, anything not a regular file `EINVAL` (the reference blocks on a FIFO), `O_NONBLOCK` cleared unless asked for; no file-system type check on `/dev/shm`. §25.4 now states the name rules and that `/dev/shm` fails only when missing (owner ruling 2026-10-04). |
| D-25.6 | §25.3 | ARB, KERN | **mq_notify `SIGEV_THREAD` service** (COLD-REWRITE2-W-far-10-REWRITE and PROOF-2, 2026-10-21; record `liella-historic:handoff/decisions/COLD-REWRITE2-W-far-10-REWRITE.md`; D-25.3, D-25.5). (M1) One netlink socket and one service thread per process, made lazily, the socket above the standard descriptors (D-25.3). (M2) The cookie is a key that is never reused, looked up among the live records: an address arriving through a socket is never dereferenced. (M3) Records are heap blocks of atomic words on a grow-only list; key 0 is free and reused; freed on a failed registration, on its REMOVED cookie, when its thread cannot start, and by the notification thread before it calls the function. (M4) NULL function EINVAL before any side effect; thread, socket and ENOMEM errors passed on; kernel errors passed through and the record freed; other `sigev_notify` values go straight to the kernel. (M5) The service loop accepts only 32-byte messages, ignores EINTR and ENOBUFS, sleeps 1 s on other errors, never exits. (M6) Notification threads via `stacks::launch` with the record's attribute copy and an empty signal mask (D-25.5). (M7) fork child: reset the lock, close the socket copy, mark every record free, allocate nothing. (M8) `__mq_open_2` with `O_CREAT` is EINVAL (D-25.5). |
