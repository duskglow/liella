#### §6: Multibyte text, wide characters and conversion

| ID | Spec | Ann. | Decision |
|---|---|---|---|
| D-6.1 | §6.1 | HIST | **Internal:** explicit `Decoder`/`Encoder` state values per codec. **Boundary:** `mbstate_t` is an 8-byte serialisation of that state (`legacy::mb_state`), which suffices for all built-in codecs. Its kind, need and have bytes sit in the header's `__count` (offset 0), the value in `__value`; `mbsinit` is true exactly when `__count` is 0, whatever `__value` holds, as the reference answers for a state a program wrote itself (gnulib's replacement converters keep their own partial characters there and ask the C library's `mbsinit`; validation T18, 2026-10-05). A NULL `s` in `mbrtowc`, `mbrtoc32`, `mbrtoc16` and `mbrtoc8` stores nothing through the output pointer (C17 7.29.6.3.2, 7.28.1: the call is `mbrtowc(NULL, "", 1, ps)`; the reference agrees). |
| D-6.2 | §6.2 | HIST, PATH | **Internal:** results are `Decoded::{Char(u32, len), Null, Incomplete, Invalid, SurrogateContinuation}`. **Boundary:** `(size_t)-1/-2/-3` via `abi::ret`. The non-restartable forms use a per-thread state (P-scope). |
| D-6.3 | §6.3 | HIST | **Internal:** conversion into a caller slice returns `Converted{written, consumed, needed}`, or allocates an owned result. **Boundary:** the NULL-destination measuring mode is one conversion choice (`conv::opt_buf`). |
| D-6.4 | §6.4 | HIST | **Internal:** iconv is built in (no gconv module loading; F28). `IGNORE`/`TRANSLIT` report counts of dropped and approximated characters separately. **Boundary:** reproduces "-1/EILSEQ at end if anything was ignored", per the contract. |
| D-6.5 | §6.2 | HIST, ARB | `MB_CUR_MAX` is 6 for UTF-8 locales, per the contract, because programs size buffers from it. Internally, UTF-8 needs at most 4. |
| D-6.6 | §6.5 | HIST | **Internal:** `display_width(u32, AmbiguousWidth::{Narrow, Wide})`. **Boundary:** narrow is the default. |
| D-6.7 | §5–§7 | ARB (spec silent) | **Approved.** The built-in `"C"`/`"POSIX"` locale's charset is ASCII. Bytes 0x80–0xFF: no class, mapped to themselves by `tolower`/`toupper`, `mbrtowc` fails with `EILSEQ`, `btowc` returns `WEOF`, `wctob` of a code point above 0x7F returns `EOF`, and `MB_CUR_MAX` is 1. Wide classification in `"C"` covers ASCII only. `"C.UTF-8"` (phase 7) is the Unicode locale. |
| D-6.8 | §6.2–6.4 | HIST | **Charsets from the system charmaps** (owner ruling 2026-10-01, phase 7; refines D-6.4). Built in, with no file access: UTF-8, UTF-16, UTF-32, UCS-2 and UCS-4 (both byte orders and the BOM forms), `WCHAR_T`, ASCII (`ANSI_X3.4-1968`) and ISO-8859-1. Every other charset is read on first use from `/usr/share/i18n/charmaps/<name>.gz` (or uncompressed): installed system data in the POSIX charmap format, read under the format-inspection decision. Its `<code_set_name>`, `% alias` lines, `<mb_cur_max>` and mapping lines (including `<U…>..<U…>` ranges) are compiled in memory into a decoding trie and an encoding map, cached per process and immutable. Gzip decompression (RFC 1951/1952) is a small safe-Rust inflater in core. Stateful encodings that glibc implements only in modules (ISO-2022 family, UTF-7, stateful EBCDIC) are not supported: `iconv_open` reports `EINVAL` (deviation). A locale whose codeset has no codec (charmaps not installed) fails to load its `LC_CTYPE`. Charset names match case-insensitively, through the charmap's name and aliases. **Compared with the reference iconv** (all 231 charmaps that list mappings, every mapping of small charsets and an even sample of large ones, both directions): 200 agree exactly; 26 are unknown to the reference iconv; 5 differ where the charmap and glibc's module disagree, and Liella follows the charmap: the teletex sets (ANSI_X3.110-1983, ISO-IR-90, ISO_6937, T.61-8BIT) list their non-spacing diacritic prefixes as private-use code points that the modules combine with the next letter, and MAC-CYRILLIC's 0xA2 is U+00A2 in the charmap, U+0490 in the module. Composing charsets (TCVN5712-1, TSCII) decode the longest listed sequence; a code point listed under several sequences encodes as the lowest. **Names** match a charmap's name and aliases as codeset names do (case and punctuation aside: `eucjp` is `EUC-JP`). A name no loaded charmap answers to is tried as a file name, then found by a scan of the directory: first by file name, then by the header's `<code_set_name>` and aliases (read from the first 4 KiB of each file, without parsing it). Runs of mappings that continue one another merge into one range when parsed, so the 8-bit charsets search a few ranges. **Locale differential test** (`locale_products`, adds ja_JP.EUC-JP, ru_RU.KOI8-R and zh_CN.GB18030): `mbrtowc` returns −2 only for a valid prefix (§6.2), where the reference also returns it for a prefix no character extends (UTF-8 `ED A0`, a surrogate; EUC-JP's lone 0xA0); and the GB18030 charmap lists supplementary characters only up to its Unicode version (U+1F600 is absent), where the reference module maps the whole linear four-byte range. The test records these three lines and fails if one stops differing. **Owner: the recorded differences are accepted (2026-10-01).** GB18030's newer characters stay as the charmap gives them; revisit only if they cause coreutils failures (phase 15). |
| D-6.9 | §6.4 | HIST, ARB | **iconv** (phase 7; refines D-6.4). A descriptor decodes to code points and encodes from them (pivot UCS-4), with its decoder and encoder states in the descriptor, so a conversion resumes at any split point. `//TRANSLIT` uses the current `LC_CTYPE` locale's transliteration table (Appendix D.1.3) and its default replacement. The built-in `C`, `POSIX` and `C.UTF-8` locales have no table file; their transliteration is derived from the UCD and is not the reference library's table, which the spec does not give: in `C.UTF-8`, a character's full decomposition without combining marks; in `C` and `POSIX`, only a decomposition that involves a compatibility mapping, with marks kept (they then become `?`, as in the reference `C` locale); then an ASCII-equivalents table (quotes, dashes, guillemets, `© ® ™ € × ⁄`, `ß æ œ` and their capitals); a vulgar fraction is set off by spaces (` 1/2 `); what still does not convert becomes `?`. `//IGNORE` reports as the contract says (−1/`EILSEQ` at the end if anything was dropped). **The reference library's behaviour, observed and followed** (phase 7; compared line by line by `iconv_products.rs`): `UTF-16` and `UTF-32` read an optional BOM in either order and otherwise assume little-endian; written, they begin with a little-endian BOM, once per descriptor until a reset or flush (no room for it is `E2BIG`); the forms that name an order neither read nor write one. `UCS-2` is little-endian, `UCS-4` big-endian, `WCHAR_T` little-endian. Every UTF-16 and UCS-2 form rejects surrogates. The `UCS-4` forms carry values up to `0x7FFFFFFF`, which `UTF-8` writes in the original 5- and 6-byte forms; `UTF-16`, `UTF-32` and the byte charsets reject values above U+10FFFF. Suffixes count on the target name only, separated by `/` or `,`, in any case; unknown ones are ignored. Incomplete input stays in the caller's buffer (`EINVAL`). With `//IGNORE`, invalid input is skipped as well; `E2BIG` still reports first, and an incomplete end after a drop is `EILSEQ`. The empty name is the current `LC_CTYPE` codeset. **Recorded differences** (the test lists them and fails if one stops differing): ISO-2022-JP and UTF-7 (stateful, D-6.8); the alias `WINDOWS-1252`, which no charmap lists; CP932's U+2014, which WINDOWS-31J's charmap does not map. **Owner: accepted (2026-10-01).** |
| D-6.10 | §6.2 | PERF | **The single-character decoders read their input lazily (AUD-M4).** `mbrtowc`, `mbrtoc32/16/8`, `mbrlen`, `mbtowc`, `mblen` read the text one byte at a time (`strz::LazyText`, `mb_compat::MbInput`) and stop where the character does: no `strnlen` over `n` (a loop `mbrtowc(p, end - p)` was O(N^2)), and no byte past the character is touched (the reference returns 1 for an `A` ending a page before an inaccessible one with `n` 100000; Liella faulted: probe 551e4d076fae). The window grows while the decoder says incomplete or, for a multibyte charmap (longest match), while a character took every byte so far; at most `MAX_ENCODED` bytes then the terminator, which is the window the whole-text form used, so every answer is unchanged. Residual difference: in a multibyte charmap locale a complete character at a page end before an unreadable page may still read one byte more than the reference. Tests: `single_character_forms_read_no_byte_past_the_character` (boundary, guard page), `single_character_forms_read_only_the_character` (core, counts bytes read). MB-K2: UTF-8 from the initial state is read and decoded in one pass (`text::decode_utf8_initial`, same rules, bytes read, answer and state as the per-byte loop; `mbrtoc16`/`mbrtoc8` apply `split_utf16`/`split_utf8_units` to its result); `utf8_fast_path_matches_the_per_byte_definition` also compares the state left. Zen 1 3-byte: 360 -> 196 instructions per call (glibc 244). WL-HOT-SEQ3: `mbrtowc`/`__mbrtowc`/`mbrtoc32`/`mbrlen`/`__mbrlen` answer at the export, before the lazy reader and the state machinery, when `s` is non-NULL, `n >= 1` and the state (caller's or hidden) is all zero bytes: a byte below 0x80 in a UTF-8 or ASCII locale, or a well-formed two-byte UTF-8 character with `n >= 2`; the state is left as is (the general path stores the same zero bytes). Everything else takes the general path unchanged. Test: `single_character_quick_path_matches_the_general_decoder` (every 1-2 byte input, n 0..3, against a zero-__count non-zero state that takes the general path). WL-HOT-SEQ4: the 2-byte en_US.UTF-8 'regression' (wl_percall 237 -> 260) was the probe, not the library: its spec never called setlocale, so it ran in the C locale (encoding Ascii: the ASCII quick path applies, a 0xC3 lead correctly declines). In en_US.UTF-8 and C.UTF-8 every case takes the quick path with identical counts. Instruction ceiling (gate-asserted): conformance/c/s06_mbrtowc_quick_ceiling.c single-steps a traced child (exact, no PMU, so it also runs in the 5.10 guest) and fails when any of mbrtowc/mbrtoc32/mbrlen ASCII or 2-byte, caller's or hidden state, in C.UTF-8 or en_US.UTF-8, costs more than 100 instructions per call (quick path 48-71 on Zen 1). |

Considered: eight-byte ASCII attempt at every ASCII byte (mixed 59k but regressed ascii-only, then 75k: the failed attempt's setup spilled registers), per-char run counter chosen. |
| D-6.12 | §6.4 | PERF | **Fused UTF-16/UTF-32/UCS-2/UCS-4 -> UTF-8 transcoder (ICONV-2), the reverse of D-6.11.** `Conv::convert` offers a wide source whose byte order is known (`fast::wide_source`: fixed, or selected by a BOM / the first unit, so BOM sensing and the first unit of the BOM forms stay in the general loop) with target UTF-8 to `fast::wide_to_utf8` at the top of each loop turn: one tight loop (const-generic on unit size, order, UCS-2) with inline unit load, surrogate-pair join and inline UTF-8 encode, and an out-of-line 16-byte-block ASCII narrowing run entered after eight ASCII units in a row. It stops, touching nothing further, at the end of the input, a partial unit, no room for the next character, a lone or reversed surrogate (or a surrogate in UCS-2 / UTF-32 / UCS-4), a high surrogate not followed by a complete low unit, and any value above U+10FFFF (UCS-4 up to 7FFFFFFF is the general loop's 5/6-byte encode); the general loop then handles that one character (EILSEQ, EINVAL, E2BIG, //IGNORE, //TRANSLIT as before). No ABI or boundary change. Tests in `fast.rs`: every source x byte order x flag set x C/C.UTF-8 x unit string x every byte prefix x every output size + resume vs the pivot loop; every scalar value vs `char::encode_utf8`; planted bugs (wrong BE/LE load, no low-surrogate check, wrong 4-byte continuation) each fail. |
